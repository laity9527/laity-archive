# Laity 档案库 · 从零开始的体验与逐页规格（2026-11-16）

| 前提 | 事实 |
|---|---|
| 设计前提 | 视觉侧已定案「校验台」：暗态为原生工作态、亮态为阅图台；标题下三读数（发布时间 / 内容摘要 / 提交来源）是信息签名 |
| 事实基线 | 多租户、GitHub OAuth、无 UGC；`contentHash = title + before + after`；`userId` 租户隔离；扫描→哈希→落库；密钥不落库 |
| 数据边界 | 只有 `User` / `Project` / `Log` 三表；无 Tag / Audit / Settings 表；Project / Log 无 featured / series / pinned 字段 |
| 能力边界（HEAD `b86ba09` 实测） | **已存在、可推翻或可重写**：`/tags` `/archive` `/admin/settings` `/api/search` `/feed.json` `/tags/[tag]/feed.*` 等路由；`CommandPalette` / `Toast` / `ThemeToggle` / `ZoomableArticle`（灯箱）/ `Breadcrumbs` / `SectionHead` / `CodeBlock` / 15 个图标组件；`themeScript` 首帧防闪与 `@media print`；大厅排序记忆、实时字数与阅读时长、编辑器敏感信息实时提示、标签按主题分组、GitHub 同步、AI 帮写、大小写归一。本文一律按「已落地」口径写推翻成本，不写成「不存在、要新建」 |
| 预算 | 任一前台页 Prisma ≤3；首屏 JS 增量 ≤15KB gzip；LCP ≤2.0s；CLS ≤0.05 |

## 1. 产品定位与用户任务

| # | 核心任务 | 触发场景 | 当前痛点 | 设计要解决的题 |
|---|---|---|---|---|
| T1 | 核验一条改动的真实性 | 招聘 / 合作前，看到某人声称做过某优化 | 只能读到结论，拿不到「改前是什么、改后是什么、何时改、从哪来」 | 证据读数必须在列表行就露出，详情页一步到位可复算，不需先接受任何隐喻 |
| T2 | 在大量日志里定位一条相关的 | 同行想找某技术主题下他做过的具体改动 | 目录式浏览找不到；搜索结果只有标题，命中后仍要进详情才见证据 | 搜索结果行本身就是证据卡；筛选 / 时间 / 标签是同一发现面的不同视图 |
| T3 | 判断这个项目是不是他做的、还活着吗 | 合作方评估交付方 | 项目列表只有名字和状态，连不到过程，无法判断证据密度 | 项目条目必须挂「关联日志数 + 最近提交 / 最近日志时间」两项读数 |
| T4 | 站主发布一条可自证的记录且不出错 | 写完复盘准备发布 | 怕敏感信息泄露、怕摘要口径写错导致历史印章作废、怕发布时间不可信 | 扫描→哈希→落库在界面上有可见的三段回执，而不是黑盒成功提示 |

定位一句话：**这是让人在 90 秒内完成「核验」的场所，不是让人停留欣赏的场所。** 这四条解释了后面全部 IA：**T1 决定三读数与详情页结构；T2 决定「唯一发现面 + 视图写进 URL」；T3 决定项目条目的字段优先级；T4 决定后台定位为「发布校验台」而非通用 CMS。** 反过来，任何不服务 T1–T4 的页面、字段、入口都不设。

## 2. 信息架构

### 2.1 一级导航：三项

| 项 | 指向 | 为什么是它 | 为什么不是更多 |
|---|---|---|---|
| 项目 | `/projects` | T3 的落点：先看证据密度再决定是否深读 | — |
| 日志 | `/logs` | T1/T2 的唯一发现面 | — |
| 关于 | `/about` | 解释「为什么可核对、口径是什么」 | 隐私与开源致谢作为合规子页从属于它，不占一级位 |

**不设第 4 项**：标签与归档不是目的地，而是「日志」的两种视图状态（`/logs?view=tags`、`/logs?period=`）。仪器只有几个旋钮；多一个导航项就多一个读者要判断「我该去哪」。前台全站不出现「管理 / 编辑 / 批量 / 删除 / 仪表盘 / 控制台」任一词汇——出现即触发视觉侧定义的最大失败模式。

### 2.2 路由全集

| 路由 | 处置 | 承载什么 | 为什么不并入别处 |
|---|---|---|---|
| `/` | 保留·重构 | 状态条 + 最新 3 条证据 + 项目读数表 | 90 秒验证的唯一入口，不承载查询态 |
| `/logs` | 保留·升级为唯一发现面 | 搜索、项目 / 类型 / 状态 / 标签筛选、时间切片、标签分布，全为查询参数 | T2 要求一个面解决所有定位，拆页会让读者猜 |
| `/logs?view=tags` | **推翻已实现**的 `/tags`，降为视图 | 标签分布读数表：标签 / 条目数 / 最近时间 | 标签是「日志的切片」，不是独立内容类型 |
| `/logs?period=YYYY-MM` | **推翻已实现**的 `/archive`，降为视图 | 时间切片 + 年份锚点 | 归档是筛选，不是新内容类型 |
| `/tags/[tag]` | 保留·降级 | 可分享 / 可订阅的固定地址，带 feed 入口 | 外链与 RSS 订阅需要稳定 URL，不能只是查询参数 |
| `/projects` | 保留 | 项目读数表 | 项目与日志是两种证据粒度 |
| `/u/[handle]` | 保留 | 租户主页：账号身份 + 档案读数总览 + 最新日志 | 多租户身份落点 |
| `/u/[handle]/logs/[slug]` | 保留·重构 | 日志详情：三读数签名 + BEFORE/AFTER + 经验总结 | 核心可信度页，不可合并 |
| `/u/[handle]/projects/[slug]` | 保留 | 项目详情 + 关联日志 | 从项目到过程的桥 |
| `/about` `/privacy` `/licenses` | 保留·静态 | 口径说明与合规 | 合规需独立可引用地址，但导航只露「关于」 |
| `/login` | 保留 | GitHub OAuth（含失败态） | 身份边界 |
| 404 / 错误边界（非独立路由） | 保留·增强 | 走失恢复 | 证据链断裂时不能静默 |
| `/admin` | 保留·重定位为「发布校验台」概览 | 计数 + 待发布 + 同步 / 导出入口，措辞只谈档案事实 | 与前台语义隔离 |
| `/admin/logs` `/admin/logs/new` `/admin/logs/[id]/edit` | 保留 | 写作、发布、下架、删除 | T4 的作业面 |
| `/admin/projects` `/admin/settings` `/admin/export` | 保留 | 项目与身份设置、导出 | — |
| `/feed.xml` `/feed.json` `/tags/[tag]/feed.*` `/sitemap.xml` `/robots.txt` `/api/health` | 保留 | 机器可读的核对入口与探针 | 订阅者需要不需要登录的入口 |

**本方案主动推翻的已落地能力**：`/tags`（并入 `/logs?view=tags`）；`/archive`（并入 `/logs?period=`）；`/api/search` + `CommandPalette`（并入 `/logs?q=` 服务端渲染）。三者**当前都已实现且可用**，不是"待建"；推翻它们不损失核对能力，只减少目的地数量，代价是已有代码作废。`ThemeToggle` / `Toast` / `ZoomableArticle` / `CodeBlock` / 15 图标 / `themeScript` / `@media print` 则改为**复用机制、重写规格**。

### 2.3 URL 语义

| 状态 | 是否写入 URL | 理由 |
|---|---|---|
| 搜索 `?q=` | 是 | 命中片段与高亮可被分享，别人点开看到同一份证据 |
| 筛选 `?project=&kind=&status=&tag=` | 是 | 筛选即「我核的是哪一批」，是事实的一部分 |
| 时间 `?period=` / 视图 `?view=tags\|timeline` | 是 | 归档与标签分布都是可引用的查询态 |
| 分页 `?cursor=` | 是（单向向前） | 推翻现有双向游标：仪器只需「继续读数」，双向增加状态与焦点复杂度；游标入 URL 才能分享到同一页 |
| 主题 `dark\|light` | 否（localStorage + 系统偏好） | 主题是观察者偏好，不是档案事实；写进 URL 会污染可核对地址 |
| 复制状态 / 加载态 / Toast | 否 | 瞬时态不入地址栏 |

### 2.4 搜索的产品形态

**裁定：不做浮层 / 命令面板，只做日志大厅内联搜索（`?q=` 服务端渲染）。** 三条理由：① 「可核对」要求结果行直接带出发布时间、摘要缩写与提交来源，浮层放不下这三读数；② 已实现的命令面板是工具隐喻，会把「档案」读成「别人的后台」，且其客户端 JS 成本逼近 15KB 预算；③ `?q=` 天然可分享，搜索结果与筛选结果复用同一套证据行，不新增页面与心智。降级方案：结果为空时输出「无命中 + 清除条件」，不做猜你喜欢。

### 2.5 与 V3 的 IA 差异

| 维度 | V3 | 本方案 | 为什么 | 代价 |
|---|---|---|---|---|
| 一级导航 | 4 项（含标签） | 3 项（项目 / 日志 / 关于） | 标签从目的地降为视图 | 老用户需重新定位标签 |
| 路由 | 已落地 `/tags` `/archive` `/api/search` | 三者撤回，降为 `/logs` 查询态 | 减少目的地、URL 承载事实 | 已落地代码作废 |
| 标签地址 | 保留显示名、不做 `tagsKey` 双轨（V3 已裁定） | 沿用显示名；`/tags/[tag]` 仅作订阅落地页，`/tags` 索引撤回 | 不引入大小写双轨，不碰归一口径 | 索引页撤回 |
| 分页 | 双向游标 | 单向游标入 URL | 降低状态复杂度 | 往回翻靠浏览器后退 |
| 搜索 | ⌘K 命令面板 | 大厅内联 SSR 结果 | 结果带证据、JS 更省 | 快捷唤起感消失 |
| 后台 | 通用管理面 | 发布校验台 | 与前台可信度同构 | 措辞需全套重写 |

## 3. 核心信息模型

读者看到的「一个条目」由以下字段按优先级构成，与数据库顺序无关。

| 条目 | 字段层级（从高到低） | 排列规则 |
|---|---|---|
| 日志条目 | ① 标题 → ② 三读数行（发布 UTC / 摘要前 6 位 / 提交来源标记）→ ③ 项目归属 → ④ 标签（≤5）→ ⑤ 经验总结一行截断 → ⑥ 阅读时长 | 三读数固定占第二行；阅读时长永远垫底且不单独成行，避免与「证据」争位 |
| 项目条目 | ① 项目名 → ② 类型 / 状态（文字徽章）→ ③ 证据密度（关联日志数 + 最近日志或提交时间）→ ④ 摘要一行 | ③ 必显，它是 T3 的判断依据；`repoUrl` 作为次要操作而非主字段 |
| 详情页专属 | 上下篇、相关阅读、目录、经验总结全文、BEFORE / AFTER 全文 | 只出现在详情，不进任何列表条目 |
| 可核对性前置 | 每张日志卡右上固定 6 位摘要缩写 + UTC 日期 + 来源类型文字（有提交则 `branch` 标记 + sha6，无则「本地记录」） | 列表页即回答「这条有没有据」；不需要点进去才知道 |
| 反例约束 | 不显示 `isAiAssisted` 作为前台徽章、不显示草稿、不显示 `beforeDate` / `afterDate` 的原始值 | 前者会引发无关判断，后者是写作时间不是发布事实，易与发布时间混淆 |

## 4. 逐页规格

每页四件事：目标 / 布局（375 / 1440）/ 状态（空、载、错、极端）/ 验收（可测）。主表按页面逐行给出，详情页在其后专项展开。

| 页面 | 目标 | 布局：375 / 1440 | 状态：空 / 载 / 错 / 极端 | 验收（可测） |
|---|---|---|---|---|
| 首页 `/` | 90 秒给出「这里有据可查」的判断 | 375：状态条 1 行 + 最新证据 3 条 + 项目定义列表；1440：状态条 + 最新证据 3 条 + 项目四列表格 | 空：无已发布日志时状态条改为「档案已就绪 · 尚无已发布条目」；载：骨架行高 56px；错：状态条显示错误读数而非整页白；极端：项目 >30 折叠为「展开全部」 | 首屏可见状态条与 ≥1 条含摘要缩写的证据行；Prisma ≤3；无横向滚动 |
| 日志大厅 `/logs` | 唯一发现面：定位并当场核 | 375：条件区折叠 details + 证据行单列；1440：左侧筛选 200px + 右侧证据行流 | 空：120px 虚线框「无匹配条目 · 清除条件」；载：56px 骨架 10 行；错：就地错误条 + 重试，不清空已加载行；极端：>50 条用 `cursor` 继续按钮，超长标题 2 行截断 | `?q=` / `?tag=` 刷新后条件回显；每行含 6 位摘要缩写 + UTC 日期 + 来源类型；Prisma ≤2 |
| **日志详情** `/u/[handle]/logs/[slug]` | **让读者在不理解任何隐喻的前提下完成一次核对** | **375：三读数压缩条置正文前（≤120px）+ 目录 details 折叠；1440：主内容 760px + 右栏 280px sticky，三读数全量面板在右栏顶部、目录紧随** | 空：`beforeContent` 或 `afterContent` 为空时显示「该侧无内容 · 单侧记录」并保留另一侧；载：正文区骨架；错：读数面板显示「读数暂不可用」且正文保留；极端：摘要 64 位 `break-all`、超长正文不撑破栏宽 | 见下方专项 4 条；Prisma ≤3；CLS ≤0.05 |
| 项目列表 `/projects` | 按证据密度筛选项目（T3） | 375：定义列表（名 / 类型状态 / 日志数 / 最近时间）；1440：四列表格 | 空：虚线框 + 文字；载：骨架 56px；错：错误读数行；极端：日志数 0 显示「0 条 · 尚无过程记录」不隐藏 | 每行可见日志数与最近日期；按最近日期倒序可验证 |
| 项目详情 `/u/[handle]/projects/[slug]` | 把项目声明连到它的过程证据 | 375：信息区在上、关联日志在下；1440：信息卡 + 关联证据行表格 | 空：无关联日志时显示「尚无公开过程记录」+ 返回大厅；载 / 错同上；极端：`repoUrl` 超长截断为域名 + 完整 `title` 属性 | 关联日志每行带三读数；`repoUrl` 不产生横向滚动 |
| 租户主页 `/u/[handle]` | 90 秒内回答「这个人做过什么、能不能核」 | 375：身份块 + 读数三格（项目数 / 已发布数 / 最近发布） + 最新 5 条证据；1440：同结构，读数三格横排 | 空：读数全 0 + 空态说明，不隐藏区块；载 / 错同上；极端：handle 超长 `break-all` | 三格读数与列表条数一致；无 featured / pinned 字段参与排序 |
| 标签分布 `/logs?view=tags` | 找到主题入口，不是欣赏词云 | 375 / 1440：统一表格（标签 / 条目数 / 最近时间），按条目数降序 | 空：「尚无标签」；载：骨架；错：错误读数；极端：标签 >24 字截断但 `title` 保留全名 | 全表无字号差异表意（仅一种字号）；每行可点进 `/tags/[tag]` |
| 标签聚合 `/tags/[tag]` | 分享与订阅一个切片 | 375 / 1440：面包屑 + 切片标题 + 证据行列表 + feed 入口文字链接 | 空 / 载 / 错同大厅；极端：标签含特殊字符时 URL 编码且解码后与显示名一致 | 显示名原样出现在 H1 与 URL；无大小写改写 |
| 归档切片 `/logs?period=YYYY-MM` | 按时间找，年份可分享 | 375：月份 details + 证据行；1440：年份锚点条 + 月分组列表 | 空：「该时段无条目」；载 / 错同上；极端：单月 >30 条显示「继续加载」 | `?period=` 刷新后定位同一分组；锚点可复制 |
| 关于 `/about` | 解释口径：为什么可核对、拿什么复算 | 375 / 1440：单一正文列，含三读数释义段与复算口径纯文本 | 无动态态 | 页面含完整口径字符串，可被 grep 命中；无营销形容词 |
| 登录 `/login` | GitHub OAuth，失败也要有路 | 375 / 1440：单一按钮 + 一行说明 | 错：OAuth 失败显示「授权未完成 · 重试」并保留返回首页链接；极端：已有会话显示「已登录 · 前往校验台」 | 失败态不出现技术错误码；登录后跳回来源页 |
| 404 / 错误边界 | 证据链断了也不静默 | 375 / 1440：读数式提示（请求路径 / 状态 / 下一步） | 极端：详情 slug 不存在由前置判定给 404，不渲染空壳 | 状态码 404；页面含「返回日志大厅」文字链接 |
| 后台概览 `/admin` | 站主确认「档案处于什么状态」 | 375：四读数格 + 待发布列表；1440：读数格横排 + 待发布表格 | 空：待发布为 0 显示「无待发布条目」；载：骨架；错：错误读数；极端：草稿 >20 分页 | 四读数与库内计数一致；前台词汇零出现在此页之外 |
| 后台日志列表 `/admin/logs` | 逐条确认发布 / 下架，不做批处理 | 375：卡片式行；1440：表格 + 状态筛选 + 标题 / 项目筛选 | 空 / 载 / 错同大厅；极端：标题超长截断 | 下架为就地二次确认；无「批量发布」「批量删除」按钮 |
| 编辑器 `/admin/logs/new`…`/[id]/edit` | 写出可被核对的记录，并让 T4 可见 | 375：单栏 Markdown + 底部格式栏；1440：编辑区 + 预览区 | 空：新日志给最小骨架；载：草稿恢复提示；错：保存失败保留输入；极端：超长正文不分块冻结 | 发布后显示三段回执（扫描 / 摘要 / 发布时间）各带值；密钥字段不在任何 UI 出现 |
| 设置 `/admin/settings` | 站点标识只读、显示名可改 | 375 / 1440：定义列表 | 错：保存失败保留输入值；极端：显示名超长截断 | 只读项标明来源键名但不显示值；GitHub 集成状态用文字 |

### 4.1 详情页三读数：两种形态、一套数据

| 形态 | 放什么 | 怎么不重复 |
|---|---|---|
| 1440 右栏全量面板（sticky，与目录同一根） | ① 发布时间 UTC 到秒（mono 12px）；② 内容摘要 64 位全文 + 复制按钮 + 复算口径纯文本；③ 提交来源：有则 sha + 仓库跳转，无则「本地记录」+ 口径说明 | 读数面板是摘要与来源的**唯一权威展示位**；正文内不再出现第二张摘要卡 |
| 375 正文前压缩条（≤120px） | ① UTC 到分；② 摘要前 8 位 + 复制按钮；③ 来源类型一行文字 | **同一读数块 DOM 提升为正文首块**，只改呈现粒度：默认压缩态，`<details>`「展开完整读数」后显示 64 位与口径。字段只存在一份，非两处并列 |
| 验收 | 同一篇日志在 375 / 1440 下 DOM 中摘要字符串只出现 1 次；375 压缩条 `getBoundingClientRect().height ≤ 120`；复制按钮命中区 ≥40×40px | — |

### 4.2 BEFORE / AFTER：从「对照」改为「变换读数」

| 项 | 规格 |
|---|---|
| 结构 | 两栏等宽，中间 1px 网格分隔；栏头标 `INPUT / 变更前` 与 `OUTPUT / 变更后`，各带字符数与行号刻度（行号 1..n，mono 12px，作为「刻度」不是装饰） |
| 差异读数 | 栏上方一行：`Δ +128 / −43 字符`，先给改动的量，再给改动的内容；这是仪器语义与 V3「编号 + 线 + 留白」的根本不同 |
| 中间标记 | 分隔线上置一个 `Δ` 或 `→` 字符标记，不发光、不加动画 |
| 极端 | 单侧为空显示「该侧无内容 · 单侧记录」占位，不折叠另一侧；超长内容栏内滚动，不撑破 760px 主栏 |
| 验收 | 两栏字符数与命令行统计一致；375 下两栏上下堆叠且中间标记保留；打印时两栏不跨页断裂 |

### 4.3 提交来源缺失时的表达

| 项 | 规格 |
|---|---|
| 有 `sourceCommitSha` | 来源读数 = 类型文字「GitHub 提交」 + sha（4 位分组）+ 仓库跳转链接 |
| 无 `sourceCommitSha` | 来源读数 = 「本地记录」 + 口径说明「该条目未经 GitHub 同步，无可追溯提交」；原图标位置放同宽文字占位，不发光、不空白、不编造 |
| 验收 | 无来源时来源读数非空字符串；不出现匹配 `^[0-9a-f]{40}$` 的伪 sha；读屏播报含「本地记录」 |

### 4.4 打印：核对单小票

| 项 | 规格 |
|---|---|
| 版式 | 顶部三栏表：发布时间（UTC 到秒）/ 内容摘要（64 位全文，9pt mono，允许换行）/ 提交来源（sha 或「本地记录」）；每栏带文字标签 |
| 口径行 | 表下一行纯文本：`复算口径 SHA-256(title + before + after)` |
| 丢弃 | 复制按钮、目录、`<details>` 箭头、灯箱、导航、搜索、主题、阴影、渐变 |
| 页码 | CSS counter 页脚「第 N 页 / 共 M 页」 |
| 验收 | 打印预览三读数齐全且顺序固定；黑白打印下来源类型文字可读；无交互控件残留；CSS 覆盖 `html[data-theme]` 优先级 |

## 5. 交互契约（跨页只写一次）

| 类别 | 契约 |
|---|---|
| 反馈双通道 | **URL 承载事实**（筛选 / 搜索 / 分页 / 视图 / 时间，浏览器前进后退即还原，任意地址可直接分享核对）；**就地状态承载瞬时反馈**（复制按钮变「已复制」并 `aria-live` 播报，不弹 Toast）。前台无 Toast；后台操作回执才用 Toast（成功 4s 收起，错误保持到手动关闭） |
| 破坏性确认 | 删除沿用输入 slug 确认；下架是可逆操作，用就地二次确认（一次点击 + 就地「确认下架」），不弹模态；不做批量发布——发布是不可逆的信任动作，必须逐条过扫描 |
| 异步三态 | 加载：56px 骨架、无流光动画、高度与真实行一致；成功：读数更新 + 就地文字确认；失败：就地错误行 + 重试，**不清空已有内容** |
| 键盘地图 | `/` 聚焦大厅搜索（仅 `/logs` 生效，输入框内失效）；`j/k` 移动行焦点；`Enter` 打开焦点行；`Esc` 关闭浮层 / 清除搜索焦点；`c` 复制当前读数；`←/→` 上下篇；`n` 后台新建。所有快捷键在输入态失效 |
| 焦点管理 | 路由跳转后焦点移到 `h1`；浮层开时焦点陷阱、关后回到触发元素；复制后焦点留在按钮并播报；筛选变更不重置焦点到页首 |
| 空 / 载 / 错通用 | 空态 120px 虚线框 + 13px 文字 + 一个明确「下一步」按钮，高度固定防 CLS；错误态保留已加载内容；极端数据（>1000 条 / 超长标题 / 无标签）截断 + 展开，不撑破版心 |
| 响应式断点 | 375 / 768 / 1024 / 1440；<768 单列、表格转定义列表；<1024 右栏整体上移为压缩摘要条；1440 版心 1320 居中。触控目标 ≥40×40px，指针设备才显示 hover 次要操作，触控端提供常驻入口 |
| 动效语义 | 动效只表达「系统正在工作」（同步 1.2s 呼吸）或「状态已改变」（120ms 换色），不做装饰性移动；`prefers-reduced-motion: reduce` 全部归零，呼吸改静态文字「同步中…」 |
| 无障碍 | 状态用文字不用灯，颜色仅冗余线索；焦点环 2px + 2px offset；译屏可达三读数全部字段；荧光青一屏最多一处语义，第二处改为描边中性色 |

## 7. 明确不做

| # | 不做 | 理由（仪器方向） |
|---|---|---|
| 1 | 全局命令面板 / ⌘K（已落地，本方向撤除） | 浮层放不下三读数，且工具隐喻把档案读成后台 |
| 2 | 标签字号三档词云（`/tags` 已落地，本方向撤除） | 字号表意是装饰；仪器用刻度（条目数）不用字号 |
| 3 | 双向游标（不引入，维持单向） | 仪器只需「继续读数」，双向让焦点与状态变复杂 |
| 4 | 主题写进 URL | 观察者偏好不是档案事实，写进去会污染可分享地址 |
| 5 | 前台 Toast | 前台反馈应是读数自身的状态变化，不是弹出通知打断核对 |
| 6 | 状态灯 / emoji 指示 | 颜色掉色与黑白打印下核对链会断，状态必须文字化 |
| 7 | 霓虹描边 / 终端雨 / 扫描线 | 越过「可核对的仪器」变成「赛博布景」 |
| 8 | 语法高亮引擎 | 无依赖预算；代码块只给语言标签 + 复制 |
| 9 | 批量发布 | 发布是不可逆的信任动作，必须逐条过扫描与确认 |
| 10 | 前台出现管理 / 编辑入口 | 一旦出现，可信度反转成「在看别人的 CMS」 |
| 11 | 拖拽上传的动效反馈 | 动效只表达系统工作，不表达操作乐趣 |
| 12 | 暗色直接反相（现有暗色已落地，本方向重写不反相） | 须按明度阶梯独立推导，反相会让控件边界掉到 3:1 以下 |

## 8. 与 V3 的体验差异

| 维度 | V3 | 本方案 | 判断 |
|---|---|---|---|
| 导航 | 4 项含标签 | 3 项，标签降为视图 | **更好**：少一个要判断的目的地 |
| 路由 | 已落地 `/tags` `/archive` `/api/search` | 三者撤回，归入查询态 | **不同**：集中度换掉直达性，代价是已有代码作废 |
| 发现方式 | 已落地 ⌘K 命令面板 + 大厅筛选 | 撤回面板，大厅内联 SSR，结果即证据行 | **更好**：核对前置到搜索结果 |
| 详情信息签名 | 标题 + 面包屑 + 文末摘要卡 | 标题下三读数，摘要卡并入读数面板 | **更好**：可信度出现在首屏而非末尾 |
| 列表页密度 | 标题 + 日期 + 标签 | 标题 + 三读数 + 来源标记 | **更好但更贵**：密度上升需重新校准行高 |
| 后台定位 | 通用管理面 | 发布校验台 + 三段回执 | **不同**：作业面与可信度同构 |
| 反馈机制 | 统一 Toast | URL / 就地状态 / 后台 Toast 三通道 | **更好**：反馈按语义分工 |
| 响应式 | 双栏 + 移动 details 目录 | 右栏整体上移为压缩摘要条 | **不同**：同一读数块两种呈现 |
| 无障碍 | 颜色 + 图标表意 | 文字优先、颜色冗余、焦点闭环 | **更好**：色弱与读屏下核对链不断 |
| 打印 | 已落地 `@media print`：黑字白底、印章保留 | 改写为核对单小票 + CSS 页码 | **更好但更贵**：页码是新能力，样式需重写 |
| 功能优先级 | 命令面板 / 批量 / 工具栏 / 拖拽上传 | 三读数 / 证据行 / URL 语义 / 键盘地图 | **不同**：从编辑效率转向核对效率 |
| 搜索实现 | 已落地 `CommandPalette` + `/api/search` | 大厅 SSR 结果行，撤回面板 | **更好**：JS 预算更省、可分享 |
| 状态表达 | 灯 / 色 | 文字 + 口径（含「本地记录」） | **更好**：不编造也不留白 |
| 落地成本 | V3 已全批次落地（B0–B4 完成），边际近 0 | 视觉层全量重写 + 撤回 3 条已落地路由 + 改写打印/灯箱/代码块/主题规格；无新增依赖 | **更贵**：贵在推翻已验证且已运行的资产，不在新建 |
