## 二、踩坑记录（现象 → 根因 → 修复）

### 坑 1：Tailwind v4 静默跳过 `.gitignore` 的目录
- **现象**：在详情页写好了桌面端双栏的 `lg:grid` 布局，但在浏览器实测时发现右侧的 TOC 完全没吸附，检查 CSS 发现 `lg:grid` 类名根本没有生成。`lint` 和 `tsc` 全绿，完全查不出错。
- **根因**：详情页的路径是 `src/app/u/[handle]/logs/[slug]/page.tsx`，包含了 `logs` 这一段。Tailwind v4 在扫描源代码时，会自动读取并遵循 `.gitignore` 的规则。仓库里有一条历史遗留的 `logs/` 规则，导致 Tailwind 直接跳过了这个文件。
- **修复**：在 `globals.css` 里加 `@source inline("lg:grid lg:grid-cols-[...]...");` 强制生成兜底。尝试过用 `@source "./src/app/u"` 显式指定目录，但发现该指令同样受 `.gitignore` 过滤，只有 `inline` 是最终解。

### 坑 2：正则重建导致扫描器丢失 `/i` 标志
- **现象**：在修复敏感信息扫描脚本时，意外发现一个存在了 11 天的漏判：大写开头的 `Password = "..."` 无法被阻截。
- **根因**：`sensitive-scan.ts` 的 `findAll` 函数在提取匹配项时，使用了 `new RegExp(source, "g")`。`RegExp.source` 只包含正则的主体，不包含 `i` 这个标志，导致原本“大小写不敏感”的扫描器变成了严格的大小写敏感。
- **修复**：改为 `new RegExp(source, originalFlags + "g")` 继承原有标志。并补了一条“大小写不敏感”的回归测试钉死这个缺陷（先红后绿）。

### 坑 3：应用内浏览器不派发 IntersectionObserver 通知
- **现象**：TOC 目录画出来了，但在浏览器里滚动页面时，目录的高亮项不跟着变，顶部的进度条也一动不动。
- **根因**：在沙盒或应用内浏览器（Webview）里，引擎底层的渲染层被隔离，`scrollTop` 变化时不会派发 `IntersectionObserver` 或 `ScrollTimeline` 的回调。
- **修复**：确认不是代码缺陷（用现场新建的实例对照验证），改用 iframe 做几何实测。算法层用真实几何在 5 个滚动位复算，确认逻辑自证正确。

## 三、今日结论
TOC 的加入让长篇日志的阅读体验有了质的飞跃。同时，那两个极其隐蔽的坑（Tailwind 依赖 gitignore、正则重建丢标志）让我们深刻认识到：**自动化门禁（CI、lint、tsc）只能保证“代码能编译”，不能保证“页面是对的”**。必须依赖真实的浏览器几何实测。
