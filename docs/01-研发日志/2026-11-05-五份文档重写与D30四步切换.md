## 三、D30 令牌切换：四步、每步一 commit、四类漂移点一次改全

纸白 `#FBFBF9` → `#f4f1ec` 只是第一步。真正决定这步会不会留尾巴的是**同一个颜色在几个地方各写一遍字面量**：

| 步骤 | 令牌 | 同批必须改的漂移点 |
|---|---|---|
| 纸白 | `--background` | `--color-paper` 改为引用它；`proxy.ts` 404 内联页背景 |
| A1 主墨 | `--foreground` | `--color-ink` 与 `:focus-visible` 的 outline **由字面量改为引用**；`proxy.ts` 三处主墨（body 文字、链接文字、`a:hover` 下边框） |
| A2 辅助灰 | `--color-ink-soft` | `blockquote` 的 `var(--color-ink-soft, #5c5c5c)` **整个去掉回退值**；`proxy.ts` 两处 |
| A3 极细线 | `--color-hairline` | `proxy.ts` 的 `a` 下边框 `#E7E7E2`，**绑同一条 commit** |

A2 去回退值之前先做了一件事：实测产物 CSS 里 `@theme inline` 确实输出 `--color-ink-soft:#625d53` 且 `color:var(--color-ink-soft)` 成立。**如果 Tailwind 只做内联替换不落变量，去掉回退值会静默失效**——这类"框架行为假设"必须先验再改，改完再验一次。

A3 我把 `--color-hairline` 与 `proxy.ts` 的字面量绑成一条 commit，理由很直白：分两条就会出现"全站暖线、404 页冷线"的中间态，而这正是这一天要消灭的那类漂移。实算 `#d9d2c5/#f4f1ec` = 1.33:1，我要求同时写一句"I073 已裁定装饰性分隔线豁免 3:1，本处实算仅作留档，不作为验收门槛"——**豁免是裁定，不是数据被推翻**，两件事必须同时留在文档里。

B1 引入全站唯一强调色 `--brown #7a5a3a`，只给持久导航的当前项（文字 + 1px 下划线），非文本对比实算 5.56:1。B1 落地后我发现一件事：首页的"当前态"由字标 LAITY 承担，它仍是主墨、按下边框也不在 `SECTIONS` 分支里——**棕色只在其余三页出现**。我没有让助手顺手改，而是让它把这条不一致原样记进 AGENTS/DESIGN/方案文档三处，等下一轮点名。下一轮我选了微调方案（下划线走 `border-brown`、文字保持 `text-ink`），单独一条 commit `a9aba42`。现在全站任何时刻只有一个元素带棕色下划线。

## 四、/about 上线：清单里两条配套点被实测证明不需要改

F19/D31 的配套清单原本写了五处：新增页面、`routes.ts` 归属判定、`sitemap-data.ts`、`SiteNav`/`SiteFooter`、SPEC 的 F19 追溯行。实测下来两条不用动：

- `src/lib/routes.ts` **不需要改**——它按 `/admin`、`/login` 黑名单判前台，`/about` 天然公开；
- `SiteFooter` **也没改**——页脚本就不含导航项，"页脚给入口"由既有的隐私/许可入口承担。

这提醒我：清单是"改一处要跟着改哪里"的假设集，不是事实集，**每条都要拿实测判据结一次账**。三条完成判据齐备才算落地：`id="main"`、`aria-current`（浏览器 hydrated DOM 里仅「关于」项带）、`generateMetadata`；未配置 `SITE_CONTACT_EMAIL` 时「待补充」以斜体渲染且 `mailto` 数为 0——**没有虚构联系方式**。

新页面确实吃了材料窗口容量：`about/page.tsx` 让 ④ 段涨 155 行，`assertWindowFit()` 第七次拒绝出件，按它的建议把 `not-found.tsx` 从 ④ 平移进折走段 ③ 才放行。这条写进清单：**新增前台页要先预留窗口容量**。

## 五、踩坑记录（现象 → 根因 → 修复）

### 坑 1：对比度这类数字，"切完就达标"是想当然

- 现象：外部三份设计产物（优化方案、整合方案、原型 HTML）一致收敛到 `#f4f1ec` 体系，方案表里给了 `--rule #d9d2c5`、`--rule-strong #b9b0a0`，读起来像是"换了令牌体系顺带把对比度问题解决了"。
- 根因：把设计意图当成了工程结论。我让助手做第 5 条指令的全站核查时明确"只做核查、不改代码"，它按 WCAG 2.1 相对亮度公式对**源码实抽的前景/背景配对**逐对计算，结论是切完之后 1px 分隔线仍只有 1.33:1，`--rule-strong` 也只有 1.91:1；真要达 3:1，线色得压到 `#948a77` 一档，那就不是"极细线"了。
- 修复：分两刀。文本层没有任何问题（最差 5.56:1，AA 档位与切换前同档）；线层按"装饰性分隔线、非功能性组件边框"裁定豁免，记 I073 WONTFIX，同时把**方法边界**写进处置栏——后续轮次直接复用这个结论，不必再跑 `getComputedStyle` 复核，因为源码层已覆盖全部实际用到的颜色组合。
- 同一类错误在别处也犯过：A2 与 B1 的 commit 正文里曾写过"余量约 32/34 行""余量吸收了后续增长"这类没有实测支撑的数字与因果句，后来在收口轮当场重算后改成如实表述。规矩就此定死：**文档里的数字一律当场重算，历史读数不作当前值用**。

### 坑 2：等行替换被误判为"不动行数"，材料窗口第八次拦下

- 现象：A1 那轮只改了四处色值、没加逻辑，跑生成器却被 `assertWindowFit()` 拒绝出件。
- 根因：文件头注释铁律要求每次修改追加一行修改记录。`proxy.ts` 与几个组件各加一两行，①+② 段就被顶过 1500 行切口，`proxy.ts` 尾部被切在外。**窗口容量按整页折算，不是固定 1500 行**——末页只有 9 行也占一个整页名额。
- 修复：按"折排版不折逻辑"选让位者，而不是按行数最少机械挑。第八次拦下时助手选了 67 行的 `StatusBoard.tsx`，没选行数更少的 62 行 `Timeline.tsx`，判断依据是 SPEC 是否点名了该文件的形态——`Timeline.tsx` 是 F02 点名的 Before/After 时间轴，不折；`StatusBoard.tsx` 只是把 `getArchiveBoard()` 的结果排版成行，可折。这条判据当天固化进 AGENTS 的「软著材料生成铁律」，并给「已知坑速查」加一行。
- 另一处配套：让位者必须同时看它承载的不是不是需求点名的界面形态。机器建议是默认路径，但负责人点名"先报后动"时以点名为准（A2 就明确要求先看清被切的文件与行范围再定）。

### 坑 3：dev 的 SSR 静态壳与 hydrated DOM 不一致，归因是假设就只能记 OPEN

- 现象：`/about` 实施完成后，用 curl 取 dev 返回的 HTML，静态壳里**缺 `/about` 导航项、也没有 `aria-current`**，导航只剩两项；但同一份源码在生产构建的预渲染产物 `.next/server/app/about.html` 里三项齐全，浏览器 hydrated DOM 也正确。
- 根因（假设，未闭环）：`.next/dev` 里编辑前留下的预渲染缓存。证据只有"同源码在生产产物里输出正确"这一条，**没有做清缓存复现的对照**，也没有在缓存存在时反复取到同一结果。
- 修复：按判据缺口定性——记 I074 **OPEN** 而不是 FIXED，处置建议里写明"清缓存复现一次才定性"，并补一条方法：**导航类/静态壳类判据不要用热更过程中的 dev HTML，要用生产构建产物或清缓存后的 dev**。这一条也写进了当天几条 commit 正文：验 hydrated DOM 之前先用 `list_pages` / `location.href` 确认自己真的在目标页上——此前有过一次 `location.pathname` 还停在首页却以为在读日志详情页的误判。

### 坑 4：我引号里的"原句"，文件里并不存在

- 现象：文档收口第 1 项让我"清理三处'首页不一致待点名'的过期记录"。助手没有直接动手，而是先 grep 出清单：文件里实际写的是「**留给负责人的一条不一致**」（AGENTS、DESIGN）与「一条**留待点名的不一致**」（方案文档），README 挂账清单里还有一句「首页当前态仍用主墨（待点名）」。条数与语义都对得上，字面没有一处是我引号里的写法。
- 根因：人复述自己文档时的措辞必然漂。如果按描述去"找一句最像的"改，就会改到不该改的句子。
- 修复：助手的处置正确——**停下来报清单**，把每一处的实际原文、所在行号、以及"哪些是历史留痕不该动"一次列全，我逐条批。同轮还定了一条配套口径：修订留痕里的历史文字（包括我裁断的逐字引用）不碰，修文档是修**当前事实**，不是修历史。
- 顺带把一类隐性矛盾收掉：同一份文档里「已实施」与「仍待做：B1」并存（DESIGN 的 D30 状态段与实施进度段自相矛盾）、留痕条目里带"现"字的句子过期（SPEC 的"现只余 C2/D30 的剩余令牌切换待批准"）。判据统一成一句：**带"现"字的状态描述必须与事实一致，历史留档的措辞保留**。

### 坑 5：未 push 的 commit 里引用了它自己的哈希，会自指过期

- 现象：AGENTS 续十二要记"D30 文档收口本轮 amend 追加三处过期表述"，而我给的措辞是"见 `cc8f3ca`"。这句话本身就在被 amend 的那条 commit 里，写完哈希立刻失效。
- 修复：助手没有照抄，改成"原 commit `cc8f3ca`，本次 amend 以替换该条生效，故最终哈希以 `git log -1` 为准"，并在动手前先报备这处偏离。我采纳。amend 前它每次都先 `git log -1 origin/main` 证明这条 commit 没被推走——`bf5acd3 → cc8f3ca → 99013d3 → 48b371b` 三次 amend 都是这么安全过来的。

## 六、这一天我判对了什么、判错了什么

判对的是把 D30 切成四步、每步一 commit 并强制"停下报 diff"。A2 那次要求"先报被切的文件与行范围再动"，结果窗口没被拒；A3 把 `proxy.ts` 绑进同一条 commit，避免了一个中间态。判对的另一件事是第 12 条那句"对不上先问我"——它把一个本来会演变成"AI 自己挑句子改文档"的坑挡在了 grep 之后。
