## 二、踩坑记录（现象 → 根因 → 修复）

### 坑 1：Windows 下 Prisma 引擎被锁定（EPERM）
- 现象：改了 `schema.prisma` 后，跑 `npx prisma migrate dev`，终端报 `EPERM: operation not permitted, rename ...query_engine-windows.dll.node`。
- 根因：本地的 Next.js dev server（`npm run dev`）还在后台跑着，它加载了 Prisma 的查询引擎 DLL。Windows 系统不允许覆盖正在被进程占用的文件。
- 修复：停掉 dev server 进程，再跑迁移。教训：以后改数据库结构，先关本地服务。

### 坑 2：React 受控组件读不到最新值
- 现象：编辑器写好了，用户改了 textarea 里的字，但点击 `[ AI 帮我写 ]` 时，发给 AI 的还是修改前的旧内容。
- 根因：在按钮的 `onClick` 里直接读 React 的 `state` 拿到的是旧快照。
- 修复：使用 `new FormData(formRef.current)` 序列化表单，直接从 DOM 里拿用户输入的真实最新值。

## 三、今日结论
AI 接入不是简单的套壳 API，它涉及到 Prompt 的健壮性、Token 的成本管控（设置了 12 次上限）以及合规的边界（必须打上 `[ AI 辅助生成 ]` 的存证标签）。另外，生产环境的 SSL 证书申请（Let's Encrypt 走 DNS 验证）与阿里云备案拦截，也让我深刻体会到了国内 Web 开发环境的特殊性。
