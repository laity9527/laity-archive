## 四、踩坑记录（现象 → 根因 → 修复）

### 坑 1：`font-mono` 与 `font-sans` 混排，被 flex 的 `gap-x-6` 撑出 24px

- 现象：按"数字与日期留等宽、中文走 Inter"拆 span，写成 `<span class="font-sans">1 篇日志</span> <span class="font-mono">· 2026-11-04</span>` 之后，界面上"1 篇日志"和日期之间出现一道明显空隙，像漏了一个字段。
- 根因：这两个 span 是 `<li class="flex flex-wrap items-baseline gap-x-6 …">` 的**直接子元素**，`gap-x-6` = 24px 对它们同样生效。CSS 的 gap 只认 flex/grid 子项关系，不认"语义上是一组"。
- 修复：两段包进同一个外层 span，外层只留 `ml-auto` 与字号色，字体类下沉到内层。改完在浏览器里量了真实数字：两段之间 **0px**、`top` 差 **0px**（`items-baseline` 下 mono 盒高 +2px 不产生跳动）、格子右缘与行右缘齐平 **0px**。同一个坑在访客详情页的「始于 + 日期」上又踩一次，直接按包 span 的写法处理。
- 一条连带裁定：为什么不能整行 `font-sans` 只给日期加宽字距？因为视觉铁律写死"时间戳强制 JetBrains Mono"，那是合规级约束，不是审美偏好。这条冲突当天以授权方式改进铁律本身：**时间戳、数字与英文标识强制等宽；中文标签走 Inter 并移除大写字母专用的宽字距**（AGENTS 续十三）。
- 量测方法也记一条：`/` 是 `◐` PPR 路由，浏览器里动态段还挂在 `<template>` 内不参与布局，`getBoundingClientRect()` 全 0；`/admin` 又需要登录。所以用同一套 class 造了一份临时副本注入当前页、量完即删（返回 `removed: true`，未写库未改文件）。**读不到布局时先问是不是 PPR 壳，不要急着下"没生效"的结论。**

### 坑 2：把 `" ".repeat` 摘成短别名，`this` 丢了

- 现象：批量替换脚本里写 `const pad = " ".repeat;` 然后 `pad(4)`，直接抛 `TypeError: String.prototype.repeat called on null or undefined`。
- 根因：方法一离开接收者就废——`repeat` 需要在某个字符串上调用，摘下来当裸函数传时接收者是 undefined。这不是 Node 版本问题，是 JS 语义。
- 修复：写成箭头函数 `const pad = (n) => " ".repeat(n);`。同类风险点当场一起改：脚本里所有 `arr.join`、`s.split` 形式的短别名一律包一层函数。
- 沉淀：批量脚本里的"短别名"要么写成完整调用，要么写成函数包装，**不允许直接摘方法引用**。已写进 AGENTS 已知坑速查。

### 坑 3：工作区 CRLF 与 LF 混用，多行匹配永不命中

- 现象：第三批的批量替换脚本对 `src/app/admin/logs/new/page.tsx` 报"标签未命中"，但同一份模式对 `src/app/page.tsx` 正常。看上去像文案根本不存在，我差点判它是清单写错了。
- 根因：仓库里两种行尾**并存**——没被工具重写过的文件是 CRLF 检出，被 Edit 或脚本重写过的变成 LF。脚本用 `"\n"` 拼的多行模式在 CRLF 文件里永远匹配不上，而单行替换不受影响，所以症状是"一部分文件能改、一部分报未命中"。
- 修复：脚本按文件自身探测行尾（`s.includes("\r\n")`）再拼模式，写回时保留原行尾；落笔前用 `node -e` 打印目标片段的 JSON 看真实字节，而不是凭 Read 的显示猜。已写进 AGENTS 已知坑速查。
- 同一条坑的另一面：`Edit` 工具的 `old_string` 只占半行时会把标签或引导句吞掉、留下残句（这一天真的发生过一次，AGENTS 里那句被切成残行，靠按行号 splice + 锚点断言的脚本修回）。**改中文长行改用脚本按行替换，落笔后数结构而不是看 diff**。

### 坑 4：文档里的代码行号是易腐数据

- 现象：D30 方案文档的表格里写 `src/proxy.ts` 的字面量在「55、61、62」行。今天因为 404 文案改动按铁律追加了 2 行文件头，实际位置已经漂到 62、65、67、68、69 一带；同一张表的 `globals.css` 行更早就过期了——它写的 94、139 指向 blockquote 回退值与 `:focus-visible`，而这两处在 A1/A2 已改成引用令牌、字面量根本不存在了。
- 根因：文件头注释铁律要求每次修改追加记录，被引用的文件行号必然随每轮改动漂移。写死行号等于埋一颗定时炸弹。
- 修复：**把定位从绝对行号换成可搜索锚点**——"以 `color:` 与 `border-bottom-color:` 所在行为准""以五个令牌的定义行为准"，同时保留一句"2026-11-06 实测在 ×× 一带"作参考，并写明它为什么不作数。表格的「内容」列（旧色值）不动，那是方案文档当时的分析，属历史留档。
