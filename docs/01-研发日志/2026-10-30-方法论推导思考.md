# 2026-10-30 研发日志：一套开发工作法的推导过程

作者：张磊
日期：2026-10-30
背景：Laity 档案库刚起步，仓库骨架准备入库。今天没急着写代码，先把"我以后到底该怎么指挥编程助手干活"这件事想透了。这篇是完整的思考过程，结论沉淀在 docs/00-开发方法论/我的AI协作开发方法论-五层防线.md。

## 一、先想清楚我到底在防什么

用编程助手这段时间，翻车不外乎三种：

第一种，它擅自换我的技术栈、加我没批准的依赖。我明明定了 Next.js + Prisma，它写着写着给我冒出别的方案。

第二种，需求说一句"帮我做个 XX"，它替我做了二十个隐含决策——权限模型、分页策略、错误码格式全是它自己定的，其中至少五个跟我想要的不一样，而且埋到几千行代码之后才暴露。

第三种，它说"已完成、测试通过"，我一跑就崩。它给自己打了满分。

往深挖，三种翻车其实是三个根因：

1. **它不知道**——每次会话都失忆，我不给项目事实，它就拿通用最佳实践填空；
2. **目标模糊**——我的需求没边界，它就自由发挥；
3. **验收主观**——"质量良好"这种话没法证伪，它说过关就过关。

想通这一点后我的心态变了：不是指望助手"自觉"，而是把它当一个执行力很强但每天失忆的初级工程师来管。管理靠制度，不靠信任。

## 二、逐层推导

### 为什么先建"事实基座"

失忆问题没法靠每次口头重复解决——我总有一次会忘说。所以事实必须落成文件（AGENTS.md），让它每次自动加载。

写这个文件时我悟出一条：**禁令比鼓励有效十倍**。"禁止引入新依赖"是可以机械检查的，"尽量用现有技术"只会被自由发挥。同理，视觉规范不能写"简洁大气"——助手对这四个字有一万种理解，对 border-radius: 0 只有一种。纸白文献风的每个色值、每条形态规则都要量化到能被 grep 检查的程度，不然产出永远一股模板味。

### 为什么要三道确认门禁

我复盘过：跑偏最贵的不是写错代码，而是**错误决策被默认通过**。所以需求 → 规格 → 方案，每一步都让它停下来等我确认。特别是第一步，我要求它先复述约束、最多问三个阻塞性问题——复述错了我当场就能纠正，成本几乎为零；等它写完三千行再纠正，一天就没了。

规格阶段我加了条狠规则：禁止出现"待定""视情况而定"。写不出来的地方就是它没想清楚的地方，必须变成问题抛回给我，而不是糊过去。

### 为什么坚决拒绝一次性生成全部代码

这条是我态度最强硬的。一口气生成全部代码的问题不在"生成"，在于错误会**复利**：第一层的地基错了，上面每一层都跟着错，最后没法归因，只能全部推倒。

所以按 Phase 拆，而且 Phase 1 必须是贯穿前后端的最小纵向闭环——哪怕只有一条数据的增查。我否掉的备选方案是横切分层（先全部实体、再全部服务、再全部页面），那种拆法把联调风险全推到最后一刻。纵向闭环让技术栈问题、联调问题在第一个 Phase 就炸出来，此时返工最便宜。

配套的硬约束还有两条：每个 Phase 列出允许触碰的文件清单（清单可以用 git diff --stat 机械核查，比"只做登录模块"这种自然语言硬得多）；单 Phase 不超过 15 个文件，超了继续拆。

### 为什么验收要"可证伪"，还要换个会话审

"登录功能完善"不可验收，"传错误密码返回 401 + 错误码 AUTH_001"可验收。我给自己定了标尺：验收标准必须是「可执行命令 + 预期输出」或「可观察的具体行为」，出现"稳定""健壮""良好"就打回重写。

而且我发现一个更隐蔽的坑：**同一个会话里，助手倾向于维护自己先前的输出**。让它自己审自己，基本查不出问题。所以验收开新会话，用独立审查者的身份，逐条跑命令、贴真实输出、给 PASS/FAIL，不许因为"整体看起来不错"放行 FAIL 项。

还有一条前置经验：验收标准要在设计阶段就逼它写出来。写不出验收标准的功能，往往就是它自己也没想清楚的功能——这时候该拆需求，不是硬写。

### 为什么加了第五层"过程存证"

这层是做软著准备时想通的。前四层都在管"代码对不对"，但还有一件事同样重要：**怎么证明这是我主导创作的**。

答案是把开发过程本身变成一条证据生产线：

- docs 下除方法论目录外，分研发日志、测试记录、功能截图、软著材料四个证据目录；
- 每个源码文件顶部手写文件头注释（文件/描述/作者/日期/修改记录）；
- 每天把发给助手的指令原文、我的思考、踩的坑记进日志；
- 验收通过截带地址栏的运行图；
- commit message 用我自己的一句话写，把工具自动生成的英文描述删掉——全中文、有真实感受的记录，比机器翻译腔有力得多。

想通后有个反直觉的结论：**助手修错的过程比修对的结果更有证据价值**。因为那些"现象 → 我判断根因 → 修正"的记录，恰恰证明了人在主导判断和取舍。所以踩坑不许删，照实记。

## 三、今天顺手记下的几个坑

审自己之前拿到的骨架方案时，发现三处要修的：

1. **骨架先行的阶段没有可运行验证。**没有本地环境时先出配置和静态骨架入库，这个降级路径本身没问题（今天就能做，比"先装三天环境"强），但骨架正确性全靠肉眼。补救：有环境后第一件事是回头验证这批产物，不能默认它们是对的。
2. **方案里的版本号是拍脑袋的。**写着 Next.js 14 的用法，但项目约定里明确警告过：本项目要用的 Next.js 版本有 breaking changes，API 和旧版不一样。而且我核实了一下，本地目前什么都没装（仓库还是空的），任何"已验证能跑"的说法都没有依据。教训写进红线：版本事实以 node_modules 里的实际文档为准，禁止凭记忆用旧 API。
3. **数据库配置偷懒。**compose 文件里的 version 字段已是废弃写法，root/root 弱口令也就本地开发能忍，上线前必须换。这类"能跑但不合格"的细节，正是独立验收要抓的。

## 四、今天的结论

五层防线定稿：事实基座、规格锁定、阶段闭环、验收门禁、过程存证。所有门禁——前三道确认（需求、规格、方案）加上每个 Phase 的验收——共同点是：助手必须停下等我，不许滑过去。这是整套方法里最容易被破坏、也最需要我坚持的一点。

下一步：按这套工作法，对 Laity 档案库跑一次门禁 1（复述现状约束），然后补 SPEC.md 和 DESIGN.md，再开始 Phase 1。

## 五、同日追加：从 0 启动的三项决策与文档入库

方法论定稿后没停，直接把 Laity 从 0 启动的门禁 1 走完了。有三个方向性问题我拍了板：

1. **后台登录选 GitHub OAuth**（否掉账号密码和暂缓登录）。理由：个人站不用存密码、不用做注册找回，白名单只放我自己的账号 ID 进去，实现最简、攻击面最小。
2. **部署定在自有服务器 Docker + Nginx**（否掉暂不上线和托管平台）。理由：原方案就是这么推演的，数据自己攥着；代价是要自己管运维，用 standalone 小镜像防 OOM。
3. **本地环境近期就装**（否掉降级骨架路线）。理由：Phase 1 必须是可运行真闭环，这是工作法的硬规则——环境早一天装好，骨架产物早一天被验证，"看起来没问题"早一天变成"跑出来没问题"。

基于这三项决策，今天入库了从 0 启动的全套文档：

- SPEC.md：P0 九条 / P1 两条功能清单、Prisma 建表草案、Server Action 接口契约与错误码、非目标清单（评论区、搜索、commits 统计这些花活明确不做）；
- DESIGN.md：六条架构决策记录（每条含被否备选和代价）、六个 Phase 路线图（每个 Phase 有文件清单和可执行验收命令）、七项风险及降级方案；
- README.md、ISSUES.md（已登记 3 条：废弃 compose 字段与弱口令、旧骨架 API 不可采信、AGENTS.md 登录行待同步）、.gitignore；
- 环境搭建指南（含 npmmirror 下 npm audit 必报错、WSL2 虚拟化、Prisma 文件锁三个已知坑）和每 Phase 复用的自测表模板。

一个值得记的取舍：防伪哈希的口径我在设计阶段就定死了（SHA-256 覆盖标题+双正文，UTF-8），而不是等写代码时随手定。这种口径类的东西一旦有历史数据就不能再改，属于"现在不想清楚、以后没法补救"的决策——正好印证了"验收标准前置"那条经验。

当前状态：SPEC 和 DESIGN 都处于"待确认"，我在走门禁 2/3 的审阅，确认之前一行实现代码都不写。

## 六、同日追加：Phase 1 开工记录（代码侧跑通，数据库被环境卡住）

"继续"之后正式开 Phase 1。先说环境实况的意外：Node 其实已经装了（v24.13.0），Docker CLI 也有（29.9.2），和 AGENTS.md 里"全部未装"的旧记录不符，这条要更新。但 Docker Desktop 起不来，一查根因是 **WSL2 没装**——`wsl --status` 直接告诉我系统没启用 Linux 子系统。装 WSL2 要管理员权限加重启，属于提权级改动，我不自己动，停下来留给我本人处理。

**版本红线这次真撞上了**：脚手架拉下来的是 Next.js 16.4.3，不是旧方案里以为的 14。三个没见过的新东西：
1. 布局组件的 props 用 `LayoutProps<"/">` 类型化写法，不再是手写 children 类型；
2. Tailwind 是 v4，`@import "tailwindcss"` + Turbopack loader，没有 tailwind.config；
3. 默认开启 Cache Components + Partial Prefetching，页面里直接读未缓存数据（比如数据库）必须包 `<Suspense>`，否则构建和 dev 都会报 blocking-route。

所以日志大厅写成了"静态壳 + Suspense 包一个异步查库组件"，构建产出的路由表是 `/logs` 部分预渲染，符合文档描述。要是凭记忆写 Next 14 那套，这一步就翻车了。

**Prisma 版本做了一个保守决定**：最新稳定版已经是 7.x，但 7 的生成器和配置文件体系都变了，和我按老写法定好的 schema 对不上。锁定 6.19.3，跟设计文档保持一致，升级的事另外立项（记进 I005）。

**一处主动的范围偏差**：Phase 1 文件清单里没有 src/lib/logs.ts，但 AGENTS.md 红线要求前台只能走 getSafeLogs 封装。红线优先于清单，我建了这个最小版封装并在自测表里明写了偏差原因，没有让页面直接查 Log 表。

**验证状态**（详见 docs/02-测试记录/Phase-1-自测表.md）：构建通过、lint 零报错、视觉红线 grep 零命中、首页真实渲染核对无误；`/logs` 页面能出静态壳但查库部分因数据库未启动而报连接错误，迁移、种子、真数据展示四项全部"未验证"，没有粉饰成通过。

**待办**：我本人装 WSL2 并重启 → 启动 Docker → 建库迁移种子 → 回填自测表 → 截图 → 独立验收 → 提交。

## 七、同日追加：Phase 2 前台三页（等 WSL2 期间先把不依赖库的活干完）

WSL2 在下载，我没干等，先把 Phase 2 里不碰数据库运行的部分推完：字体、主题、三个组件、首页、日志大厅、详情页和 Markdown 管线。运行期验收等库起来统一回填，自测表里如实标"未验证"。

**坑一：`searchParams` 放页面顶层会把静态壳打掉。** 日志大厅第一版在页面函数里直接 `await searchParams`，构建立刻报 "encountered uncached or runtime data during prerendering"，`/logs` 整页失败。根因是 Cache Components 下静态壳不允许等待请求期数据。改成把 searchParams 的 Promise 传进 Suspense 子组件里再 await，壳保住了，筛选项照样从 URL 取。

**坑二：详情页要真 404，就不能"先出壳后报错"。** 未发布 slug 如果放在 Suspense 里判空，状态码已经流式发出去了，只能是 200 带 404 内容——验收标准要的是 404。框架给了明确出口：`export const instant = false` 把该段标记为允许阻塞，先查完再决定输出，`notFound()` 就发生在流式之前。这条是路由段配置，不是 build 配置，我按红线边界判断后加了，并写进自测表。

**依赖门禁走了一遍。** DESIGN D4 锁定的渲染管线要 react-markdown 和 rehype-sanitize，AGENTS.md 说新增依赖必须停下来报批，所以我停了一轮：列出 10.1.0 / 6.0.0、MIT 许可、用途和"不装就做不了 F03/F09"，批准后才装。装完顺手审了传递依赖：84 个包，83 个 MIT，1 个 ISC（宽松许可，不是 GPL 系），记进自测表。

**清洗不是嘴上说，跑了一遍。** 用 react-dom/server 渲染含 `<script>`、`onerror`、`javascript:` 的正文，输出里三个危险特征全部为 false，`alert(1)` 只剩纯文本。这只是组件级证据，浏览器级等库起来再补。

**字体要验到"真有中文"，不能只看配置写没写。** next/font 接完我查了构建产物：`.next/static/media` 里 6.3MB woff2、一堆 50–100KB 分片，是 Noto Serif SC 的中文 unicode-range 分片。要是只有几十 KB 的拉丁子集，中文就会悄悄回退到系统宋体，那种"配置正确但效果不对"最坑。

**又一处范围偏差。** Phase 2 验收第 2 条要求详情页显示哈希，但种子数据原本没有 contentHash。我在 prisma/seed.ts 里按 D5 口径现算 SHA-256 写进去——这个文件不在 Phase 2 清单里，但验收标准点名要它，我选择服从验收并在自测表明写偏差，没有默默改。

**验证状态**（详见 docs/02-测试记录/Phase-2-自测表.md）：构建通过、lint 零报错、视觉 grep 零命中、清洗组件级通过、字体中文分片确认；草稿隔离、详情印章、375px 三项等数据库。

## 八、同日追加：自己抓到一个"看起来通过"的错判——真 404 只能靠 Proxy

验证详情页时我拿 curl 打了一条不存在的 slug，状态码是 200。上一节我还写"`instant = false` + `notFound()` 就能在流式之前返回 404"，这条判断是错的，得当着记录改掉。

翻 node_modules/next/dist/docs：流式响应固定以 200 开头，`notFound()` 只有赶在正文开始流式之前调用才保得住状态码；本项目开了 Cache Components，详情页有预渲染的静态壳，响应头必然先发出去，页面级判空只能是"200 + 404 页面"。框架文档给的出口写在 loading.md 里：动态路由要真 404，在 Proxy 里前置判定，然后重写或直接返回 404 响应。

到底哪种写法管用，我没猜，做了三组探针：Rewrite 带 `{status:404}` → 实测 200，`rewrite()` 会把 init 摊进响应，但被重写路由自己的状态码盖掉；直接 `new NextResponse(html, { status: 404 })` → 404，状态码和正文都在。所以定案：新增 src/proxy.ts，matcher 只圈 `/logs/:slug`，查一次 `select id` 判断有没有这条已发布日志，没有就直接返回纸白极简 404 页，带 noindex 和 no-store（日志发布后同一个 URL 必须立刻能回到 200，不能让 CDN 把这次 404 缓存住）。

查询走了 `src/lib/logs.ts` 的 `isPublishedLogSlug()`，不图省事在 Proxy 里裸查 Log 表——前台数据只走封装这条红线，Proxy 也算前台。这条改动超出了 Phase 2 原清单，我停下问了一轮，批准后补进 DESIGN 的 D7 和 Phase 2 文件清单，连带把 Phase 3 的 `src/middleware.ts` 改成 `src/proxy.ts`（Next 16 已把 middleware 更名 Proxy，同一个文件往上扩鉴权即可）。

数据库还没起，所以现在 `/logs/*` 全部 500：`Can't reach database server`。这是"诚实失败"，不是把 404 兜底成 500——库不可用就说不可用，不能假装这条日志不存在。404 分支和 200 分支都要连库才验得了，自测表第 1 条继续记"未验证"，不因为探针 C 过了就写成 PASS。

**验证状态**：lint 无输出、build 退出码 0（路由表出现 `ƒ Proxy (Middleware)`）；本轮同步改了详情页那条误导性注释和自测表的错误表述。

## 九、同日晚间：WSL2 到位，数据库闭环终于跑通

WSL2 装好之后我以为一步就能到底，实际连着踩了三脚。

**第一脚：装了 WSL2，Docker 还是起不来。** `wsl --status` 已经显示默认版本 2，`docker ps` 照样报 `Docker Desktop is unable to start`。翻后端日志看到一句 `still waiting for the engine to respond to _ping after 1h51m`——它从 WSL2 装好之前就开始等了，一直没重试。用 `docker desktop stop` / `start` 重启后端，引擎立刻正常。教训是：装环境不是装完就好，得看那个依赖它的进程有没有重新建立连接。

**第二脚：Docker Hub 连不上。** `docker compose up -d` 报 `dial tcp 108.160.169.174:443: connectex`，本机没有代理，官方 registry 探测是 000。这事我不敢自己拍：镜像从哪来属于依赖来源问题，停下问了一轮。你选了镜像站拉取 + 本地打标，我就按这个做——`docker pull docker.m.daocloud.io/library/postgres:16` 拿到 digest `sha256:1beaa308…77c61c`，`docker tag` 成 `postgres:16`，一个 Docker 配置文件都没改。镜像不是官方直连来的，这条我记进 ISSUES I007，日后有代理可以重拉覆盖。

## 十四、自建登录页：先读源码，才知道 /admin/login 不能用

**指令**：我说"挂在我手上的三件事先不处理，剩下的根据计划继续"。计划里下一步 Phase 5b 卡在 OSS 密钥，于是问了两个决定：5b 依赖走哪条（我把 `npm install --dry-run` 的真实包数摆出来：`ali-oss` 68 个、`@alicloud/oss20190517` 47 个、零依赖自写签名 0 个），我选 A 官方 `ali-oss`（MIT）；空档期做什么，我选"建 `/admin/login`（I012-B）"。

**"建 /admin/login"这句我自己写的话，读完源码发现不能用。** `node_modules/next-auth/core/index.js` 的 GET 分支里 `case "signin"`：只要配置了 `pages.signIn`，`/api/auth/signin*` 的 GET 一律 307 到那个页面。而 `/admin/login` 同时被两个守卫管着——Proxy 的 matcher `/admin/:path*` 和 `admin/layout.tsx` 里第二道 `!session → redirect`。三者首尾相接就是死循环：登录页把自己 307 给signin 接口，接口又把自己 307 回来。所以落点改成 `/login`：不在 matcher 里、也不吃 admin 布局。这条判断没有靠记忆，是靠读 `core/index.js` 得出的。

**为什么必须再来一个客户端组件。** 登录动作只能由带 `csrfToken` 的 POST 发起，而 `next-auth.csrf-token` 只在 `/api/auth/*` 的响应里铸造；服务端渲染的 `/login` 首次访问时手里根本没有这个 cookie，隐藏字段填不出值。所以按钮交给 `next-auth/react` 的 `signIn("github", { callbackUrl })`，它自己取 csrf 再 POST。D3 原来写"仅编辑器、筛选器两处客户端组件"，实际筛选器压根没用客户端组件——一并改成"编辑器 + 登录按钮两处"，并把原因写进 D3。

**等价验证这次被拦了。** 想沿用 Phase 3 的手法（本地 `NEXTAUTH_SECRET` 签一枚 `githubId` 会话）验"已登录访问 /login 自动跳回"和"白名单外账号被拦"，运行时安全策略直接判成"读取高敏感凭证 + 越权测试"拒了。我不绕，标成未验证记 I017。能做的替代：把 `safeCallbackUrl` 当纯函数在 node 里跑判表——`//evil.com/x`、`https://evil.com`、空值全部回落 `/admin`；再去 `core/lib/default-callbacks.js` 确认 v4 自己的 `redirect` 回调对非本站 origin 也回 `baseUrl`。两层兜底都有据，但"真跑通"仍要等我登录一次（I010）。

**一个小返工。** 首版错误提示写的是 `{errorCode} · {ERROR_TEXT[errorCode] ?? errorCode}`，结果未知码会原样打出来——`GET /api/auth/signin/github` 因为 `pages.signIn` 的解析怪味，跳过来带的是 `error=github`，页面上就成了"github · github"。改成只给中文文案、不回显裸码。

**顺手赚到一条证明。** 用 375px 隐藏 iframe 量响应式时，顺便在同一个 iframe 里加载 `/admin`：最终渲染出来的是登录页文本、`scrollWidth=375`、越界元素空数组。浏览器只有在重定向链断开后才会交出内容，所以这同时证明了没有死循环——这是设计时最怕的那件事，用一条本来就打算跑的探针顺手验掉了。

**收尾**：`lint` / `tsc` / `build` 全部退出 0，路由表新增 `ƒ /login`；红线 grep `ZERO_MATCH`；`"use client"` 恰好两处。没往库里写任何数据，服务停掉、端口释放。

## 十五、Phase 6 环境准备：本地能装，不等于 linux 能装

**指令**：我说"按建议继续，完成 Phase 6 的环境准备"——只做能在本机验的那半（镜像、编排、反代、门禁），域名证书生产 OAuth 还在我手里。

**第一个坑花了最久，而且不是我的坑，是 lockfile 的。** `docker build` 死在 `npm ci`：`Missing: @emnapi/runtime@1.11.3 from lock file`。诡异的是同一条命令在我 Windows 上 `--dry-run` 干干净净。我把同一份 lock 挂进 `node:24-slim` 容器只读复现，才确认这是**平台差异**：`@img/sharp-wasm32`、`@tailwindcss/oxide-wasm32-wasi`、`@unrs/resolver-binding-wasm32-wasi` 这些只在 wasm32 路径上才需要的边，Windows 生成 lock 时压根没写进去，而 linux 的 npm 校验阶段就要。`--omit=optional` 也救不了——校验发生在解析之前。

**改 lockfile 是红线，所以我先取证据再问。** 在容器里用 `--package-lock-only`（不装任何包）重算一份放到临时目录，逐条比：条目 570→578、**0 删除、0 版本变化**、`lockfileVersion` 仍是 3、resolved 仍是 `registry.npmmirror.com`，新增的 8 条全是 `@emnapi/*` 和 oxide-wasm32 名下的嵌套依赖。再拿这份新 lock 在容器和本地两侧各跑一次 `npm ci --dry-run`，都退出 0。数据摆完你才批下 A 方案。中间还有一次自我纠正：我先用 `cmp` 确认验证过程没把仓库里的原 lock 改掉，才敢往下走。

**第二个坑是 Prisma 的一句告警。** 容器里第一次跑查询，`prisma:warn Prisma failed to detect the libssl/openssl version … Defaulting to "openssl-1.1.x"`。原因：我特意选 `node:24-slim` 躲开 alpine 的 musl 坑，但 slim 只带 libssl3，**没有 `openssl` 可执行文件**，而 Prisma 是靠它判版本的。修法是在 deps 和 runner 两个阶段都 `apt-get install -y --no-install-recommends openssl`，重建后镜像内 `openssl version` → `OpenSSL 3.0.22`，日志里 grep 告警为 `0`。这类"跑起来了但有告警"的东西不能留，它会在某次系统升级后变成跑不起来。

**第三个发现最值钱：compose 的"必填"根本拦不住弱口令。** 我在 `docker-compose.prod.yml` 里写了 `${POSTGRES_PASSWORD:?…}`，空值确实报错（`required variable … is missing a value`），但拿 `root/root` 去试，`config` 退出码是 **0**——照放。而风险清单里那条是"上线门禁硬卡：口令不改不发版"。所以我加了 D12：一次性 `preflight` 容器判 root 用户、root 口令、口令与用户名同名、长度不足 12、`NEXTAUTH_URL` 不是 https 或还指向 localhost、`NEXTAUTH_SECRET` 短于 32、白名单为空，任一条就非零退出；db 服务 `depends_on: preflight (service_completed_successfully)`。实测 `up -d` 直接被拦停：`service "preflight" didn't complete successfully: exit 1`，db 停在 `Created` 从未启动。**"硬卡"这个词要么写成代码，要么就是句口号。**

**读文档而不是猜的两处。** Next 官方 `output.md` 明写 standalone **不含** `public` 与 `.next/static`，要手工拷——所以 Dockerfile 里那两条 COPY 不是多余；另外 `PORT`/`HOSTNAME` 由环境变量决定监听，runner 里显式设成 `3000` / `0.0.0.0`。

**顺带赚到几条证明。** 空库起栈时我先打了一轮路由：`/projects/earth-mirror` 返回 **404**——库里还没数据，说明 Proxy 的前置判定在容器里照常生效。再把 Phase 2 第 1 条和 Phase 4 第 3 条搬进镜像内跑：`docker compose run --rm migrate` 建表，探针脚本用镜像自带的 `@prisma/client` 灌一条已发布 + 一条草稿，经 nginx 抓取后草稿在 `/`、`/logs`、`/projects`、`/projects/probe6` 命中全是 `0`、`/logs/probe6-draft` **404**，印章 `CONTENT HASH · 8eecb417…` 与容器内独立重算 `match: true`。同一镜像、同一条链路，上线只是换个环境。

**没验成的老实记着。** HTTP/2 我只 `curl -sI` 没带 `--http2`，读到的还是 `1.1`，所以 h2 是否协商上标未验证；`node:24-slim`、`nginx:1.27-alpine` 是走 daocloud 镜像站拉的（docker.io 直连仍超时，同 I007），摘要已留档但没跟官方逐层比对（I019）；线上域名、受信证书、生产 OAuth App、docs/04 全部等 6b。

**收尾**：`down -v` 把容器与卷都清掉，`tmp/` 下的冒烟 env、自签证书、覆盖文件、探针脚本全删；本地 `npm run lint` / `tsc` / `build` 退出码 `0 / 0 / 0`。
