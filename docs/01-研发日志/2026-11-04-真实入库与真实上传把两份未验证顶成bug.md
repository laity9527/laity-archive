## 二、把本项目自己当第一条数据，这个决定本身要记

本地库被我清空以后，最省事的做法是 `npx prisma db seed` 把示例数据灌回去——种子脚本里现成有一个"地球 Mirror"项目和一条讲索引预构建的日志，十秒就能让前台不再是空列表。我没这么做。理由是：这个软件的核心卖点是"发布即存证"，如果印章下面压的是一条我为了演示编出来的情景，那前台每一条公开摘要都在替一个不存在的项目说话；而且用种子回填等于把"新建项目 → 存草稿 → 保存并发布 → 前台读摘要"这条真实路径整个绕过去，绕过去的部分恰恰是最容易埋 bug 的部分。

于是第一条数据就是这次入库这个动作本身：项目 `laity-archive`（Laity 项目档案库，product / WIP），日志 `archive-itself-as-first-entry`，正文写"为什么不能用假数据"。发布后前台印章是

```
73020c50d142c3d7affd6211d0f6ee9dae80ec4a26875df9d6ed0b880358f15b
PUBLISHED AT · 2026-11-04 10:59 UTC
```

我没有直接信它。让助手在浏览器里把服务端从库里渲染出来的标题、BEFORE、AFTER 三个值原样取回，按 D5 口径（`title + "\n" + before + "\n" + after`，UTF-8）用 `crypto.subtle` 独立重算一遍 SHA-256，与页面印章逐字符比对——一致。这条判据的价值不在于"哈希算对了"，而在于它证明**盖章的内容就是我看到的那份内容**：先存再发（D25）与摘要口径（D5）这两件事在真实数据上闭环了。

## 三、踩坑记录（现象 → 根因 → 修复）

### 坑 1：填了仓库地址，点"保存"没反应

- 现象：新增项目时把 `https://github.com/laity9527/laity-archive` 填进 REPO URL，点保存后页面纹丝不动——没有跳转、没有红色横幅、没有控制台报错，看上去像按钮坏了。
- 根因：上一轮为了让"最常见的错误在提交前就出不去"，我在 `src/app/admin/projects/page.tsx` 写了 `pattern="https?://\\S+"`。**JSX 的字符串属性不做 JS 转义**，所以浏览器拿到的属性值里是两个反斜杠，等价于要求 URL 中真有一个反斜杠字符，任何合法地址都通不过 `checkValidity()`；而原生校验拦截是不发请求的，页面自然毫无反应。
- 修复：源串搬到 `src/lib/forms.ts` 做单源（`REPO_URL_SOURCE`，反斜杠写一个），服务端的 `REPO_URL_PATTERN` 从同一份派生，`tests/forms.test.ts` 加一条"同一 source 在浏览器的 `v` flag 与 Node 的正则里判定必须一致"。加上上一轮那条 `SLUG_SOURCE`，两条坑合起来定了一条口径：**正则字面量的 `.source` 不能直接喂给 HTML 属性**——`pattern` 属性按 `v` flag 编译，`[a-z0-9-]` 这种尾随连字符在其中还是非法字符类。记 I060。
- 顺手记下读数方法：`f.checkValidity()` 只告诉我"表单无效"，真正指认凶手的是 `[...f.elements].filter(e => e.willValidate && !e.checkValidity())`。我最早一次归因归错了——以为超长标题被拦，实际无效的是空着的 slug。

### 坑 2：图片上传的"未验证"，真相是一次也没成功

- 现象：后台点"插入图片"选一张图，永远回"图片不合格：仅支持 jpg / png / webp / gif，且不超过 5MB。"（IMG_001）。这句话我在 AGENTS.md、Phase-5b/6/7 自测表和上线手册里以"未验证"的名义写了十几遍。
- 第一层排除：先在 Node 里用同一份 `sniffImage()` 跑这张 PNG，返回 `{ext:'png',mime:'image/png'}`——**类型判定是好的**，如果我只信那句文案就会一头扎进 magic bytes 里。剩下的三个 IMG_001 出口从页面上分不开，我在动作里临时把形状数字通过既有 `code` 字段带回页面（只带数字，不带文件内容、不带凭据，测完删掉），拿到 `blob=70 ab=70 type=image/png`。
- 根因之一：`upload-action.ts` 判的是 `formData.get("file") instanceof File`，而 Server Action 的参数跨 React 边界反序列化后落地的是 **Blob**。任何文件都被判成"类型不合法"。这条从 Phase 5b 起就在，一直被记成"没条件验"。
- 根因之二：改判 Blob 之后仍然 IMG_001。看服务端日志里动作耗时从 7ms 变成 248ms（开始真走网络）才确认过了这一关，回头查 `oss.ts` 里那句 `!/^[a-z0-9./-]+$/.test(key)`：对象名的时间戳来自 `toISOString()`，里面必然带大写 `T` 和 `Z`，而断言只允许小写——**它把自己生成的每一个键都判死**。
- 根因之三（写回归测试时才现形）：这条断言的白名单里 `.` 和 `/` 本来就在，`logs/../etc/passwd` 完全通过。注释里写的"排除目录穿越"此前是假的。现在改成逐段判：空段、`.`、`..` 全拒，并要求整体落在 `logs/` 前缀下，和 RAM 策略的 `resources` 限定对齐。
- 结构处置：把键的生成与断言从 `oss.ts` 拆成 `src/lib/object-key.ts`。理由和当初把 `sniffImage` 拆成 `image-signature.ts` 一模一样——留在原文件里就进不了 `node --test`（那会拉起 ali-oss），于是"生成器比断言宽松"这种矛盾只能靠人肉撞见。
- 端到端判据：70 字节合法 PNG 两次上传都回 `已上传 · 70 字节`，直链
  `https://laity-archive.oss-cn-beijing.aliyuncs.com/logs/2026-11/20261104T112157Z-72fc4931e9ca.png`
  能作为图片加载（`naturalWidth=1`）。这里记一条方法：直链跨域，`fetch()` 会被 CORS 挡（报 `Failed to fetch`），**不能用 fetch 判可达性**，改用 `<img>` 的 `onload/onerror`。
- 收尾：探针图片没有进任何日志正文（编辑器里的引用已回退，未落库）；桶里两个 70 字节对象由我手工清理或交给生命周期规则——应用按设计没有删除权限。记 I061、I062。

### 坑 3：原生校验这类东西，不读控制台就等于没生效

上一轮我以为给字段加了 `pattern`/`maxLength` 就是加了一道防线。这一天连着两次被同一条打脸：`SLUG_PATTERN.source` 进了 `pattern` 会让浏览器报 `Invalid character class`（控制台里静静躺着一条 error），`REPO_URL_SOURCE` 写错转义则是静默不提交。**声明式校验必须去控制台和 `checkValidity()` 里核对一次**，光看代码写完就宣布生效是不成立的。

### 坑 4：材料窗口第五次拦人，我的自检脚本又先报了假错

`④` 段因为给正文标题补样式涨了十几行，把 `globals.css` 的头部切在后窗口外，`assertWindowFit()` 直接拒绝出件。按它给的处置把 `src/app/privacy/page.tsx`（88 行、纯静态承诺文案）从 ④ 平移进折走段 ③。之后我自己的反查脚本 `tmp/whole-check.mjs` 报"1 个文件未整份可见"——那是它的 MUST 清单没跟着这次**有意**的分带调整更新，属清单过期而不是产物出错。这已经是同一类事第二次发生（上一轮是 `image-signature.ts`）。结论：这类自研清单是第二份真相，动完分带必须回头改它，否则下一次它会用一条假红把我引向错误的方向。

## 四、第五轮按"美观"改的七项，都没动视觉语言

前几轮已经实测过八条路由没有横向溢出、`h1` 唯一、正文 18px/1.85、最小字号对比 6.45:1，所以"美观"依旧没有可修的排版缺陷。这轮改的全是可指认的缺失：10 处状态横幅补 `role="alert"`（后台 9 处 + 登录页那条最常被读到的），编辑器的上传提示再按语义分成 `alert`/`status`；`confirmSlug` 补可访问名（此前只有 placeholder，而它要求的是"原样输入标识"这种关键信息，一输入提示就没了）；`/login` 的 `<main>` 补 `id="main"`；正文里的 `#` 由渲染出口降级成 `h2`，并给 `h4–h6` 补上字号阶内的观感——实测临时日志里 `# 一级` 与 `## 二级` 都是 24.3px Noto Serif SC、`#### 四级` 18px，页面 `h1` 总数从 2 变 1；`globals.css` 三处硬编码 `#e7e7e2` 改回 `var(--color-hairline)`；`/licenses` 三处 `text-[13px]` 归到 14px；勾选确认行 `items-baseline` 改 `items-center`。零新依赖，没碰 `next.config.ts`。

被否的：后台导航 `aria-current`——Server Component 看不到 pathname，为三个链接要么引 `headers()` 要么包一层客户端组件，代价与收益不称。

## 五、这一天里我判对了什么、判错了什么

判对的是第 11 条那个要求：**让助手去录真实数据、去查那张图**。这两件事都不在它的优化清单上，也不是读代码读得出来的；它们是唯一能把"文档里写着未验证"和"实际上根本不能用"区分开的动作。这一天两处确定性故障都是这么现形的。

判错的是我自己此前的口径：我把上传长期标成"未验证"，并以此为准做了三份文档。"未验证"这三个字在我这里是中性描述，但它的实际效果是把一条**已知的坏路径**伪装成了"待办"。从这天起改一条规矩：凡是我有本地条件跑、却因为怕麻烦或怕副作用而没跑的，不写"未验证"，写"未跑，怀疑不可用"。今天真正被安全策略正当拦下的只有那条"把删除请求指向真实项目"（`PRJ_003` 的服务端分支），那条我照旧标未实测，并且不打算换写法绕。
