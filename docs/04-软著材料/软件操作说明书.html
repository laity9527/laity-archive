Laity 项目档案库软件 V1.0 软件操作说明书
 
著作权人：张磊
开发完成日期：2026-10-30
 
 
一、软件概述
 
本软件是一套面向个人全栈开发场景的项目档案库系统，同时承担两项用途：对外作为厂牌作品展示站点
　　，对内作为开发过程与判断依据的存证载体，可用于软件著作权登记后的权属举证与日后维权。
 
系统由一个面向访客的只读站点和一个仅管理员可写的后台构成，二者共用同一套代码与同一个数据库。
　　访客可以浏览首页看板、开发日志与项目档案；管理员通过 GitHub 账号登录后，可以新建与编辑日
　　志、发布日志、维护项目条目。
 
软件的核心特征是"发布即存证"：每条日志在发布动作发生时，由服务端按固定口径计算正文的 SHA-256
　　 摘要并连同服务器时间一并写入数据库，前台详情页据此展示一枚存证印章。已发布的日志一旦被
　　再次保存，会自动退回草稿状态，原有摘要与发布时间作为历史保留，需重新发布才会按新正文重算
　　，从而保证前台展示的印章与正文内容始终一一对应。

　　• 应用框架：Next.js 16.4.3（App Router，Turbopack 构建）
　　• 语言：TypeScript 5，React 19.3.0

3.1 开发环境启动
 
　　1. 获取源码后执行 `npm install` 安装依赖。
　　2. 启动数据库：`docker compose up -d`（本地 PostgreSQL 16，端口 5432，库名 laity）。
　　3. 在仓库根目录创建 `.env` 文件，填入数据库连接串、NextAuth 会话密钥、GitHub OAuth 凭据

　　5. 启动开发服务：`npm run dev`，浏览器访问 `http://localhost:3000`。
 
 
3.2 生产环境部署

　　`。
　　6. 检查：`curl -I https://<正式域名>/logs` 应返回 200，证书受信。
 
 
3.3 上线前置门禁

　　密钥值。

五、管理端功能与操作说明
 
 
5.1 登录与登出
 
后台所有页面的访问前都会经过两道检查：请求进入应用前的统一守卫，以及后台布局内的会话检查。未
　　登录访问任意后台地址会被重定向到登录页 /login，并携带原本要访问的地址作为回调参数。
 
登录页说明准入规则后提供"用 GITHUB 登录"按钮。点击后由浏览器向鉴权接口发起带防护令牌的请求，
　　跳转至 GitHub 授权页；授权完成后回到本站。只有账号标识在允许名单内的用户才会建立会话，其
　　余情况返回登录页并显示"这个 GitHub 账号不在白名单里，登录被拒绝。"
 
允许名单比对的是 GitHub 的账号数字标识而非用户名，因为用户名可以修改而数字标识不会变。名单内
　　容存放在环境变量中，调整后即时生效。后台页面右上角提供退出入口。

5.2 后台概览
 
后台首页显示三项计数：项目总数、已发布日志数、草稿数；其下是最近改动的五条日志，逐行标注发布
　　状态、标题、所属项目与最后更新日期，并提供进入编辑页的链接与新建日志入口。
 
 
5.3 项目管理
 
在 /admin/projects 页面可以新建与编辑项目。表单字段为：标识（小写字母、数字与连字符组成，2
　　至 64 位）、名称（必填，不超过 80 字）、类型（产品、工具、站点三选一）、状态（进行中、已
　　上线、已归档三选一）、简介（不超过 200 字）与仓库地址（需为 http 或 https 开头的合法地址
　　）。
 
列表每行右侧提供编辑与删除操作。删除时若该项目下仍挂有日志，操作会被拒绝并提示"该项目下还有
　　日志，禁止删除。"；标识与其他项目重复时提示"slug 已被占用，换一个。"；字段不合法时提示参
　　数校验失败的具体规则。上述结果均通过网址参数回传并在页面顶部以带边框的提示条显示，不依赖
　　任何前端框架状态。
 
 
5.4 新建与编辑日志
 
新建入口为 /admin/logs/new。表单字段包括：标题、标识、所属项目、标签（英文逗号分隔，最多 10
　　个，每个不超过 24 字）、判断时间与验证时间、正文编辑器与经验总结。

5.5 正文插图上传
 
编辑器工具条提供"插入图片"入口，点击后由系统文件选择框挑选本机图片，选择框默认只列出 png、jp
　　eg、webp 与 gif 四类。选中文件交由服务端的上传动作处理，浏览器不持有任何对象存储凭据。
 
服务端按顺序完成三道判定。先校验会话，未登录返回 AUTH_001；再校验类型与大小，文件的 MIME 类
　　型不在 jpg、png、webp、gif 白名单内，或字节数为零、超过 5 MB，一律返回 IMG_001，页面提示
　　"图片不合格：仅支持 jpg / png / webp / gif，且不超过 5MB。"；两项都通过才把文件字节写入

写入用的对象名完全由服务端生成，形如 logs/2026-11/20261102T091530Z-a1b2c3d4e5f6.png，由固定
　　前缀、年月、协调世界时时间戳与 12 位随机十六进制组成，扩展名取自 MIME 映射表，不使用上传
　　文件的原始名称；写入前还断言对象名只含小写字母、数字、点、斜杠与连字符，以排除目录穿越与
　　控制字符。前缀固定落在 logs/ 下，与子账号"只允许对该前缀写入、无删除与列举权限"的最小权
　　限策略配套；地域、存储桶名与两把密钥只来自环境变量。
 
上传成功后服务端返回公共读直链，编辑器在当前激活页签的光标位置插入 ![替代文字](直链) 形式的

正文中的图片以外链形式由对象存储直接提供，服务器本地磁盘不产生任何图片文件。前台与后台预览共

5.6 发布动作
 
点击发布后，服务端按固定口径计算正文摘要、记录服务器当前时间，并将摘要、发布时间与发布状态三
　　项在同一次写入中完成，三者缺一不可。发布成功后页面提示"已发布，前台可见"，前台对应地址即
　　时可访问。
 
摘要计算口径为：将标题、判断正文、验证正文（为空时按空字符串处理）以换行符依次拼接，取 UTF-8
　　 编码后计算 SHA-256，输出十六进制小写字符串。该口径自第一版起固定不变，任何复核者都可以
　　据此独立重算并与库中值比对。
 
 
5.7 后台操作的结果反馈
 
所有写操作的成功与失败都通过页面提示条与网址参数表达，可复核、可截图留证。参数不合法、标识重
　　复、记录不存在等情况分别对应独立错误码，详见第九章。
 
 
六、数据模型与存证机制
 
 
6.1 数据表

系统包含两张表。项目表记录标识、名称、类型、状态、简介与仓库地址；日志表记录标题、标识、所属
　　项目、标签数组、判断正文、验证正文、判断时间、验证时间、是否已发布、经验总结、正文摘要与
　　发布时间，并维护创建与更新时间。
 
日志表按"是否已发布 + 判断时间"以及"所属项目"建立索引，前台列表与筛选查询直接命中索引。
 
 
6.2 时间处理
 
所有时间一律以协调世界时（UTC）存储，展示层再做转换；页面显示的发布时间明确标注 UTC 时区。表
　　单录入使用本地时间控件，写入时转换为 UTC。
 
 
6.3 草稿隔离
 
前台读取日志的唯一入口在数据访问层强制附加"已发布"条件，页面代码无法绕过该条件查询日志表；项
　　目页的日志条数与最近日期同样只统计已发布记录，因此草稿既不会出现在任何列表，也不会影响计
　　数。
 
 
6.4 存证完整性
 
摘要只在发布动作时写入，与发布时间同步产生。正文任何改动都会使日志退回草稿，避免"摘要对应旧
　　正文、页面显示新正文"的失效状态。历史摘要与历史发布时间在退回草稿时保留，供后台展示与追
　　溯，不做清除。
 
 
七、安全设计
 
　　• 富文本安全：所有 Markdown 渲染统一经过清洗管线，脚本标签、事件属性与危险协议链接会被剥

　　离；代码中不存在直接注入 HTML 的写法。
　　• 越权控制：后台地址在请求前置守卫与页面布局两处校验会话与账号白名单；写操作在服务端动作
　　内部再次校验会话，不依赖前端隐藏按钮。
　　• 输入校验：所有写操作的字段长度、格式、取值范围与时间先后关系均在服务端判定，不信任浏览
　　器提交值。
　　• 上传边界：正文插图的类型白名单、大小上限、对象名前缀与字符集全部在服务端裁定，对象名不
　　使用上传文件的原始名称；写对象所使用的凭据只放在环境变量中，对应子账号仅有向固定前缀写入
　　的权限，无删除与列举权限；服务器本地磁盘不保存任何上传图片。
　　• 凭据管理：数据库连接串、会话密钥、OAuth 凭据、白名单与对象存储的两把密钥只存放在环境变
　　量中，本地环境变量文件与生产环境变量文件均不纳入版本库；仓库内只保留不含真实值的模板文件
　　。
　　• 传输与响应头：生产环境由反向代理终结 TLS，仅启用 TLS 1.2 与 1.3，并下发严格传输安全、
　　内容类型嗅探禁止、来源引用策略与同源框架限制等响应头；应用容器仅绑定本机回环地址，外部流
　　量必须经过反向代理。
　　• 搜索引擎控制：404 响应与后台页面均带禁止索引标记。
　　• 数据库访问边界：数据库结构变更只能通过声明式模型文件与生成的迁移脚本完成，运行期不提供
　　任何执行任意 SQL 的入口。
 
 
八、备份、升级与故障处理
 
　　• 数据备份：使用 PostgreSQL 自带的逻辑备份工具定期导出整库，备份文件存放于服务器之外的存
　　储。
　　• 版本回滚：每个开发阶段形成独立提交，出现问题时按阶段回滚，不做跨阶段连环回退。
　　• 数据库不可用：前台页面会显示加载失败，日志与项目的详情地址返回服务端错误而非伪装成不存
　　在，属于诚实失败，便于第一时间定位。
　　• 会话失效：任何后台操作遇到会话过期都会回到登录页并提示重新登录，不会静默丢失已填写内容
　　以外的状态。
