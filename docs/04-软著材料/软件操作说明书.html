Laity 项目档案库软件 V1.0 软件操作说明书
 
著作权人：张磊
开发完成日期：2026-10-30
 
 
一、软件概述
 
本软件是一套面向个人全栈开发场景的项目档案库系统，同时承担两项用途：对外作为厂牌作品展示站点
　　，对内作为开发过程与判断依据的存证载体，可用于软件著作权登记后的权属举证与日后维权。
 
系统由一个面向访客的只读站点和一个仅管理员可写的后台构成，二者共用同一套代码与同一个数据库。
　　访客可以浏览首页看板、开发日志与项目档案；管理员通过 GitHub 账号登录后，可以新建与编辑日
　　志、发布日志、维护项目条目。
 
软件的核心特征是"发布即存证"：每条日志在发布动作发生时，由服务端按固定口径计算正文的 SHA-256
　　 摘要并连同服务器时间一并写入数据库，前台详情页据此展示一枚存证印章。已发布的日志一旦被
　　再次保存，会自动退回草稿状态，原有摘要与发布时间作为历史保留，需重新发布才会按新正文重算
　　，从而保证前台展示的印章与正文内容始终一一对应。

　　• 运行时：Node.js 24（开发与容器构建均使用该主版本）
　　• 应用框架：Next.js 16.4.3（App Router，Turbopack 构建）
　　• 语言：TypeScript 5，React 19.3.0

三、安装与部署
 
 
3.1 开发环境启动
 
　　1. 获取源码后执行 `npm install` 安装依赖。
　　2. 启动数据库：`docker compose up -d`（本地 PostgreSQL 16，端口 5432，库名 laity）。
　　3. 在仓库根目录创建 `.env` 文件，填入数据库连接串、NextAuth 会话密钥、GitHub OAuth 凭据

　　、允许登录的账号白名单，以及对象存储的地域、存储桶名与两把写入密钥。
　　4. 生成并应用数据表结构：`npx prisma migrate dev`。
　　5. 启动开发服务：`npm run dev`，浏览器访问 `http://localhost:3000`。
 
 
3.2 生产环境部署
 
　　1. 复制 `.env.production.example` 为 `.env.production`，填写生产数据库用户名与强口令、正
　　式域名、生产会话密钥、生产 GitHub OAuth 凭据、账号白名单、对象存储的地域、存储桶名与两把
　　写入密钥（生产建议另建子账号密钥，不与开发环境复用），以及 ICP 备案号。备案号属非敏感信
　　息，未填入时页脚不显示该行。
　　2. 将 TLS 证书放置于 `deploy/certs/` 目录，并确认 `deploy/nginx.conf` 中的域名与证书路径
　　一致。
　　3. 构建镜像：`docker compose --env-file .env.production -f docker-compose.prod.yml build
　　`。
　　4. 应用数据库迁移：`docker compose --env-file .env.production -f docker-compose.prod.yml
　　 run --rm migrate`。
　　5. 启动服务：`docker compose --env-file .env.production -f docker-compose.prod.yml up -d
　　`。
　　6. 检查：`curl -I https://<正式域名>/logs` 应返回 200，证书受信；`curl https://<正式域名
　　>/api/health` 应返回 `200` 与 `{"status":"ok","db":true}`，数据库不可达时该端点返回 `503
　　` 且 `db:false`。应用容器的健康探针即以该端点的 `db` 字段判定容器健康，因此"容器 healthy
　　"同时代表进程在、路由通、且应用真能连上库；入口网关等应用转为健康之后才启动。
 
 
3.3 上线前置门禁
 
编排中设有一次性检查服务，在任何业务容器启动之前校验环境变量：数据库用户名或口令不得为默认弱
　　口令、二者不得相同、口令长度不得少于 12 位、站点地址必须为 https 开头的正式域名且不得指
　　向本机、会话密钥长度不得少于 32 位、账号白名单不得为空。任一条不满足，整个启动流程直接失

　　败，数据库容器不会被拉起。检查通过时仅输出脱敏信息（用户名、口令长度、域名），不回显任何
　　密钥值。
 
在上述检查之前，应用容器所需变量已在编排的插值阶段被标记为必填：数据库用户名与口令、站点地址
　　、会话密钥、OAuth 凭据与白名单、对象存储的地域与存储桶名及两把密钥。任一缺失时编排命令在

　　流水线使用一次性数据库服务容器，其中所有配置值均为占位内容，不含任何真实环境的凭据。

4.1 首页
 
页面顶部为厂牌标语与一句话定位。其下是精选项目区：从已有已发布日志的项目里按最近发布时间取前
　　三条，每条目给出名称、类型、当前状态、日志条数与简介，名称链接到该项目详情页；区头右侧提
　　供"全部作品"文字入口指向项目列表页。尚无已发布日志的项目不进精选区。
 
再往下是档案状态看板，逐行列出全部项目——包括尚未发布任何日志的项目——每行包含状态灯、项目名称
　　、类型、当前状态、日志条数与最近一次记录的日期；没有已发布日志的项目显示"尚未发布"，其条
　　数计为 0，不用创建时间冒充更新时间。状态灯为实心圆点表示项目处于已上线状态，空心圆点表示
　　其他状态；项目名称同样链接到详情页。
 
最后是最新日志列表，展示最近发布的三条日志，每条左侧为时间轴，右侧为标题与所属项目、标签。

4.5 站点导航与抓取规则
 
前台每一页顶部为同一套持久导航：左侧字标指向首页，右侧依次为"开发日志""作品档案"，当前所在项
　　以文字下划线与 aria-current="page" 双重标记；后台与登录页不叠加第二层导航。导航首个可聚
　　焦元素是"跳到正文"链接，键盘用户按一次 Tab 即可跳过导航直达正文，正文容器带对应的锚点标

每个页面有独立的标题与描述：列表页使用固定文案，日志详情页的标题即日志标题、描述优先取"经验

五、管理端功能与操作说明
 
 
5.1 登录与登出
 
后台所有页面的访问前都会经过两道检查：请求进入应用前的统一守卫，以及后台布局内的会话检查。未
　　登录访问任意后台地址会被重定向到登录页 /login，并携带原本要访问的地址作为回调参数。
 
登录页说明准入规则后提供"用 GITHUB 登录"按钮。点击后由浏览器向鉴权接口发起带防护令牌的请求，
　　跳转至 GitHub 授权页；授权完成后回到本站。只有账号标识在允许名单内的用户才会建立会话，其
　　余情况返回登录页并显示"这个 GitHub 账号不在白名单里，登录被拒绝。"
 
允许名单比对的是 GitHub 的账号数字标识而非用户名，因为用户名可以修改而数字标识不会变。名单内
　　容存放在环境变量中，调整后即时生效。后台页面右上角提供退出入口。

5.2 后台概览
 
后台首页显示三项计数：项目总数、已发布日志数、草稿数；其下是最近改动的五条日志，逐行标注发布
　　状态、标题、所属项目与最后更新日期，并提供进入编辑页的链接与新建日志入口。
 
 
5.3 项目管理
 
在 /admin/projects 页面可以新建与编辑项目。表单字段为：标识（小写字母、数字与连字符组成，2
　　至 64 位）、名称（必填，不超过 80 字）、类型（产品、工具、站点三选一）、状态（进行中、已
　　上线、已归档三选一）、简介（不超过 200 字）与仓库地址（需为 http 或 https 开头的合法地址
　　）。
 
列表每行右侧提供编辑与删除操作。删除时若该项目下仍挂有日志，操作会被拒绝并提示"该项目下还有
　　日志，禁止删除。"；标识与其他项目重复时提示"slug 已被占用，换一个。"；字段不合法时提示参
　　数校验失败的具体规则。上述结果均通过网址参数回传并在页面顶部以带边框的提示条显示，不依赖
　　任何前端框架状态。
 
 
5.4 新建与编辑日志
 
新建入口为 /admin/logs/new。表单字段包括：标题、标识、所属项目、标签（英文逗号分隔，最多 10
　　个，每个不超过 24 字）、判断时间与验证时间、正文编辑器与经验总结。

　　预览与前台使用完全相同的清洗与渲染管线，因此不会出现后台预览正常而前台异常的差异。

5.5 正文插图上传
 
编辑器工具条提供"插入图片"入口，点击后由系统文件选择框挑选本机图片，选择框默认只列出 png、jp
　　eg、webp 与 gif 四类。选中文件交由服务端的上传动作处理，浏览器不持有任何对象存储凭据。
 
服务端按顺序完成三道判定。先校验会话，未登录返回 AUTH_001；再校验内容类型与大小——类型判定读
　　取文件头部的签名字节，不采信浏览器上报的 MIME 类型：PNG 的八字节签名、JPEG 的 FF D8 FF、
　　GIF 的 GIF87a/GIF89a、WEBP 的 RIFF….WEBP 之外一律拒绝，字节数为零或超过 5 MB 同样拒绝，
　　均返回 IMG_001，页面提示"图片不合格：仅支持 jpg / png / webp / gif，且不超过 5MB。"因此
　　把可执行文件改名成 .png 或伪造上报类型都无法通过；两项都通过才把文件字节写入阿里云对象存
　　储。
 
写入用的对象名完全由服务端生成，形如 logs/2026-11/20261102T091530Z-a1b2c3d4e5f6.png，由固定
　　前缀、年月、协调世界时时间戳与 12 位随机十六进制组成，扩展名取自上一步的内容签名判定结果
　　而非上传文件名，不使用上传文件的原始名称；写入前还断言对象名只含小写字母、数字、点、斜杠
　　与连字符，以排除目录穿越与控制字符。前缀固定落在 logs/ 下，与子账号"只允许对该前缀写入、
　　无删除与列举权限"的最小权限策略配套；地域、存储桶名与两把密钥只来自环境变量。

5.6 发布动作
 
点击发布后，服务端按固定口径计算正文摘要、记录服务器当前时间，并将摘要、发布时间与发布状态三
　　项在同一次写入中完成，三者缺一不可。发布成功后页面提示"已发布，前台可见"，前台对应地址即
　　时可访问。
 
摘要计算口径为：将标题、判断正文、验证正文（为空时按空字符串处理）以换行符依次拼接，取 UTF-8
　　 编码后计算 SHA-256，输出十六进制小写字符串。该口径自第一版起固定不变，任何复核者都可以
　　据此独立重算并与库中值比对。
 
已发布的日志在编辑页会多出"下架"动作：点击后服务端只把发布状态翻回未发布，前台立即不可见，而
　　历史摘要与上一次发布时间原样保留、正文不做任何改动，页面提示"已下架，前台不再可见，历史
　　摘要与发布时间保留"。下架与"修改正文自动退回草稿"是两条不同路径：后者由保存动作触发，前
　　者由管理员显式发起，两者的历史留痕规则一致。

5.8 彻底删除
 
编辑页底部提供"彻底删除"表单：连正文、内容摘要与发布时间一起从数据库中移除，不可恢复，与"下
　　架"是两条不同路径。由于不可逆，确认方式不是弹窗按钮，而是要求在原样输入框中填写该条日志
　　的标识；服务端把输入值与库中标识比对，不一致则返回 LOG_004 并且不执行任何删除。
 
删除只作用于数据库中的文字内容。正文里引用过的图片对象不会被应用删除——写入对象存储使用的密钥
　　只有上传权限，没有删除与列举权限，这是刻意的最小权限配置，为它扩权限反而降低安全性；遗留
　　对象由存储桶的生命周期规则清理。删除成功后回后台概览并提示"该条日志已彻底删除"。

六、数据模型与存证机制
 
 
6.1 数据表
 
系统包含两张表。项目表记录标识、名称、类型、状态、简介与仓库地址；日志表记录标题、标识、所属
　　项目、标签数组、判断正文、验证正文、判断时间、验证时间、是否已发布、经验总结、正文摘要与
　　发布时间，并维护创建与更新时间。
 
日志表按"是否已发布 + 判断时间"以及"所属项目"建立索引，前台列表与筛选查询直接命中索引。
 
 
6.2 时间处理
 
所有时间一律以协调世界时（UTC）存储，展示层再做转换；页面显示的发布时间明确标注 UTC 时区。表
　　单录入使用本地时间控件，写入时转换为 UTC。
 
 
6.3 草稿隔离
 
前台读取日志的唯一入口在数据访问层强制附加"已发布"条件，页面代码无法绕过该条件查询日志表；项

　　数。
 
 
6.4 存证完整性
 
摘要只在发布动作时写入，与发布时间同步产生。正文任何改动都会使日志退回草稿，避免"摘要对应旧

七、安全设计
 
　　• 富文本安全：所有 Markdown 渲染统一经过清洗管线，脚本标签、事件属性与危险协议链接会被剥
　　离；代码中不存在直接注入 HTML 的写法。
　　• 越权控制：后台地址在请求前置守卫与页面布局两处校验会话与账号白名单；写操作在服务端动作
　　内部再次校验会话，不依赖前端隐藏按钮。
　　• 输入校验：所有写操作的字段长度、格式、取值范围与时间先后关系均在服务端判定，不信任浏览
　　器提交值。
　　• 上传边界：正文插图的内容类型（按文件头签名字节判定，不采信浏览器上报的 MIME 与文件后缀
　　）、大小上限、对象名前缀与字符集全部在服务端裁定，对象名不使用上传文件的原始名称；写对象
　　所使用的凭据只放在环境变量中，对应子账号仅有向固定前缀写入的权限，无删除与列举权限；服务
　　器本地磁盘不保存任何上传图片。
　　• 凭据管理：数据库连接串、会话密钥、OAuth 凭据、白名单与对象存储的两把密钥只存放在环境变
　　量中，本地环境变量文件与生产环境变量文件均不纳入版本库；仓库内只保留不含真实值的模板文件
　　。
　　• 传输与响应头：生产环境由反向代理终结 TLS，仅启用 TLS 1.2 与 1.3，并下发严格传输安全、
　　内容类型嗅探禁止、来源引用策略与同源框架限制等响应头；应用容器仅绑定本机回环地址，外部流
　　量必须经过反向代理。
　　• 信息最小化：运维健康端点只回答"进程与数据库是否可用"两个布尔值，错误边界与 404 页不携
　　带任何异常文本、内部路径或参数；后台与登录页在反向代理层与抓取规则层双重禁止索引。
　　• 凭据边界：对象存储写入使用只允许向固定前缀 PutObject 的子账号密钥，无删除与列举权限；
　　会话密钥、OAuth 凭据与数据库口令分处环境与编排两侧，均不进入版本库。
　　• 凭据留痕口径：密钥与口令的轮换只在过程文档中记状态（何时轮换、旧密钥是否已删除），不记
　　任何实际值；核实某个键是否合规时只输出派生判定（键名、值长度、是否等于模板值），不复述文
　　件内容。成品材料交付前逐行扫描凭据形态，且先以注入的伪凭据证明扫描规则有效，再采信"未见
　　凭据"的结论。

八、备份、升级与故障处理
 
　　• 数据备份：使用 PostgreSQL 自带的逻辑备份工具定期导出整库，备份文件存放于服务器之外的存
　　储。
　　• 版本回滚：每个开发阶段形成独立提交，出现问题时按阶段回滚，不做跨阶段连环回退。
　　• 发版门禁：代码合并前依次跑静态检查、类型检查、生产构建与纯逻辑回归测试四条（回归测试使
　　用运行时自带的测试跑器，不引入第三方测试框架），四条全绿才允许发版；回归用例锁定摘要口径
　　、图片内容签名、标识与表单校验规则、错误码文案、时间展示与路由归属判定。数据库层与需登录
　　的动作层不由其覆盖，由人工联调与运行截图留证。同一套顺序由持续集成流水线在每次提交与合并
　　请求上代跑，门禁不依赖人记得执行。
　　• 材料门禁：源程序收录清单会核对源码目录，新增文件未登记即失败；生成结果要求逐字节可复现
　　，说明正文与成品不同步同样会被拦下。收录排版按"提交窗口"设计：前后两个窗口各自必须完整容
　　纳数据模型、核心逻辑、鉴权守卫与站点外壳，任一关键文件被窗口切口打断或整段落进省略段，生
　　成程序即拒绝出件。
　　• 数据库不可用：前台页面会显示加载失败，日志与项目的详情地址返回服务端错误而非伪装成不存
　　在，属于诚实失败，便于第一时间定位。
　　• 会话失效：任何后台操作遇到会话过期都会回到登录页并提示重新登录，不会静默丢失已填写内容
