Laity 项目档案库软件 V1.0 软件操作说明书
 
著作权人：张磊
开发完成日期：2026-10-30
 
 
一、软件概述
 
本软件是一套面向个人全栈开发场景的项目档案库系统，同时承担两项用途：对外作为厂牌作品展示站点
　　，对内作为开发过程与判断依据的存证载体，可用于软件著作权登记后的权属举证与日后维权。
 
系统由一个面向访客的只读站点和一个按账号隔离的个人控制台构成，二者共用同一套代码与同一个数据
　　库。访客可以浏览首页看板、开发日志与项目档案；完成 GitHub 登录的账号各自进入自己的后台，
　　只能新建与编辑自己的日志、发布自己的日志、维护自己的项目条目，账号之间的数据互相不可见。
 
软件的核心特征是"发布即存证"：每条日志在发布动作发生时，由服务端先按提交表单保存正文，再按固
　　定口径计算该正文的 SHA-256 摘要并连同服务器时间一并写入数据库，前台详情页据此展示一枚存
　　证印章——盖上的是编辑器里那一份，而不是库里未被覆盖的旧内容。已发布的日志一旦被再次保存，
　　会自动退回草稿状态，原有摘要与发布时间作为历史保留，需重新发布才会按新正文重算，从而保证
　　前台展示的印章与正文内容始终一一对应。
 
 
二、运行环境
 
 
2.1 服务端软件环境
 
　　• 运行时：Node.js 24（开发与容器构建均使用该主版本）
　　• 应用框架：Next.js 16.4.3（App Router，Turbopack 构建）

　　• 语言：TypeScript 5，React 19.3.0
　　• 样式：Tailwind CSS 4
　　• 数据访问：Prisma 6.19.3（ORM，provider 固定为 postgresql）
　　• 数据库：PostgreSQL 16
　　• 登录鉴权：NextAuth 4.24.15，GitHub OAuth 提供方，会话为签名 JWT

三、安装与部署
 
 
3.1 开发环境启动
 
　　1. 获取源码后执行 `npm install` 安装依赖。
　　2. 启动数据库：`docker compose up -d`（本地 PostgreSQL 16，端口 5432，库名 laity）。

　　把写入密钥（生产建议另建子账号密钥，不与开发环境复用），以及 ICP 备案号。备案号属非敏感
　　信息，未填入时页脚不显示该行。
　　2. 将 TLS 证书放置于 `deploy/certs/` 目录，并确认 `deploy/nginx.conf` 中的域名与证书路径
　　一致。
　　3. 构建镜像：`docker compose --env-file .env.production -f docker-compose.prod.yml build
　　`。
　　4. 应用数据库迁移：`docker compose --env-file .env.production -f docker-compose.prod.yml
　　 run --rm migrate`。
　　5. 启动服务：`docker compose --env-file .env.production -f docker-compose.prod.yml up -d
　　`。
　　6. 检查：`curl -I https://<正式域名>/logs` 应返回 200，证书受信；`curl https://<正式域名
　　>/api/health` 应返回 `200` 与 `{"status":"ok","db":true}`，数据库不可达时该端点返回 `503
　　` 且 `db:false`。应用容器的健康探针即以该端点的 `db` 字段判定容器健康，因此"容器 healthy
　　"同时代表进程在、路由通、且应用真能连上库；入口网关等应用转为健康之后才启动。
 
 
3.3 上线前置门禁

　　流水线使用一次性数据库服务容器，其中所有配置值均为占位内容，不含任何真实环境的凭据。

5.6 发布动作
 
点击「保存并发布」后，服务端先校验会话与表单，再按这张表单的内容执行一次保存，然后按刚写入库
　　的正文计算摘要、记录服务器当前时间，并把摘要、发布时间与发布状态在同一次写入中完成，三者
　　缺一不可。这一"先存再发"的顺序是为了让所见即所发：若发布只按记录标识取库中旧内容，改了正
　　文却忘了点保存就会盖上一个与编辑器不符的摘要，而页面写的却是"按当前正文计算"。表单校验不
　　通过时既不写入也不发布，返回 VAL_001；发布成功后页面提示"已发布，前台可见"，前台对应地址
　　即时可访问。
 
摘要计算口径为：将标题、判断正文、验证正文（为空时按空字符串处理）以换行符依次拼接，取 UTF-8
　　 编码后计算 SHA-256，输出十六进制小写字符串。该口径自第一版起固定不变，任何复核者都可以
　　据此独立重算并与库中值比对。

　　不小于 16 的十六进制串——否则正文里展示的 64 位内容摘要或 40 位提交号中的数字片段会被误判
　　成手机号；而跨标点的形态（口令赋值、私钥块）必须在全文上匹配，按词元切开会永远命不中。其
　　二，邮箱只提示不拦发布，因为联系方式常常是作者有意公开的，用它设卡只会让人关掉整个功能。

　　文已经按这次表单存进库中，只是不对外公开——草稿本就只对自身可见，这一副作用换掉的是"发布

6.2 时间处理
 
所有时间一律以协调世界时（UTC）存储，展示层再做转换；页面显示的发布时间明确标注 UTC 时区。表

6.3 草稿隔离
 
前台读取日志的唯一入口在数据访问层强制附加"已发布"条件，页面代码无法绕过该条件查询日志表；项

　　数。
 
 
6.4 存证完整性
 
摘要只在发布动作时写入，与发布时间同步产生。正文任何改动都会使日志退回草稿，避免"摘要对应旧
　　正文、页面显示新正文"的失效状态。历史摘要与历史发布时间在退回草稿时保留，供后台展示与追
　　溯，不做清除。
