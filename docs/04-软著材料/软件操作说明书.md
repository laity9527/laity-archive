# Laity 项目档案库软件 V1.0 软件操作说明书

著作权人：张磊
开发完成日期：2026-10-30

## 一、软件概述

本软件是一套面向个人全栈开发场景的项目档案库系统，同时承担两项用途：对外作为厂牌作品展示站点，对内作为开发过程与判断依据的存证载体，可用于软件著作权登记后的权属举证与日后维权。

系统由一个面向访客的只读站点和一个仅管理员可写的后台构成，二者共用同一套代码与同一个数据库。访客可以浏览首页看板、开发日志与项目档案；管理员通过 GitHub 账号登录后，可以新建与编辑日志、发布日志、维护项目条目。

软件的核心特征是"发布即存证"：每条日志在发布动作发生时，由服务端按固定口径计算正文的 SHA-256 摘要并连同服务器时间一并写入数据库，前台详情页据此展示一枚存证印章。已发布的日志一旦被再次保存，会自动退回草稿状态，原有摘要与发布时间作为历史保留，需重新发布才会按新正文重算，从而保证前台展示的印章与正文内容始终一一对应。

## 二、运行环境

### 2.1 服务端软件环境

- 运行时：Node.js 24（开发与容器构建均使用该主版本）
- 应用框架：Next.js 16.4.3（App Router，Turbopack 构建）
- 语言：TypeScript 5，React 19.3.0
- 样式：Tailwind CSS 4
- 数据访问：Prisma 6.19.3（ORM，provider 固定为 postgresql）
- 数据库：PostgreSQL 16
- 登录鉴权：NextAuth 4.24.15，GitHub OAuth 提供方
- 包管理：npm
- 容器与反向代理：Docker（镜像构建为多阶段），nginx 1.27

### 2.2 硬件环境（最低）

- 处理器 1 核、内存 1 GB、磁盘 10 GB 即可运行；构建过程在内存不足时应在构建机或持续集成环境完成，服务器只负责拉取镜像并运行。

### 2.3 客户端环境

- 支持主流现代浏览器（Chrome、Edge、Firefox、Safari 的近年版本）。
- 页面为响应式布局，宽度 375 像素至 1920 像素均无横向滚动。

## 三、安装与部署

### 3.1 开发环境启动

1. 获取源码后执行 `npm install` 安装依赖。
2. 启动数据库：`docker compose up -d`（本地 PostgreSQL 16，端口 5432，库名 laity）。
3. 在仓库根目录创建 `.env` 文件，填入数据库连接串、NextAuth 会话密钥、GitHub OAuth 凭据与允许登录的账号白名单。
4. 生成并应用数据表结构：`npx prisma migrate dev`。
5. 启动开发服务：`npm run dev`，浏览器访问 `http://localhost:3000`。

### 3.2 生产环境部署

1. 复制 `.env.production.example` 为 `.env.production`，填写生产数据库用户名与强口令、正式域名、生产会话密钥、生产 GitHub OAuth 凭据与账号白名单。
2. 将 TLS 证书放置于 `deploy/certs/` 目录，并确认 `deploy/nginx.conf` 中的域名与证书路径一致。
3. 构建镜像：`docker compose --env-file .env.production -f docker-compose.prod.yml build`。
4. 应用数据库迁移：`docker compose --env-file .env.production -f docker-compose.prod.yml run --rm migrate`。
5. 启动服务：`docker compose --env-file .env.production -f docker-compose.prod.yml up -d`。
6. 检查：`curl -I https://<正式域名>/logs` 应返回 200，证书受信。

### 3.3 上线前置门禁

编排中设有一次性检查服务，在任何业务容器启动之前校验环境变量：数据库用户名或口令不得为默认弱口令、二者不得相同、口令长度不得少于 12 位、站点地址必须为 https 开头的正式域名且不得指向本机、会话密钥长度不得少于 32 位、账号白名单不得为空。任一条不满足，整个启动流程直接失败，数据库容器不会被拉起。检查通过时仅输出脱敏信息（用户名、口令长度、域名），不回显任何密钥值。

## 四、访客端功能与操作说明

### 4.1 首页

页面顶部为厂牌标语与一句话定位。其下是档案状态看板，逐行列出已有公开日志的项目，每行包含状态灯、项目名称、类型、当前状态、日志条数与最近一次记录的日期；状态灯为实心圆点表示项目处于已上线状态，空心圆点表示其他状态。再往下是最新日志列表，展示最近发布的三条日志，每条左侧为时间轴，右侧为标题与所属项目、标签。

### 4.2 开发日志大厅

访问路径为 `/logs`。页面提供两层筛选：项目维度与标签维度，均以文字链接形式呈现，选中项以下划线标识，未选中项为浅灰色。筛选状态通过网址参数传递，可直接分享带筛选条件的链接。列表每行左侧是一条贯穿的细竖线时间轴，标出该条日志的判断时间（BEFORE）与验证时间（AFTER）；右侧是所属项目、日志标题与标签。无匹配结果时显示空状态提示。

### 4.3 日志详情

访问路径为 `/logs/<标识>`。正文限宽 720 像素，采用宋体、18 像素字号、1.85 倍行距。页面按顺序展示：所属项目、标题、时间轴、标签，随后是判断阶段（BEFORE）、验证阶段（AFTER）与经验总结（LESSON LEARNED）三段内容，各段标题以等宽小字呈现。段落支持标题、列表、表格、引用、代码块与图片等常见排版。

页面底部为存证印章区块，标注"存证印章"，其下两行分别是发布时写入的正文摘要（CONTENT HASH）与发布时间（PUBLISHED AT，UTC 时区）。

未发布的日志与不存在的地址一律返回 404 状态码，响应附带禁止索引与禁止缓存标记。

### 4.4 项目档案

项目列表访问路径为 `/projects`，列出全部项目条目，每行包含状态灯、项目名称、标识与类型、当前状态、简介以及已发布日志条数与最近日期；尚无任何已发布日志的项目同样列出，条数显示为零。

项目详情访问路径为 `/projects/<标识>`，顶部展示该项目的标识、类型、状态、名称、简介、起始时间与日志条数，并在配置了仓库地址时提供外链；下方按时间轴列出该项目全部已发布日志，并提供跳转到日志大厅并按本项目筛选的链接。不存在的标识同样返回 404 状态码。

## 五、管理端功能与操作说明

### 5.1 登录与登出

后台所有页面的访问前都会经过两道检查：请求进入应用前的统一守卫，以及后台布局内的会话检查。未登录访问任意后台地址会被重定向到登录页 `/login`，并携带原本要访问的地址作为回调参数。

登录页说明准入规则后提供"用 GITHUB 登录"按钮。点击后由浏览器向鉴权接口发起带防护令牌的请求，跳转至 GitHub 授权页；授权完成后回到本站。只有账号标识在允许名单内的用户才会建立会话，其余情况返回登录页并显示"这个 GitHub 账号不在白名单里，登录被拒绝。"

允许名单比对的是 GitHub 的账号数字标识而非用户名，因为用户名可以修改而数字标识不会变。名单内容存放在环境变量中，调整后即时生效。后台页面右上角提供退出入口。

### 5.2 后台概览

后台首页显示三项计数：项目总数、已发布日志数、草稿数；其下是最近改动的五条日志，逐行标注发布状态、标题、所属项目与最后更新日期，并提供进入编辑页的链接与新建日志入口。

### 5.3 项目管理

在 `/admin/projects` 页面可以新建与编辑项目。表单字段为：标识（小写字母、数字与连字符组成，2 至 64 位）、名称（必填，不超过 80 字）、类型（产品、工具、站点三选一）、状态（进行中、已上线、已归档三选一）、简介（不超过 200 字）与仓库地址（需为 http 或 https 开头的合法地址）。

列表每行右侧提供编辑与删除操作。删除时若该项目下仍挂有日志，操作会被拒绝并提示"该项目下还有日志，禁止删除。"；标识与其他项目重复时提示"slug 已被占用，换一个。"；字段不合法时提示参数校验失败的具体规则。上述结果均通过网址参数回传并在页面顶部以带边框的提示条显示，不依赖任何前端框架状态。

### 5.4 新建与编辑日志

新建入口为 `/admin/logs/new`。表单字段包括：标题、标识、所属项目、标签（英文逗号分隔，最多 10 个，每个不超过 24 字）、判断时间与验证时间、正文编辑器与经验总结。

编辑器为双栏结构：左侧在判断正文与验证正文两个页签之间切换并输入 Markdown，右侧为实时预览，预览与前台使用完全相同的清洗与渲染管线，因此不会出现后台预览正常而前台异常的差异。

保存后页面跳转到该条日志的编辑页并提示"已保存，当前为草稿"。草稿状态的日志在任何前台页面都不会出现，直接访问其详情地址返回 404。

编辑页会回填该条日志的全部字段，并在顶部显示当前发布状态：实心圆点加 PUBLISHED 表示已发布且前台可见，空心圆点加 DRAFT 表示草稿。已发布过的日志还会显示上一次发布的摘要与时间；若当前处于草稿状态，页面会注明"这份哈希对应的是上一次发布的正文；重新发布会按当前正文重算。"

页面提供两个动作按钮：保存修改与发布。已发布的日志点击保存修改会立即退回草稿状态，页面提示"已发布的日志一保存就退回草稿，需要重新发布"，前台同时不再可见。

### 5.5 发布动作

点击发布后，服务端按固定口径计算正文摘要、记录服务器当前时间，并将摘要、发布时间与发布状态三项在同一次写入中完成，三者缺一不可。发布成功后页面提示"已发布，前台可见"，前台对应地址即时可访问。

摘要计算口径为：将标题、判断正文、验证正文（为空时按空字符串处理）以换行符依次拼接，取 UTF-8 编码后计算 SHA-256，输出十六进制小写字符串。该口径自第一版起固定不变，任何复核者都可以据此独立重算并与库中值比对。

### 5.6 后台操作的结果反馈

所有写操作的成功与失败都通过页面提示条与网址参数表达，可复核、可截图留证。参数不合法、标识重复、记录不存在等情况分别对应独立错误码，详见第九章。

## 六、数据模型与存证机制

### 6.1 数据表

系统包含两张表。项目表记录标识、名称、类型、状态、简介与仓库地址；日志表记录标题、标识、所属项目、标签数组、判断正文、验证正文、判断时间、验证时间、是否已发布、经验总结、正文摘要与发布时间，并维护创建与更新时间。

日志表按"是否已发布 + 判断时间"以及"所属项目"建立索引，前台列表与筛选查询直接命中索引。

### 6.2 时间处理

所有时间一律以协调世界时（UTC）存储，展示层再做转换；页面显示的发布时间明确标注 UTC 时区。表单录入使用本地时间控件，写入时转换为 UTC。

### 6.3 草稿隔离

前台读取日志的唯一入口在数据访问层强制附加"已发布"条件，页面代码无法绕过该条件查询日志表；项目页的日志条数与最近日期同样只统计已发布记录，因此草稿既不会出现在任何列表，也不会影响计数。

### 6.4 存证完整性

摘要只在发布动作时写入，与发布时间同步产生。正文任何改动都会使日志退回草稿，避免"摘要对应旧正文、页面显示新正文"的失效状态。历史摘要与历史发布时间在退回草稿时保留，供后台展示与追溯，不做清除。

## 七、安全设计

- 富文本安全：所有 Markdown 渲染统一经过清洗管线，脚本标签、事件属性与危险协议链接会被剥离；代码中不存在直接注入 HTML 的写法。
- 越权控制：后台地址在请求前置守卫与页面布局两处校验会话与账号白名单；写操作在服务端动作内部再次校验会话，不依赖前端隐藏按钮。
- 输入校验：所有写操作的字段长度、格式、取值范围与时间先后关系均在服务端判定，不信任浏览器提交值。
- 凭据管理：数据库连接串、会话密钥、OAuth 凭据与白名单只存放在环境变量中，本地环境变量文件与生产环境变量文件均不纳入版本库；仓库内只保留不含真实值的模板文件。
- 传输与响应头：生产环境由反向代理终结 TLS，仅启用 TLS 1.2 与 1.3，并下发严格传输安全、内容类型嗅探禁止、来源引用策略与同源框架限制等响应头；应用容器仅绑定本机回环地址，外部流量必须经过反向代理。
- 搜索引擎控制：404 响应与后台页面均带禁止索引标记。
- 数据库访问边界：数据库结构变更只能通过声明式模型文件与生成的迁移脚本完成，运行期不提供任何执行任意 SQL 的入口。

## 八、备份、升级与故障处理

- 数据备份：使用 PostgreSQL 自带的逻辑备份工具定期导出整库，备份文件存放于服务器之外的存储。
- 版本回滚：每个开发阶段形成独立提交，出现问题时按阶段回滚，不做跨阶段连环回退。
- 数据库不可用：前台页面会显示加载失败，日志与项目的详情地址返回服务端错误而非伪装成不存在，属于诚实失败，便于第一时间定位。
- 会话失效：任何后台操作遇到会话过期都会回到登录页并提示重新登录，不会静默丢失已填写内容以外的状态。

## 九、错误码对照表

| 错误码 | 出现位置 | 含义 |
| --- | --- | --- |
| AUTH_001 | 后台各写操作 | 会话已失效，请重新登录 |
| VAL_001 | 日志与项目表单 | 参数不合法，提示条中列出具体校验规则 |
| LOG_001 | 日志保存 | 日志标识已被占用 |
| LOG_002 | 日志发布或编辑 | 日志不存在，可能已被删除 |
| PRJ_001 | 项目删除 | 该项目下还有日志，禁止删除 |
| PRJ_002 | 项目保存 | 项目标识已被占用 |
| AccessDenied | 登录回调 | GitHub 账号不在允许名单内 |

## 十、本版本未包含的功能

为保证材料与实际交付一致，以下能力在本版本中明确未实现，不属于本软件的功能范围：访客评论、点赞与用户注册体系；全文检索与订阅源；多管理员与角色权限；站内图片上传与对象存储直传（该功能已列入后续版本计划，本版正文插图仅支持外部链接）；访问统计与数据埋点；移动端原生应用与小程序；多语言界面。
