三、差异化定案：三根支柱
双轴档案‌：项目 × 主题，同一判断可按项目聚合、也可按主题横切，档案库已跑通前半程。
结论裁决‌：每条轨迹带 verdict（待验证 / 已验证 / ‌被推翻‌），并公开反转率——同行只展示成功，公开被推翻的判断才是真正的信任资产。
双时间轴 + 存证‌：判断时间与验证时间分离，各自挂正文哈希与 commit，页面可自助核验。
四、日志模板：五要素 + 裁决

在现有 BEFORE / AFTER 上加五要素，成本几乎为零，说服力提升明显。

text
# D30 四步切换：四类漂移点一次改全……
BEFORE  2026-11-05 14:00 UTC ｜ 约束 ｜ 备选 ｜ 当时风险
AFTER   2026-11-05 18:30 UTC ｜ 结果 ｜ 偏差
裁决    待验证 / 已验证 / 被推翻
范围    Scope        涉及哪些模块
风险    Risk         可能破坏什么
回滚    Reversibility 怎么退回
影响    Impact       谁会受影响
标签    项目 · 主题 · commit

现有条目已符合这套结构，例如那条视觉切换记录同时挂着 WCAG 与 同 commit 同步，补上「回滚」与「影响」即可闭环。
模板落成后台表单的固定字段，非空校验纳入发版门禁。

六、后台：按内容流水线分三期

登录走 NextAuth.js 的 GitHub OAuth，白名单单账号，无 RBAC。

一期‌：仪表盘、轨迹（版本 + 裁决）、项目档案、主题管理、线索、媒体库、站点与 SEO、JSON 导入导出。
二期‌：首页区块编辑、导航菜单、外观主题、审计日志、人机验证。
三期‌：评价与品牌开关（有真实反馈再开）、RSS 完善、2FA。

关键调整：‌版本与核验页从三期提前到一期‌，它就是差异化本身，越晚补越贵。

七、数据模型：主题要独立成表

用 Prisma 管 schema 与迁移，动作字段全部 UTC 存储。

Project：slug、kind（自研 / 客户）、year、status、coverId、sortOrder。
Trace：slug、projectId、verdict、featured、currentRevId。
TraceRevision：traceId、version、bodyMd、bodyHash、gitSha，(traceId, version) 唯一。
Topic + TraceTopic：把现有的八类标签从字符串数组升级为实体，才能做出准确的横切聚合。
Lead：只存 ipHash 与 UA，‌不留明文 IP‌；Media、PageBlock、SeoMeta、SiteSetting、AuditLog 照原设计。
八、存证与核验：分三层，口径写死
站内层‌：正文规范化（统一换行、剔除零宽字符）后算 SHA-256，写入 revision，前台不参与计算。
时间锚层‌：同版本提交公开仓库，回填 commit SHA，页面与哈希并列展示。
外部锚层‌：后续按需接入可验证数据源，现阶段不做。

对外表述固定一句话：‌本站只证明「内容自发布起未被改动」与「服务记录的发布时间」，不构成作者身份、内容真实性或法律效力的认定。‌ 不提「不可篡改」「司法存证」。

九、技术实现与安全
渲染‌：前台 RSC 直查库，revalidateTag 按需重建；筛选、目录、主题切换抽为客户端组件。
存储‌：PostgreSQL 存结构化数据，图片走对象存储加 CDN，前端只拿签名直传地址。
令牌‌：沿用暖白 + 砖红变量、Inter / Noto Serif SC / JetBrains Mono 三套字体，暗色主题一等公民。
安全‌：MIME 白名单、体积上限、服务端重编码，禁止 SVG 直接外链；登录与表单限流；危险操作二次确认并记审计。
邮件‌：弃 25 端口 SMTP，改 API 型服务异步发信，失败只落日志不阻断访客。
统计‌：接 Plausible 自托管，无 Cookie、不追踪个人。
十、合规与运维：把软著当产出物

档案库自述「兼作软著登记的实物来源」，所以软著材料要进流水线，而不是临时翻找。

备案‌：ICP 备案与公安备案，服务器落地国内轻量云。
软著‌：源码归档 + 版本清单 + 轨迹导出，一次生成提交材料。
隐私与许可‌：写清表单字段用途与留存期，依赖协议逐条列出。
运维‌：/api/health 探活、日志轮转、每周 pg_dump 加 JSON 双备份并异地归档；健康检查失败与发布失败触发告警。
