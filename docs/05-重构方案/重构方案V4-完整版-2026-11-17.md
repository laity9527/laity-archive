### 1.3 六个结构性缺口（本轮真正要解决的）

1. **证据在文末，首屏不可核**：读者要滚到文章末尾才看到摘要卡，而「可核对」是这个站唯一不可模仿的资产。
2. **内容平铺，无系列、无反链**：52 个标签、53 次引用，等于每个标签约一次；标签不能替代结构，正文里的 `[[slug]]` 也只能单向走。
3. **发布后不可回看**：保存即退回草稿，旧正文被覆盖，无法回答「这一版改了什么」。
4. **操作不可追溯**：发布、下架、删除、导入没有审计行，出了问题只能翻 git 与对话记录。
5. **验证债务**：凡需登录的写路径，只能做到类型/lint/构建三维核对，「代码已改、行为未验」反复出现。
6. **文档数字漂移**：多份文档同时存在两套计数与两套材料口径，实施时无法判断哪份是基线。

## 二、方向裁定

### 2.1 三个方案的真实差异

| 维度 | A 只做收口 | B 从零「校验台」 | C 证据层混合（推荐） |
|---|---|---|---|
| 设计命题 | 纸墨克制是资产 | 可信度靠读数，不靠材质 | 纸墨是底，读数是签名 |
| 视觉签名 | 不变 | 石墨黑 + 磷光青 + 无衬线 + 2px 控件 | 不变，只加读数排版 |
| 导航 / IA | 不变 | 四项砍三项，标签与归档降为查询态 | 不变；系列作为新入口 |
| 详情页 | 文末印章 | 标题下三读数、Δ 字符差、打印小票 | 右栏三读数 + 文末印记 + 打印核对单 |
| 后台 | 通用管理面 | 发布校验台 + 三段回执 | 保留管理面，补三段回执与审计 |
| 新增依赖 / 迁移 | 0 / 0 | 0 / 0 | 0 / 3 次可空迁移 |
| 工时 | 3–4 人日 | 12–15 人日（CSS 全量重排、18 个图标重绘、打印重写） | 12–14 人日（含结构与安全） |
| 回滚 | 逐批无损 | 视觉可逆，废弃路由外链半可逆 | 逐批无损，迁移只增不删 |
| 材料影响 | 小 | 339 页源码文档全量重排 + 说明书重写 | 分批重出 3–4 次，说明书局部更新 |
| 文档风险 | 低 | 高：两套世界观长期并存 | 中：需一次归档与增补 |

### 2.2 为什么选 C

1. **护城河是「可核对」，不是「像档案」**。纸白宋体可以被任何主题复制；「发布时间 + 摘要 + 提交来源同屏可复算」不能。三读数用的都是现有字段，不改 `contentHash` 口径。
2. **B 的成本落在已验证资产上**。540 行 CSS、15 个图标、打印样式、暗色语义层都要重写；V3 的边际成本已接近 0，而 B 的视觉增益无法被现有流量证明。
3. **B 的收益无法测量**。站点没有访问统计，单人站流量也不足以做 A/B；为一个测不出的收益推翻已验证资产，不划算。
4. **C 可逆**。证据层是一个组件加一次页面重排，删掉即回到 V3；结构增量是加法，不删任何现有路由。
5. **材料与文档可分叉最小**。C 只改局部页面与说明书章节；B 要让 339 页源码文档、打印规范、图标规范全部重排。

## 三、目标、指标与非目标

### 3.1 三个目标

- **T1 首屏可核**：详情页标题下即可看到发布时间、内容摘要、提交来源；列表行自带证据读数；打印带走一张核对单。
- **T2 结构可走**：系列把单篇变成有顺序的一组；反链把「引用」变成可回看的双向关系。
- **T3 发布可证**：草稿可安全分享、每次发布留一版可回看、每个写操作留一行审计、发布后有三段回执。

### 3.2 可验收指标

| 指标 | 阈值 | 取证方式 |
|---|---|---|
| 证据覆盖率 | 100% 已发布详情页有三读数；除归档外所有日志列表行有证据行 | 页面 DOM 断言 + 抽样 5 篇 |
| 摘要唯一性 | 同一详情页完整 64 位摘要出现 ≤1 次 | `grep -o` 或 DOM 计数 |
| 反链一致率 | 已发布正文中所有命中 `[[slug]]` 的引用都有对应 `LogLink` 行 | 一致性脚本 dry-run 输出 0 差异 |
| 发布链完整性 | 100% 发布/下架/删除有审计行 | 审计页与库内计数对拍 |
| 性能预算 | 见 8.3 六项全部达标 | `log_statement=all` 数 `execute` 行 |
| 验证债务 | 每批收口时「代码已改未验」= 0 | 自测表逐项勾选或 E2E 报告 |
| 材料余量 | 后窗口余量 ≥100 行 | 生成器自报 |
| 门禁 | lint 0 / tsc 0 / test 全绿 / build 0 | CI 与本地双跑 |

### 3.3 非目标与触发条件

| 不做项 | 理由 | 触发条件 |
|---|---|---|
| 全站推翻重做 | 见 2.2 | 无（除非产品定位改为「公开核验平台」） |
| OG 分享图 | satori 需内嵌 CJK 字体，体积与稳定性不划算 | 需要社交卡片且接受静态模板时 |
| 语法高亮引擎 | 体积与维护成本高于收益 | 代码型日志占比 >30% |
| 图标库 | 违反零依赖与自绘铁律 | 永不 |
| 定时发布 | 要把「已发布」拆成「已排期/已上线」两态，牵动全部 DAL、RSS、sitemap | 每月 ≥3 次需要定时 |
| Markdown 批量导入 | 当前无迁移需求 | 待导入 >20 篇 |
| 后台列表表格化 | 33 条卡片行仍可读 | 条目 >50 |
| 全文检索引擎 | `contains` 在 12 篇规模足够 | 日志 >1000 篇 |
| `tagsKey` 双轨 | 库内无仅大小写不同的标签 | 出现第一个此类标签 |
| 人工精选 `featured` | 计算式精选已够用 | 首页需要人工排序 |
| 评论 / 点赞 / UGC | 与「无 UGC」定位冲突 | 永不 |

## 四、设计系统 v3.1（增量，不分叉）

### 4.1 令牌增补（只加语义，不加色值）

| 令牌 | 值 | 用途 | 约束 |
|---|---|---|---|
| `--readout-h` | 120px | 375 下读数压缩条最大高度 | 超出即折叠进 `details` |
| `--readout-label` | 12px / 1.5 / sans | 「发布时间 / 内容摘要 / 提交来源」 | 中文允许 12px，不再下调 |
| `--readout-value` | 12px / 1.5 / mono | 时间、哈希、sha | 仅拉丁与数字 |
| `--readout-gap` | 12px | 三读数之间 | 只用十档间距 |
| `--hash-group` | 4 字符 | 哈希分组展示 | 复制时去空格 |
| `--table-row` | 44px | 核对单与审计表行高 | 移动端 48px |
| `--stamp-rule` | 1px + 1px（间隔 2px） | 印记外框 | 复用 `rule-double` |

| 断点 | 位置 | 宽度 | 行为 |
|---|---|---|---|
| ≥1024 | 右栏顶部，与目录同一列 | 280px | sticky top 96px；目录紧随其下 |
| 768–1023 | 正文前整宽 | 容器宽 | 三行压缩，默认展开 |
| <768 | 正文前整宽 | 100% - 32px | 压缩态 ≤120px，`details` 展开完整哈希 |

**内容顺序（固定，不可换位）**

| # | 字段 | 格式 | 数据来源 |
|---|---|---|---|
| 1 | 发布时间 | `YYYY-MM-DD HH:MM:SS UTC`，mono 12 | `publishedAt` |
| 2 | 内容摘要 | 64 位小写十六进制，4 位分组，`break-all`，可复制 | `contentHash` |
| 3 | 提交来源 | 有则「GitHub 提交 · sha 前 7 位」+ 仓库链接；无则「本地记录」+ 一句口径 | `sourceCommitSha` / `repoUrl` |
| 4 | 复算口径 | 一行纯文本：`SHA-256(标题 + 换行 + BEFORE + 换行 + AFTER)`，UTF-8，小写十六进制 | 常量，单源在 `src/lib/evidence.ts` |

**状态**

| 状态 | 表现 |
|---|---|
| 正常 | 三读数齐全，摘要可复制 |
| 哈希缺失（异常） | 显示「读数暂不可用」+「该条目未完成发布写入」，不编造哈希 |
| 无提交来源 | 「本地记录」+「该条目未经 GitHub 同步，无可追溯提交」，不出现伪 sha |
| 超长/窄屏 | 哈希 `break-all`，不横向滚动；复制按钮换行不挤压 |
| 打印 | 转为顶部三栏表，含完整哈希与口径行；无按钮、无 `details` 箭头 |

**交互**

- 复制：点击复制去空格后的 64 位；按钮原位回显「已复制」，2 秒恢复，`aria-live="polite"` 播报。
- 展开：375 下 `details` 标题为「展开完整读数」；展开后焦点留在 `summary`。
- 焦点：复制按钮 `aria-label="复制完整摘要"`，命中区 ≥40×40。
- 不做：不弹 Toast、不跳页、不自动滚动。

**验收（P1 硬判据）**

1. 同一详情页完整 64 位哈希在 DOM 中出现 ≤1 次（展开前后都成立）。
2. 375 下压缩条 `getBoundingClientRect().height ≤ 120`。
3. 复制后的字符串长度为 64 且全为小写十六进制。
4. 详情页 Prisma 调用数仍为 2（P2 加反链后为 3，见 6.5）。
5. 打印预览含三读数与口径行，且不含复制按钮、目录、导航。

### 4.5 Stamp（原 Seal 的收编）

- 保留：双线外框、站点标记 `LAITY`、发布日（仅日期）、`返回顶部 / 核对读数` 锚点。
- 删除：完整哈希、复制按钮、重复的「发布时间」。
- 理由：哈希是「读数」，不是「印章」；两处展示会让「唯一权威」失效，也会让打印多一页。
- 回滚：`Seal` 组件保留在仓库但不再引用，需要时一个 import 即可恢复。

### 4.6 反模式增补（出现即返工）

1. 同一页面出现两次完整哈希。
2. 读数块用强调色填充、加边框卡片、加阴影。
3. 把三读数做成「仪表盘」或四宫格卡片墙。
4. 列表行放完整 64 位哈希。
5. 用图标替代「发布时间 / 内容摘要 / 提交来源」文字标签。
6. 为了对齐读数而引入新的间距值（非十档）。

### 6.4 反链回填（幂等，可重跑）

1. 读取全部 `isPublished=true` 的日志，只取 `id`、`userId`、`slug`、`beforeContent`、`afterContent`。
2. 复用 `extractLogLinkSlugs()` 抽取引用（上限 50），不另写正则。
3. 按 `(sourceUserId, targetSlug)` 在内存解析目标是否同一作者且已发布；未命中不写入。
4. 写入 `LogLink`，唯一键冲突即跳过；每条 source 先删旧行再插，保证重跑一致。
5. 输出报告：扫描篇数、命中引用数、解析成功数、未命中数、耗时；`--dry-run` 只打印不写。
6. 一致性脚本：对每篇已发布日志重算引用集合，与表中行对比，输出差异；门禁要求 0 差异。

### 6.6 回滚条件

- 三次迁移全部为加法，**代码回滚不需要回滚库**；旧代码会忽略新表与新列。
- 若迁移写入失败：Prisma 迁移为单事务，失败即整体回退；重跑前先 `migrate status` 核对。
- 若反链回填写错：`LogLink` 可整表清空重跑，不影响正文与哈希。
- 若预览令牌需要立刻停用：回滚路由与入口即可，链接自然 404；已发令牌随 7 天过期。

## 七、功能规格

### 7.1 日志状态机

| 状态 | 判定 | 必须字段 | 前台可见 |
|---|---|---|---|
| S0 草稿 | `isPublished=false` 且从未发布 | 标题、BEFORE | 否 |
| S1 已发布 | `isPublished=true` | `publishedAt`、`contentHash` | 是 |
| S2 已下架 | `isPublished=false` 且有 `publishedAt` | 保留 `publishedAt`、`contentHash` | 否 |

| 转移 | 触发 | 前置 | 副作用（同一事务内） |
|---|---|---|---|
| T1 保存 | 编辑器保存 | 标题非空 ≤120 字 | S1 → S0（退回草稿，保留旧印章作「上次发布」）；不写修订 |
| T2 发布 | 点发布 / 行内发布 | 敏感扫描通过或显式确认；标签合法 | 扫描 → 重算哈希 → 若曾发布则追加 `Revision`（旧版） → 写 `LogLink` → 写 `AuditEvent` |
| T3 下架 | 行内下架 / 批量下架 | 目标为 S1 | `isPublished=false`；正文、哈希、时间保留；写审计；反链读取侧自动隐藏 |
| T4 删除 | 编辑页输 slug 确认 | 仅作者 | 删行；级联删 `Revision`、`LogLink`、`PreviewToken`；写审计 |
| T5 生成预览 | 编辑页按钮 | 仅作者；活跃令牌 <3 | 生成随机 token，存哈希与 7 天过期；写审计 |

不可逆性说明：发布是「信任动作」，必须逐条过扫描；批量发布与批量删除继续不做。

### 7.2 证据层规则

- 唯一权威位：`EvidencePanel` 是哈希、时间、来源的唯一展示处；`Stamp` 不含哈希。
- 摘要口径不可改：`SHA-256(title + "\n" + beforeContent + "\n" + (afterContent ?? ""))`，UTF-8，小写十六进制；只允许 `contentHash.ts` 一处实现。
- 哈希只在发布时写入；草稿与预览页显示「未发布，无摘要」，不得本地计算伪造。
- 列表证据行使用 6 位前缀，仅用于识别，不用于复算；页面文案明确「完整摘要见详情页」。
- 关于页新增 `#verify`：一段纯文本口径 + 三条复算步骤（取三字段、按序拼接、任意工具算 SHA-256 比对）。

### 7.3 系列

| 规则 | 口径 |
|---|---|
| 创建 | 后台 `/admin/series`：名称、slug、摘要；slug 不改 |
| 归属 | 编辑器下拉选择已有系列；不提供自由文本，避免同名异写 |
| 排序 | `seriesOrder` 升序；并列按 `beforeDate` 升序；再按 `id` 稳定 |
| 展示 | 详情页徽章「系列 · 名称 · 第 k / N 篇」，链到系列页 |
| 系列页 | 标题、摘要、`N 篇`、按序列表（每行带 `01/05` 序号与证据行） |
| 改名 | 只改 `name` 与摘要，slug 不变，外链不失效 |
| 删除 | 仅当 `N=0`；否则先解绑（批量置空）再删；错误码 `SERIES_003` |
| 订阅 | 系列 RSS 首版不做（触发：单系列 ≥5 篇且有人订阅） |

### 7.4 反链

| 项 | 规则 |
|---|---|
| 写入时机 | 每次发布，在发布事务内先删该 source 的旧行，再插解析成功的目标 |
| 解析范围 | 同一作者、已发布；未命中（草稿/别家/写错）不写行，正文保留 `[[slug]]` 原文 |
| 读取 | 按 `(targetUserId, targetSlug)` 查 `LogLink`，只取 `source.isPublished=true`，按 `publishedAt desc`，最多 20 条 |
| 展示 | 详情页「被引用 N 处」，每条含标题 + 证据行；超过 20 条显示「仅列前 20 处」 |
| 下架影响 | source 下架后自动从列表消失，无需删行 |
| 自引用 | 允许但不展示（过滤 `sourceLogId = 当前 logId`） |
| 上限 | 单篇抽取 50 个引用（复用现有常量），超出不写并提示 |

| 环节 | 规格 |
|---|---|

| 链接 | `/preview/<token>`；不进 sitemap、不进 RSS、不出现在任何列表 |
| 有效期 | 7 天；可随时撤销；每篇最多 3 个活跃令牌 |

### 7.10 文案口径（增补）

### 8.5 E2E 决策（待批准）

用 dev 登录 provider，本地跑 5 条，不进 CI（避免 secrets 与时长）：

1. 登录 → 新建日志 → 发布 → 详情页出现三读数与哈希。
2. 编辑已发布日志 → 保存退回草稿 → 前台 404。
3. 生成预览令牌 → 未登录访问 → 200 且 `noindex`；撤销后 404。
4. 新建系列 → 挂两篇 → 系列页顺序与 `第 k/N 篇` 正确。
5. 发布含 `[[slug]]` 的日志 → 目标详情页出现反链 → 下架后消失。

成本：1 人日 + 浏览器依赖；收益：把「需登录才能验」的债务一次清掉。

### 8.6 软著材料耦合规则

- 每个批次结束**只重出一次**材料，不逐文件重出；同批多次改动会浪费窗口。
- 新增文件必须在 BANDS 收录清单登记；`src/` 文件头注释齐全。
- 后窗口余量阈值 100 行；当前 171 行，P1 后预计下降，P1 结束立即重出并登记。
- 切口落在空行时，按生成器提示小幅平移文件或增减注释；**禁止为凑边界塞无意义代码**。
- 说明书（`docs/04`）在 P2、P3 各更新一节：系列、预览令牌、修订历史、审计、三段回执。
- 材料与源码必须同一提交，避免版本错位。

### 8.7 可观测性

- 导出失败保留 `[export]` 单行错误日志（已有），新增不打印 payload。
- 发布链路各步耗时只在 dev 打印，生产不打印正文。
- 预览 404 不区分原因，避免探测；nginx 关闭该路径 access log。
- 审计表是唯一「谁在什么时候做了什么」的权威记录。
