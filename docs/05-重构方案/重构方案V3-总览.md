## 零、三条裁定的结论（本轮先答，再展开）

### ① B0 只做首页 + 日志详情：**接受**

理由不是"稳妥"，而是**这两页已经把整套设计语言用完了**：首页用到了字号阶、间距节奏、
线重三档、列表行、看板、空态；详情页用到了正文排版、区块头、代码块、图片、目录、印章、打印。
这两页定稿之后，其余页面只是"同一套语法的不同组合"，不会再有方向性分歧。
反过来，先铺全站再改方向，等于把同一套错误复制 12 遍。

B0 的验收物是**可以直接打开比较的两页 + 一份令牌表**，不是设计稿。

### ② 标签大小写：**不统一小写；改用「小写规范键 + 原始显示名」双轨**

这是品牌判断，我按"可读性优先"裁：

- **显示保留原始大小写**。这个站的标签大量是专有名词与缩写——`GitHub`、`AI`、`WCAG`、`Tailwind v4`、
  `Prisma`、`OSS`。全小写成 `github / ai / wcag / prisma / oss`，在等宽字体里会读成"命令行参数"，
  而不是"技术名词"。这与"克制但精确"的品牌调性相反：克制不等于降级信息。
- **匹配与 URL 用小写规范键**。这样 `React` / `react` / `REACT` 不会产生三个标签、三条聚合页、
  三条 RSS；`/tags/react` 是唯一规范地址，`/tags/React` 301 到它。
- **落库口径**：新增 `tagsKey String[]`（由 `normalizeTagList` 生成的小写键，写入时与 `tags` 同步），
  `tags` 继续存显示名。查询、去重、URL、RSS 一律走 `tagsKey`；渲染一律用 `tags`。
- **迁移**：一次性脚本按现有 56 个标签生成键，`tagsKey` 建 GIN 索引；已公开 URL 若含大写，
  由 proxy 做 308 到小写规范地址（保留查询串）。
- **不做的部分**：不把显示名强行改写、不颠倒 `tags` 与 `tagsKey` 的语义、不做"标签别名表"（过度设计）。

代价：多一列 + 一次迁移 + 一处 proxy 重定向。收益：URL 稳定、专有名词可读、以后接 RSS/JSON Feed 不用再改。

### ③ 文档体系：**改为一份《现状说明书》，旧编号封存**

采纳建议。执行方式（B5 完成，不在 B0 做）：

- 新建 `docs/现状说明书.md`，按"系统是什么 / 数据怎么流 / 页面有什么 / 关键口径在哪 / 哪些事不能做"五章写，
  **只描述当前事实，不写历史决策过程**。
- `SPEC.md` / `DESIGN.md` / `ISSUES.md` 整体移入 `docs/archive/2026-11-16-旧编号体系/`，
  文件头加一行"已于 2026-11-16 封存，现行事实见 docs/现状说明书.md"。
- 停止维护 D## / F## / I### 编号；新增决策用"日期 + 一句话标题"记在 `docs/现状说明书.md` 的「变更记录」章。
- 代码注释里已有的编号引用**不改写**（改注释等于全仓翻动，收益为零）。

## 一、方向：克制底子 + 精致升级（不变）

这个站点的品牌资产是"克制"：纸白、墨色、宋体、1px 线、零圆角、可核对的内容摘要。
推翻它去做一个现代 SaaS 是净损失。所以本轮做三件事：

1. **保留骨相**：色值、字体、零圆角、无阴影、720px 正文限宽。
2. **重做关节**：间距节奏、字号阶、线重三档、区块结构、状态（空/加载/错误/极端数据）。
3. **补功能闭环**：发现（标签索引、归档、⌘K）、创作（工具栏、自动保存、预览链接）、
   运营（行内操作、批量、审计）、分发（OG 图、JSON Feed）。

不做：换肤式改版、大圆角、彩色强调、图标满屏、语法高亮 engine、评论与 UGC。

## 三、验收（B0）

视觉
- 首页与详情在 1440 / 768 / 375 三档无横向滚动；正文行宽 720px ±0。
- 间距只出现 4/8/12/16/24/32/48/64/96/128 十档（抽查 20 处 className）。
- 圆角为 0（浮层除外）；无 box-shadow；无渐变。

交互
- 详情页面包屑可点、当前页不可点（`aria-current="page"`）。
- 代码块显示语言标签与复制按钮，复制后 2 秒内回显"已复制"。
- 图片点击开灯箱，Esc 关闭，焦点归还触发元素。
- 键盘 Tab 顺序：面包屑 → 目录 → 正文链接；跳转正文链接仍可用。

工程
- `npm run lint` / `npx tsc --noEmit` / `npm run build` / `npm test`（192 条）全绿。
- 详情页 Prisma 调用不回归（≤2，不含 Proxy）。
- 打印预览：导航、目录、进度条、复制按钮不出现。

### 7.4 B1-a 实施记录（2026-11-16）

**范围重整的决定**：B1 原含五项（样式拆分 / 图标 / 原子组件 / 暗色 / Toast / 骨架）。
本轮只做「主题系统 + 图标集」，其余拆成 B1-b。理由是：主题与图标是**所有后续页面的前置**（导航、后台侧栏、
空态都要用），而样式文件拆分是纯结构改动、Toast 依赖具体页面接入——把有依赖关系的先做，无依赖的后做，
可以让 B2 不被 B1-b 卡住。

| 类型 | 文件 | 说明 |
|---|---|---|
| 新增 | `src/components/icons/index.tsx` | 15 个自绘图标（1.5px、`currentColor`、无 title 时 aria-hidden） |
| 新增 | `src/components/ThemeToggle.tsx` | 主题切换；`useSyncExternalStore` 订阅 `html[data-theme]` |
| 修改 | `src/app/globals.css` | `html[data-theme="dark"]` 语义层覆盖 + 暗色 mark + 打印强制亮色 |
| 修改 | `src/app/layout.tsx` | 首屏主题内联脚本（阻塞执行，消除闪白）+ `suppressHydrationWarning` |
| 修改 | `src/components/SiteNav.tsx` | 导航右端挂主题切换 |

**两次技术裁定**（写在代码注释里）：
1. 首屏主题必须是 `body` 首子元素的阻塞脚本，否则纸白底先画再变暗；
2. 主题切换改用 `useSyncExternalStore` 读 DOM 状态——effect 里 `setState` 被 `react-hooks/set-state-in-effect`
   判错，而“读 DOM 再回写 state”本就是外部存储订阅。

**门禁**：`tsc` 0 / `lint` 0 / `test` 192 / `build` 通过。
**运行时取证**：`/about` 产物含主题脚本、`aria-pressed` 与「切换到暗色主题」；页面实际引用的 CSS 含 3 处 `data-theme` 与暗色背景值。

**过程中发现并修掉的一个真缺陷**：`@theme inline` 会把色值内联进工具类
（实测产物 `.text-ink-soft{color:#625d53}`），`html[data-theme="dark"]` 覆盖变量对工具类完全无效——
暗色会变成“底变了、字没变”。去掉 `inline` 后工具类编译为 `var(--color-*)`
（实测 `.text-ink-soft{color:var(--color-ink-soft)}`），暗色才贯穿全站。
这是“看着能跑”与“真的生效”的差别，已写进附录 A 的落地形态。
