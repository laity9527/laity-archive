# 一、综合现状总览

## 1.1 【本地项目扫描摘要】（阶段1）

**技术栈（实测）**：Next.js 16.4.6（App Router，`cacheComponents:true` + `partialPrefetching:true`）、React 19.3.0、Prisma 7.10.1（`@prisma/adapter-pg` 驱动适配器，CLI 连接串在 `prisma.config.ts`）、PostgreSQL 16（Docker）、NextAuth 4.24.15（GitHub OAuth）、Tailwind CSS 4.3.3、ali-oss 6.23.0、react-markdown + rehype-sanitize。npm 管理，285 条 node --test 单测 + 11 条 Playwright e2e。

**目录结构**：`src/app`（前台 + /admin + API）、`src/components`（24 组件）、`src/lib`（47 个库文件）、`prisma/`（schema + migrations + seed + backfill）、`tests/`、`tools/软著材料生成.mjs`、`deploy/nginx.conf`、`docker-compose.prod.yml`（preflight 门禁容器 + migrate 一次性服务 + nginx TLS）、`.github/workflows/ci.yml`（四道门禁 + SSH 部署回滚）。

**数据模型（7 个，prisma/schema.prisma 190 行）**：
- `User`：handle/email/githubId 唯一，`githubAccessToken` AES-256-GCM 密文落库（public_repo scope），isAdmin 已退役。
- `Project`：slug/kind(product|tool|site)/status(WIP|LIVE|ARCHIVED)/summary/repoUrl，`@@unique([userId,slug])`。
- `Log`：beforeContent/afterContent 双正文、beforeDate/afterDate 双时间戳、tags[]（Gin 索引）、series 字符串 + seriesId 双写、isPublished、contentHash、publishedAt、sourceCommitSha（同步去重锚）、isAiAssisted、lastPublishedSnapshot(Json)。
- `Series`、`PreviewToken`（token 哈希 + 24h 过期）、`Revision`（发布旧版归档，**每篇上限 20 条，超出同事务删最旧**）、`AuditEvent`（actorId/action/targetType/meta）。
- **无 Topic 实体、无 verdict 字段、无 Lead/Media/Service/Faq 模型**。

**路由**：前台 `/`、/logs（大厅）、/projects、/archive、/tags、/tags/[tag]、/about、/privacy、/licenses、/login、/preview/[token]、/u/[handle]/...（多租户命名空间）；机器可读 /sitemap.ts、/robots.ts、/feed.xml、/feed.json、/tags/[tag]/feed.*；API 仅 /api/health、/api/search、/api/auth/*、/admin/export。后台 /admin 概览 + logs（new/import/edit/preview/snapshot/history）+ projects + series + audit + settings；8 个 "use server" 动作文件。`src/proxy.ts` 做 /admin 前置守卫与真 404。

**已实现的业务能力（完成度高）**：
- 发布存证：`publish.ts` 敏感扫描门 → `content-hash.ts` 算 SHA-256（D5 口径：title+"\n"+before+"\n"+(after??"")）→ 事务内归档旧版 Revision + 写 contentHash/publishedAt/lastPublishedSnapshot；下架保留哈希；删除需输 slug 确认。
- GitHub 同步：`github-sync.ts` **单向拉取** commits 产草稿（四道过滤、幂等去重），**没有发布时 push 回写 commit 的双轨存证**。
- 后台：日志/项目/系列 CRUD、批量下架、AI 草稿生成（DashScope qwen-plus）、Markdown 导入、公开预览链接、行级 diff 历史页、快照对比页、审计（最近 100 条）、JSON 导出（`export.ts` 确定性排序）。
- 安全：rehype-sanitize 唯一渲染出口、图片 magic-bytes 签名判定、OSS 仅 PutObject 权限、敏感信息扫描（手机/身份证/凭据/私钥等）、nginx 边缘限流（OAuth 回调 5r/m）、CSP 静态头、凭据全环境变量。
- UI：暖纸四色令牌 + 棕色强调、**暗色主题已完整实现**（ThemeToggle + 防闪烁脚本）、三套开源字体（next/font）、零圆角无阴影、CommandPalette（⌘K）、Toast、双栏 Markdown 编辑器（粘贴上传）、EvidencePanel 哈希展示、Timeline 双时间轴。

**技术债（扫描实测）**：
1. `Revision` 20 条上限裁剪 = **历史版本可被删除**，与"版本永不覆盖删除"的证据链要求直接冲突（最高优先级）。
2. 存证免责/算法说明文案散落 6 处 tsx（Seal.tsx、about、privacy、logs 大厅、tags 页、admin edit），无代码常量单源。
3. 无 /verify 核验入口；核验靠读者看 EvidencePanel 自行重算。
4. 缓存失效全用 `revalidatePath`（粒度粗，发布一条日志重建整片路径），无 revalidateTag。
5. 动作样板重复：log-actions.ts 内 7 个动作重复「取 id→ID_PATTERN→requireAdminSession→redirect(error)」；project/series/settings 同套守卫。
6. 过长文件：logs.ts 948 行、logs/page.tsx 663 行、Editor.tsx 545 行、log-actions.ts 441 行。
7. `github-sync.ts` mapLimit 一处死代码分支；proxy.ts 内联 404 页四组色值字面量需手工同步。
8. 无 DB 集成测试（数据访问层不在 285 条单测覆盖内）。
9. TODO/FIXME/HACK：0 处；依赖 CVE 已清零。

**未完成项（docs/现状说明书.md §4.5）**：备案号 SITE_ICP 等合规位待填（唯一真实阻塞）；软著材料分页边界切口脆弱；生产真实上传联调需负责人本人 GitHub 会话。

## 1.2 【参考资料解析摘要】（阶段2）

**产品核心定位**：不是外包官网、不是博客、不是作品集，是**对外可核验的「判断轨迹交付系统」**。一人工作室，交付物 = 系统本身 + 完整判断轨迹档案（约束/备选/取舍/偏差复盘）。护城河 = 结果 + 形成结果的判断轨迹 + 可自助核验的存证；同行只展示成功，**公开「被推翻」的判断与反转率**是独有信任资产。

**业务基线（方案1）**：3 个项目（地球 Mirror 1 条、档案库 12 条、GitHub 同步 1 条 = **14 条历史轨迹**）、8 类主题（部署与运行时/数据与存证/前端与视觉/质量与门禁/协作与事实/安全与凭据/软著与材料/项目与索引）、UTC 双时间轴（判断/验证）、同 commit 同步标签。方案1 认定的短板：后台内存态、存证手工、无核验入口、主题是标签串——**注意：这是对外站 build.laity.work 的基线描述，本地仓库实际已超越其中大部分（见 1.3）**。

**三根支柱**：双轴档案（项目×主题横切）、结论裁决（verdict：待验证/已验证/被推翻 + 公开反转率）、双时间轴+存证（判断时间与验证时间各挂哈希与 commit）。日志模板五要素：BEFORE/AFTER 之上加 范围 Scope / 风险 Risk / 回滚 Reversibility / 影响 Impact。

**两套方案的优点**：方案2 架构定案坚决（单体单仓库、RSC+revalidateTag、同源后台）、数据模型版本化思路正确（TraceRevision 独立表、(traceId,version) 唯一）、安全清单完整（蜜罐/限流/ipHash/禁 SVG/审计）、排期保守不压自测。方案1 的竞品取舍清醒（抄三成弃七成）、把版本与核验从三期提前到一期、日志模板五要素成本低收益高。

**原始方案的不合理约束（可突破，逐项见 1.4 改动点表）**：
- 方案2 schema 自相矛盾：声称"永不覆盖历史正文"却给 `TraceRevision onDelete: Cascade`（删轨迹即删证据）。
- "任意一步异常事务回滚"把 Git push 包进 DB 事务——外部副作用不可回滚，是分布式事务幻觉。
- 统一规范化哈希直接覆盖旧口径，会让历史印章全部失效。
- REST CRUD 全套 API 与本地已验证的 Server Action 体系重复建设。
- 签名直传、Plausible 自托管（需 ClickHouse）、邮件服务对单人运维偏重。
- 原型演示数据含虚构客户（栖木咨询等）与虚构评价，违反方案2 自己的"不虚构"红线。
- 原型用系统字体 + 圆角 14px + 阴影 + 渐变 + 砖红，与本地视觉铁律冲突（本轮按授权以原型令牌为新基准，字体除外）。

**前台原型 UI 资产**：CSS 令牌（--bg:#f8f7f3 / --bg-alt:#efece5 / --ink:#161410 / --ink-2:#49453d / --muted:#8a8477 / --accent:#b84a2e / --accent-dark:#9a3a22 / --line:#e0dbd0 / --card:#fffef9 / --radius:14px / --radius-sm:9px / 两级阴影）；首页十区块（Hero+状态卡+数字滚动、工作原则条、关于、服务三卡+快诊横幅、四步流程、案例筛选卡、精选判断摘录、FAQ 手风琴、联系表单含"希望留存哪些证据"字段、深色页脚）；交互：滚动进度条、IntersectionObserver reveal/计数/导航高亮、移动抽屉导航、回到顶部、`prefers-reduced-motion` 全量降级。

**后台原型 UI 资产**：深色侧边栏（概览/内容/互动/设置四组 16 视图）+ 粘性顶栏（面包屑、全局搜索 / 快捷键、通知、用户菜单）；**配置驱动的通用资源管理器**（RESOURCES：列定义/筛选/排序/分页/批量选择/模态表单，一套逻辑管 cases/services/faqs/testimonials/brands/logs/leads 七类）；媒体网格、页面区块编辑、站点信息/导航/SEO（字数提示）/外观（强调色+圆角实时预览）/账户安全/系统数据（JSON 导出导入、快照、备份列表）；Modal/Toast/确认弹窗/开关/徽章全套；响应式三档断点 + reduced-motion。**全部数据在内存 JS，正是要替换的部分**。

## 1.4 对原始参考文档的改动点总表（改动点｜原方案｜重构后｜改动收益）

| # | 改动点 | 原方案 | 重构后 | 改动收益 |
|---|---|---|---|---|
| 1 | 租户结构 | schema 无 userId，单租户 | 保留 User+userId 复合条件，前台按 SITE_OWNER_HANDLE 解析唯一工作室主 | 复用全部 DAL/鉴权/proxy，零重写；为长期"客户只读账号"留位 |
| 2 | 模型命名 | Trace/TraceRevision 新表 | `Trace @@map("Log")`、`TraceRevision @@map("Revision")`，表名不动 | 领域语言对齐，数据零搬迁，迁移可回退 |

# 三、增强修正版 Prisma Schema

> 差异标注：【保留】=与本地一致；【新增】=本地缺失；【修正】=改本地或改参考。
> 表名通过 `@@map` 保持不变，**数据零搬迁**；Prisma 7 事实：datasource 不写 url（prisma.config.ts 注入），运行时 PrismaPg 适配器（src/lib/db.ts）不动。

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"

// 【保留】User 不动；githubAccessToken 密文即 Git 双轨存证的凭据来源
model User {
  id                String   @id @default(cuid())
  email             String?  @unique
  handle            String   @unique
  githubId          String?  @unique
  githubAccessToken String?
  name              String?
  isAdmin           Boolean  @default(false) // 已退役，保留不迁移

  traces            Trace[]
  series            Series[]
  previewTokens     PreviewToken[]
  media             Media[]
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

// 【修正】Project：补工作室维度字段；kind/status 沿用字符串约定
model Project {
  id          String   @id @default(cuid())
  slug        String
  name        String
  kind        String // product | tool | site
  status      String // WIP | LIVE | ARCHIVED
  ownership   String   @default("SELF") // 【新增】SELF | CLIENT（参考 ProjectKind）
  clientName  String? // 【新增】客户名；未授权不渲染（前台只读 ownership 判定）
  year        Int? // 【新增】年份筛选
  summary     String?
  solution    String? // 【新增】实施方案（参考要求）
  result      String? // 【新增】交付结果
  repoUrl     String?
  coverId     String? // 【新增】封面 → Media
  cover       Media?   @relation(fields: [coverId], references: [id])
  featured    Boolean  @default(false) // 【新增】
  sortOrder   Int      @default(0) // 【新增】
  userId      String?
  user        User?    @relation(fields: [userId], references: [id], onDelete: Cascade)
  traces      Trace[]
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt // 【新增】

  @@unique([userId, slug])
  @@index([status, ownership]) // 【新增】

// 【修正】Log → Trace（@@map 保表名）：补裁决、五要素、精选、软删除、哈希版本
model Trace {
  id              String   @id @default(cuid())
  title           String
  slug            String
  projectId       String
  project         Project  @relation(fields: [projectId], references: [id])
  userId          String?
  user            User?    @relation(fields: [userId], references: [id], onDelete: Cascade)
  tags            String[] // 【保留】作者自由标签，Gin 索引；主题横切走 TraceTopic
  series          String? // 【保留】兼容期双写
  seriesId        String?
  seriesRef       Series?  @relation(fields: [seriesId], references: [id], onDelete: SetNull)
  seriesOrder     Int      @default(0)
  beforeContent   String // 判断时正文（约束/备选/当时风险）
  afterContent    String? // 验证时正文（结果/偏差复盘）
  beforeDate      DateTime // 判断时间（UTC）
  afterDate       DateTime? // 验证时间（UTC）
  // 【新增】五要素（方案1 四节）；新发布必填，存量豁免
  scopeMd         String? // 范围：涉及哪些模块
  riskMd          String? // 风险：可能破坏什么
  rollbackMd      String? // 回滚：怎么退回
  impactMd        String? // 影响：谁会受影响
  // 【新增】裁决三态 + 反转率来源
  verdict         Verdict  @default(PENDING)
  verdictNote     String? // 裁决依据（被推翻时必填，表单门禁）
  verifiedAt      DateTime? // 裁决时间（UTC）
  featured        Boolean  @default(false) // 【新增】首页精选摘录唯一来源
  isPublished     Boolean  @default(false)
  lessonLearned   String?
  publishedAt     DateTime?
  contentHash     String? // 当前发布版哈希（历史版在 TraceRevision）
  hashVersion     Int      @default(1) // 【新增】1=D5 原口径；2=规范化口径
  currentRevId    String? // 【新增】指向最新已发布版本行
  sourceCommitSha String? // 【保留】拉取同步去重锚
  isAiAssisted    Boolean  @default(false)
  deletedAt       DateTime? // 【新增】软删除；已发布轨迹只软删，前台过滤
  previewTokens   PreviewToken[]
  revisions       TraceRevision[]
  topics          TraceTopic[] // 【新增】多对多
  lastPublishedSnapshot Json? // 【保留】草稿对比用
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt

  @@unique([userId, slug])
  @@unique([userId, sourceCommitSha])
  @@index([userId, isPublished, beforeDate])
  @@index([userId, isPublished, series])
  @@index([isPublished, beforeDate])
  @@index([isPublished, verdict]) // 【新增】反转率/裁决筛选
  @@index([tags], type: Gin)
  @@index([projectId])
  @@index([seriesId])
  @@map("Log") // 【修正】表名不动，客户端 prisma.log → prisma.trace 机械替换
}

// 【修正】Revision → TraceRevision：不可变证据表
// 铁律：只 INSERT；UPDATE 仅限 gitSha/gitSyncedAt 回填；禁止 DELETE（去 20 条裁剪）。
// onDelete: Restrict —— 有版本行的轨迹不可硬删（修正参考方案的 Cascade 矛盾）。
model TraceRevision {
  id            String   @id @default(cuid())
  traceId       String   @map("logId") // 【修正】列名保 logId，数据零搬迁
  trace         Trace    @relation(fields: [traceId], references: [id], onDelete: Restrict)
  version       Int // 【新增】从 1 自增，(traceId,version) 唯一
  title         String
  beforeContent String
  afterContent  String?
  scopeMd       String? // 【新增】五要素随版本冻结
  riskMd        String?
  rollbackMd    String?
  impactMd      String?
  tags          String[]
  verdictAtPublish Verdict @default(PENDING) // 【新增】发布时裁决快照
  contentHash   String
  hashVersion   Int      @default(1) // 【新增】
  gitSha        String? // 【新增】时间锚 commit；null=待锚定（降级态）
  gitTag        String? // 【新增】trace/<slug>/v<N>
  gitSyncedAt   DateTime? // 【新增】锚定成功时间
  publishedAt   DateTime
  createdAt     DateTime @default(now())

  @@unique([traceId, version])
  @@index([traceId, createdAt])
  @@index([contentHash]) // 【新增】/verify/[hash] 反查
  @@map("Revision")
}

// 【新增】主题实体（方案1 七节：标签串升级为实体）
model Topic {
  id          String   @id @default(cuid())
  slug        String   @unique // deploy/data/frontend/quality/collab/security/copyright/project

  description String?
  sortOrder   Int      @default(0)
  traces      TraceTopic[]

}

model TraceTopic {

  topicId String
  trace   Trace  @relation(fields: [traceId], references: [id], onDelete: Cascade)
  topic   Topic  @relation(fields: [topicId], references: [id], onDelete: Cascade)

  @@id([traceId, topicId])
  @@index([topicId])
}

// 【新增】线索（方案2 流程2）：只存 ipHash，不留明文 IP
model Lead {

# 五、核心业务流程重构设计

## 5.1 判断轨迹发布 + 双轨存证（核心）

```
编辑保存草稿（不产版本、不算哈希、前台不可见）
  └─ 已发布轨迹被保存 → 退回草稿（保留本地 D9 行为，历史版本不受影响）
点击发布：
  ① requireAdminSession + parseInput（五要素新条目必填；verdict=OVERTURNED 时 verdictNote 必填）
  ② 敏感扫描门（复用 sensitive-scan.ts，阻断级 LOG_003 拒发）
  ③ 规范化正文（v2）：CRLF→LF、剔零宽字符(U+200B/200C/200D/FEFF)、行尾空白收敛
  ④ computeContentHashV2（canonical-hash.ts 新函数；v1 函数原样保留供历史复核）
  ⑤ DB 事务：
     - INSERT TraceRevision（version = max+1，含五要素/裁决快照/hashVersion=2）
     - UPDATE Trace：currentRevId/contentHash/publishedAt/verdict/featured…
     - 写 lastPublishedSnapshot（草稿对比用）
     - 【删除】旧版裁剪逻辑 —— 版本行永不删除
  ⑥ 事务提交后 → revalidateTag（见 5.4）→ 返回发布回执
  ⑦ 异步 Git 锚定（git-evidence.ts，失败不影响发布）：
     - 解密 User.githubAccessToken（token-crypto.ts，public_repo scope）
     - Contents API PUT：EVIDENCE_REPO 仓库 traces/<slug>/v<N>.md（规范化正文+元信息头）
     - Refs API 打 tag：trace/<slug>/v<N>
     - 第二事务回填 gitSha/gitTag/gitSyncedAt → 审计 → revalidateTag
     - 失败：gitSha 留 null，仪表盘计“待锚定”，后台一键重试；env GIT_EVIDENCE_ENABLED=false 可整体关闭
核验：/verify/[hash] 或详情页 ?v=N → 展示该版本原文+规范化规则+哈希+gitSha+tag 链接；
     VerifyPanel 用 WebCrypto 在浏览器对规范化正文复算 SHA-256 并比对（自助核验，不依赖服务端结论）
```

**改动点标注**：vs 本地——去掉 20 条裁剪、首版也产版本行、新增 Git push 方向（原来只有拉取）、哈希加 v2；vs 参考——Git 移出事务（改动点4）、哈希双版本（改动点5）、Restrict（改动点6）。免责口径全部读 `evidence-constants.ts`。

## 5.2 线索表单链路

```
LeadForm（Client）：姓名/邮箱/需求类型/希望留存的证据/留言 + 蜜罐隐藏字段 + 渲染时间戳
  → 客户端基础校验 → POST /api/leads
  → nginx limit_req（5r/m/IP，burst=5，超限 429 不进应用）
  → 服务端：蜜罐非空即静默成功（不入库）；填写时长 <3s 拒；parseInput 强校验
  → ipHash = sha256(remote_addr + LEADS_IP_SALT)（X-Forwarded-For 由 nginx 覆写，复用现有防伪造配置）
  → 入库 Lead(NEW) → 审计 → 返回 {ok:true}
  → （三期）异步邮件通知，失败只落审计，访客仍见成功提示
后台：未读徽章 → 状态流转 NEW→REPLIED→ARCHIVED / SPAM，回复备注
```

**改动点**：限流从应用层改 nginx 边缘（改动点9）；邮件从一期挪三期（改动点15）。

## 5.3 JSON 导入导出（dry-run + 事务）

```
导出（扩展 export.ts）：{schemaVersion:"2", exportedAt, traces[](含全部 revisions), projects,
  topics, traceTopics, series, services, faqs, leads, media[](仅 ossKey/url 引用), settings}
  确定性排序（复用现有实现），不含媒体二进制、不含 token/凭据；导出记审计
导入：
  ① importDryRun：校验 schemaVersion、外键闭包、slug 唯一、(traceId,version) 冲突、
     哈希复算（按各行 hashVersion 用对应算法重算比对）、敏感扫描
     → 产出报告：将新增 N / 跳过 M（已存在且哈希一致）/ 冲突 K（同版本不同哈希 → 拒收该行）
  ② importCommit：单事务批量写入；TraceRevision 只追加不覆盖；任何失败整体回滚
  ③ 审计 + revalidateTag
```

**改动点**：vs 本地——从"只导出"补全导入闭环；vs 参考——冲突策略明确为"同版本不同哈希拒收"（证据不可被导入覆盖）。

## 5.4 revalidateTag 缓存闭环

```
读侧：DAL 公开读函数加 "use cache" + cacheTag（实施前必读 node_modules/next/dist/docs/ 对应指南）
  标签 taxonomy：traces / trace:<slug> / projects / project:<slug> / topics / topic:<slug> /
                series / services / faqs / leads-admin / settings / sitemap / feeds
写侧：动作成功后按影响面 revalidateTag：
  发布/下架/裁决 → traces + trace:<slug> + projects + sitemap + feeds（+ topics 若改挂）
  项目 CRUD → projects + project:<slug> + traces + sitemap
  服务/FAQ/区块 → services / faqs / home
  导入 → 全量标签
性能预算不变：/traces 首屏 ≤2 次 Prisma 调用、前台页 ≤3、sitemap ≤3（cache() 去重保留）
```

**改动点**：vs 本地——revalidatePath 全量替换为标签级；vs 参考——标签 taxonomy 具体化、与现有性能预算对拍。

# 八、存量数据迁移方案

## 8.1 迁移策略总则

- **表名不动**（@@map），全部是加列/新表迁移，`prisma migrate dev` 生成，不手改、不对库直执。

## 8.2 存量轨迹迁移脚本要点（14 条历史判断轨迹）

tools 侧脚本 prisma/migrate-to-v5.ts（node 执行，复用 src/lib）：
① 版本行补全：每条已发布 Log →
   - 既有 Revision 行按 createdAt 升序编 version=1..n（hashVersion=1，gitSha=null）
   - 当前发布态（contentHash+publishedAt+lastPublishedSnapshot）补 version=n+1
   - 下架但曾发布的：用 lastPublishedSnapshot 补历史版本行，标 verdict=PENDING
   - 从未发布的草稿：不产版本行
② 哈希校验：逐行按 hashVersion 用 content-hash.ts 对应算法复算，
   与存储 contentHash 比对；不一致 → 报告列出，不静默改写（前台已有“存证缺失”告警兜底）
③ 主题挂接：按 topics.ts 现有 8 类映射把 tags[] 归一到 TraceTopic；
   未命中的自由标签原样保留在 tags[]（用户数据不译不改）
④ verdict 初始化：全部 PENDING；负责人后台逐条裁决（不自动推断）
⑤ 五要素：存量置 null，前台标“历史条目（五要素模板启用前）”，新发布必填
⑥ Project 补字段：3 个项目 ownership=SELF、year 从 createdAt 推、封面可空
⑦ Git 锚定回填：历史版本不补 push（时间锚只对新发布生效）；
   已有 sourceCommitSha 的同步草稿在详情页继续展示“提交来源”
⑧ 幂等保障：以 (traceId,version) 存在性跳过；全程单事务 + 报告 JSON 落 tmp/
```

## 8.3 迁移校验规则（保障哈希存证一致性）

1. **数量守恒**：迁移前后 Log 行数、已发布数、Revision 行数（只增不减）对拍。
2. **哈希全量复核**：14 条轨迹每个版本行复算一致率必须 100%（v1 口径），任何不一致停下来报告，不自动"修复"。
3. **唯一性**：(userId,slug)、(traceId,version) 无冲突；冲突即 dry-run 拒收。
4. **抽样人工对拍**：随机 3 条在前台详情页比对印章哈希与迁移前截图/记录。
5. **回退预案**：迁移前 pg_dump 快照；迁移失败整体回滚 + 恢复快照；@@map 设计保证回退不需要数据反变换。

# 九、风险矩阵 & 降级预案

| 风险描述 | 影响等级 | 应对方案 | 降级开关 |
|---|---|---|---|
| 历史版本被篡改/误删 | **高** | 代码层禁 UPDATE/DELETE + DB 触发器双闸门；软删除替代硬删；导入冲突拒收 | 无需开关（常开闸门）；触发器异常时迁移可单独回退 |
| Git 存证链路故障（token 失效/网络/仓库改名） | 高 | 两阶段设计：站内 SHA-256 版本照常；gitSha=null 标"待锚定"；后台重试按钮 + 仪表盘计数 | `GIT_EVIDENCE_ENABLED=false` 整体关闭 push，仅站内存证 |
| 哈希口径漂移导致历史印章失效 | 高 | hashVersion 双版本；v1 函数冻结不改；迁移 100% 复核门禁 | 新发布可临时回退 hashVersion=1（表单开关，留审计） |
| 媒体链接失效 / OSS 迁移 | 中 | Media.ossKey 登记 + 批量替换脚本；导出 JSON 存 key 不绑域名 | 前台图片 onerror 占位（不裂图） |
| PostgreSQL 故障 / 数据丢失 | 高 | 每周 pg_dump + JSON 双备份异地归档；CI 部署失败自动回滚（已有） | 恢复演练通过后才上线（Phase 4 验收项） |
| 表单被刷 / 垃圾线索 | 中 | 蜜罐 + 时长 + nginx 429；SPAM 状态隔离 | 三期 hCaptcha；极端时 nginx 临时关 /api/leads |
| 邮件服务故障 | 低 | 异步不阻断，失败落审计（三期才接入） | 通知开关 env，关闭后仪表盘徽章兜底 |
| 视觉换肤引发 a11y/对比度回归 | 中 | 令牌定稿前全量对比度重算；暗色走查；焦点样式实算 ≥3:1 | 令牌集中在 globals.css，可单 commit revert |
| 软著材料窗口被新文件顶破 | 中 | 每次改动跑生成器，assertWindowFit 拒件即按"折排版不折逻辑"平移 | 既有机制，不绕过 |
| 轨迹断更，护城河衰减 | 高 | 每单交付强制产轨迹写进流程；仪表盘 30 天断更提示 | — |
| 单人运维精力不足 | 中 | 功能收敛：导航/SEO 不入库、统计可选、评价默认关 | 各三期模块独立开关 |
| 白名单误配把自己锁在门外 | 中 | env 校验进 preflight；本地 dev 登录过渡期保留 | STUDIO_GITHUB_ALLOWLIST 留空=仅 owner handle 兜底（需审批该语义） |
