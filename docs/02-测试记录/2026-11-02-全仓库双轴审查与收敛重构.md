## 三、`instant` 注释：代理引用的原文不在我查的文件里，我自己查到了

代理说注释把 `instant = false` 解释成"整体阻塞渲染、不出静态壳"是语义错误。我去 `route-segment-config.md` 没找到它引的句子，改查专门的 `.../02-route-segment-config/instant.md`，权威表述是：

- `false`：`Opts the segment out`（退出即时导航校验）；
- 「Disabling static shell validation」一节：要退出"每页必须产出非空静态壳"这条校验，需让路由树里**最高的** `instant` 配置为 `false`；
- 全文没有一处说 `false` 会把路由变成动态的——它调的是校验，不是渲染。

所以我们的**用法是对的**（这些页面确实请求期取数、必然阻塞导航，且 `false` 恰好也豁免静态壳校验），**注释描述是错的**。9 处已改成陈述这三层事实，并各追加一行修改记录。

## 四、1MB 上限：SPEC 的「≤5MB」此前根本达不到

- 依据（本地文档，非记忆）：`node_modules/next/dist/docs/01-app/02-guides/server-actions.md:83` — "Action requests are capped at 1MB by default. Configure `serverActions.bodySizeLimit`"。改前 `next.config.ts` 里 `bodySizeLimit` 零命中。
- 后果：任何 >1MB 的图会在进 `uploadImage()` 之前被框架拒掉，而且不映射成 IMG_001；也就是说 SPEC F10 与验收第 4 条（6MB 被拒）此前无法成立。
- 处置（经批准）：`experimental.serverActions.bodySizeLimit: "6mb"`，与 `deploy/nginx.conf` 的 `client_max_body_size 6m` 对齐。**注意我第一次写成了顶层 `serverActions`，`tsc` 直接报 TS2353 找不到该属性**——键路径必须嵌在 `experimental` 下，这也是"读本地文档再看类型定义"的价值。
- 仍未验证：真正的上传联调要等本人登录点一次。另有一处生产隐患留档：Server Action 会比对 `Origin` 与服务器可见 host（取 `x-forwarded-host` 或 `host`），我们的 nginx 只转发了 `Host $host`、没转 `X-Forwarded-Host`，按文档应可通过，但**没实测**，真上传时若动作被拒第一个查这里。

### 实测
