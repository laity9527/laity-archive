## 一、这是什么

多租户的开发者数字档案库：GitHub OAuth 一键登录，每个账号只读写自己的 Project / Log；
无自建注册、无 UGC、无评论。

**产品资产不是"好看"，是"可核对"**：每条已发布日志在发布时按固定口径写入 SHA-256 摘要与服务器发布时间，
详情页展示摘要，读者可自行复算。所有视觉选择（纸白、墨色、宋体、1px 线、零圆角）都为这个语义服务。

形态：Next.js App Router 全栈单体；无独立 API 层（仅 `/api/health`、`/api/search`、`/feed.xml`、
`/feed.json`、`/tags/[tag]/feed.xml`、`/tags/[tag]/feed.json`、`/sitemap.xml` 与 NextAuth 端点）；PostgreSQL 16 单库；阿里云 OSS 存图片。

## 二、数据与口径

### 2.1 数据模型（`prisma/schema.prisma`）

| 模型 | 关键字段 | 约束 |
|---|---|---|
| `User` | `handle`（公开标识）、`githubId`、`githubAccessToken`（AES-256-GCM 密文） | `handle` / `githubId` 唯一 |
| `Project` | `slug`、`name`、`kind`、`status`、`summary`、`repoUrl`、`userId` | `@@unique([userId, slug])` |
| `Log` | `title`、`slug`、`tags`、`series`、`beforeContent`、`afterContent`、`beforeDate`、`afterDate`、`isPublished`、`publishedAt`、`contentHash`、`sourceCommitSha`、`isAiAssisted`、`lastPublishedSnapshot` | `@@unique([userId, slug])`、`@@unique([userId, sourceCommitSha])`、`@@index([userId, isPublished, beforeDate])`、`@@index([userId, isPublished, series])`、`@@index([isPublished, beforeDate])`、`@@index([tags], type: Gin)` |

### 2.2 内容摘要口径（不可改）

`SHA-256( title + "\n" + beforeContent + "\n" + (afterContent ?? "") )`，UTF-8，小写十六进制。

- 唯一实现：`src/lib/content-hash.ts`。运行时、种子、任何复核工具都必须复用它，不得第二处重算。
- 改口径＝与所有历史印章不兼容，属产品级破坏性变更，不"顺手规范"。

### 2.3 发布与下架语义

- **保存**：可编辑任意状态；**已发布日志保存后退回草稿**（旧 `contentHash` / `publishedAt` 保留作"上次发布"）。
- **发布**：按库中正文重算摘要 + 写服务器时间，两者缺一不可；发布前跑敏感信息扫描（命中需显式确认）。
- **下架**：只翻 `isPublished`，正文、摘要与发布时间都保留。
- **删除**：行连同摘要一并消失，需输 slug 确认，仅在编辑页提供。

### 2.4 标签

- 写入时归一：去首尾空白、去开头 `@`、**忽略大小写去重**（保留首次写法），上限 5 个，单个 ≤ 24 字。
- 展示与 URL 都用显示名（`GitHub` 不会变 `github`）；`/tags/<显示名>` 是规范地址。
- **不做 `tagsKey` 双轨**：库内不存在仅大小写不同的标签，双轨的收益是"未来 URL 稳定"，代价是迁移 + 回填 + 308。
  触发条件：出现第一个仅大小写不同的标签时再启动。

### 2.5 租户隔离

- 所有前台取数走 `src/lib/` 的 DAL，`isPublished: true` 恒定；后台读写强制 `userId` 复合条件（0 行 = 不存在）。
- 详情页真 404 由 `src/proxy.ts` 前置判定（`/u/:handle/logs/:slug`、`/u/:handle/projects/:slug`、`/u/:handle/series`、`/u/:handle/series/:name`、`/tags/:tag`）。

### 2.6 正文内链（`[[slug]]`）

- 写法：正文（BEFORE / AFTER / 经验总结）里写 `[[日志-slug]]`；slug 口径与表单一致（小写字母 / 数字 / 连字符）。
- 解析范围：**同一作者、已发布**日志；链接显示目标标题而不是 slug，地址 `/u/<handle>/logs/<slug>`。
- 未命中（草稿、别家、写错）一律保留 `[[slug]]` 原文，不造死链，也不借链接泄露未发布内容。
- 代码块与既有链接内部不接管；渲染本身不设引用数上限（页面只按实际出现的 slug 生成链接）。
  `extractLogLinkSlugs()` 另设 50 个上限，供后续“被引用”统计/校验使用，目前详情页未调用它。
- 实现：`src/lib/log-links.ts`（纯函数 + hast 改写）→ `src/lib/markdown.tsx`；目标表复用详情页已有的 `getLogContext` 查询，**详情页 Prisma 调用仍为 2**。
- 尚未做："被引用"反向列表（需对正文做 contains 查询，会把详情页抬到 3；留待 V3.1 与系列/快照迁移一起定）。

## 三、页面与路由

### 3.1 公开页面

| 路由 | 说明 | 渲染 |

| `/` | 首页：Hero、馆藏条、精选项目、档案状态、最新日志、按主题 | PPR |
| `/logs` | 日志大厅：项目/主题/标签筛选 + 搜索 + 游标分页（50/页） | PPR |
| `/u/[handle]` | 租户主页：看板 + 最新日志 | PPR |
| `/u/[handle]/logs/[slug]` | 日志详情：面包屑、BEFORE/AFTER/经验总结、目录、灯箱、摘要卡（可复制链接/哈希、分享）、代码块（语言 / 行号 / 复制）、系列进度、上下篇、相关阅读 | PPR |
| `/u/[handle]/series/[name]` | 系列页：同作者同系列已发布日志，按决策时间升序，标出第 n 篇 | 动态 |
| `/u/[handle]/series` | 系列索引：本租户全部系列与篇数，链到各系列页 | 动态 |
| `/u/[handle]/projects/[slug]` | 项目详情：信息卡 + 该项目日志 | PPR |
| `/projects` | 作品档案：列表（编号 + 类型/状态 + 日志数 + 最近日期） | 动态 |
| `/tags` | 标签索引：按 `topics.ts` 的 8 个主题分组 + 「其他」，频次为灰色小字 | 动态 |
| `/tags/[tag]` | 标签聚合 | PPR |
| `/archive` | 归档：年 / 月分组，年份锚点可分享 | 动态 |
| `/about`、`/privacy`、`/licenses` | 关于 / 隐私 / 开源致谢 | 静态 |
| `/login` | GitHub OAuth（开发环境可选 `dev-admin`） | 动态 |
| `/feed.xml`、`/feed.json`、`/tags/[tag]/feed.xml`、`/tags/[tag]/feed.json`、`/sitemap.xml`、`/robots.txt` | RSS / JSON Feed / 标签订阅源（两种格式）/ 站点地图 / 抓取规则 | 路由处理器 |
| `/api/health`、`/api/search` | 健康探针 / 命令面板搜索 | 路由处理器 |

### 3.2 后台

| 路由 | 说明 |
|---|---|
| `/admin` | 概览：四项计数（项目 / 已发布 / 草稿 / 近 7 天发布）、**近 12 周发布柱（纯 CSS）**、继续处理（草稿）、同步 / 导出 / 新建入口 |
| `/admin/logs` | 列表：**表格化**（选择/状态/标题/更新时间/操作）、状态筛选、标题搜索、**项目筛选**、**排序（最近更新 / 最早更新 / 标题）**、分页、**行内发布/下架**、**批量下架**（不做批量发布与批量删除） |
| `/admin/logs/new`、`/admin/logs/[id]/edit` | 编辑器：双栏 Markdown、格式工具栏、⌘B/⌘I/⌘K、粘贴/拖拽上传、停止输入 30s 或失焦自动保存到 sessionStorage、实时字数与阅读时长、系列名联想（datalist）、AI 帮写、敏感扫描 |
| `/admin/logs/import` | 导入 Markdown：本地读 `.md`、推标题与 slug、只建草稿；slug 冲突跳过不覆盖 |
| `/admin/logs/[id]/preview` | 草稿预览：登录态可见的详情页同构排版（无印章、无 SEO），不生成公开链接 |
| `/admin/logs/[id]/snapshot` | 上次发布快照：只读回看发布当时的标题/正文/标签/系列（无印章、无 SEO） |
| `/admin/projects` | 项目管理：列表 + 表单 |
| `/admin/settings` | 设置：站点标识只读（标出来源键名）+ 个人显示名可改 + GitHub 集成状态只读 |
| `/admin/export` | JSON 导出（需登录） |

### 3.3 导航与全局交互

- 一级导航四项：作品档案 / 开发日志 / 标签 / 关于；当前项用棕左线或棕下划线。
- 右上：⌘K 搜索（按需加载命令面板）、亮/暗主题切换。
- 后台：左侧栏；操作回执用右下角 Toast（成功自动收起，错误保持到手动关闭）。

### 3.4 渲染与缓存语义

- `cacheComponents: true` + `partialPrefetching`：页面默认 PPR，静态壳 + 请求期数据。
- `export const instant = false` 的含义是"退出即时导航校验"，**不是**把路由改成动态。
- 需要请求期取数的页面先 `await connection()` 或直接查库（配 `instant = false`）。

## 四、工程与运维

### 4.1 命令

```
npm ci                       # 按锁文件安装
docker compose up -d         # 本地 PostgreSQL 16
npx prisma migrate dev       # 迁移（本地）
npm run dev                  # http://localhost:3000
npm run lint && npx tsc --noEmit && npm run build && npm test   # 四道门禁
node tools/软著材料生成.mjs    # 重出软著材料
```

### 4.2 性能预算（口径：Prisma 调用次数，不是 SQL 语句数）

| 页面 | 预算 | 2026-11-16 实测（调用 / SQL 语句） |
|---|---|---|
| `/logs` 首屏 | ≤2 | 2 / 5 |
| 任一前台页 | ≤3 | `/` 3/7、`/projects` 1/3、`/u/[handle]` 3/7 |
| 详情页 | ≤3 | 2 / 4（含 Proxy 1 条） |
| `/sitemap.xml` | ≤3 | 3 / 5 |

计数方法：dev 起 `log_statement='all'`，读 `docker logs`；**Prisma 语句在 `execute` 行，不在 `statement:` 行**。

### 4.3 环境变量（只列键名，值在 `.env` / 服务器）

- 必需：`DATABASE_URL`、`NEXTAUTH_SECRET`、`NEXTAUTH_URL`、`GITHUB_ID`、`GITHUB_SECRET`、`ENCRYPTION_KEY`
- 图片：`OSS_REGION`、`OSS_BUCKET`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`
- AI（可选）：`AI_API_KEY`、`AI_API_BASE_URL`、`AI_MODEL_NAME`
- 站点标识：`SITE_URL`、`SITE_NAME`、`SITE_DESCRIPTION`、`SITE_ICP`、`SITE_POLICE_ICP`、`SITE_CONTACT_EMAIL`
- 仅开发：`DEV_LOGIN_PASSWORD`、`DEV_LOGIN_USER`、`DEV_LOGIN_HANDLE`（生产不注册该 provider）

### 4.4 部署

`git push origin main` → GitHub Actions `ci.yml` 跑四道门禁 → `deploy.yml` SSH 到服务器：
`pg_dump` 备份 → 构建镜像 → `prisma migrate deploy` → 重启 → 轮询 `/api/health`（失败自动回滚上一版镜像）。

### 4.5 已知阻塞（2026-11-16）

- 软著材料：**已可正常出件**（2026-11-16 第十八次重出，18219 行 / 365 页 / 127 文件 / 提交 60 页 / 余量 116 行）。切口按 50 行页边界滑动，
  后续改源码可能重现“切口落在空行”的拒件，届时按生成器提示小幅平移文件或增减注释。
