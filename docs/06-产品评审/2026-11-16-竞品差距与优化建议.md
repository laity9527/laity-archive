# 竞品差距与优化建议（2026-11-16）

评审人：AI（产品视角）
方法：本项目 1440×900 实拍（首页 / 大厅 / 详情 / 标签 / 归档 / 作品 / 登录）+ 本会话已完成的后台 DOM 自查；
竞品侧按**产品形态分类**比较（不是逐家抄功能），每类只取"它做对了什么"。
局限：后台视觉细节未在本轮实拍（需登录）；`/logs` 在无头浏览器里受 PPR 揭示限制，按服务端 HTML 与人工确认结果判断。

---

## 一、先定位：我们不是哪一类产品

竞品可分四类，Laity 只与其中两类真正可比：

| 类别 | 代表 | 与我们的关系 |
|---|---|---|
| 身份卡/履历 | GitHub Profile、Read.cv 类 | **弱可比**：它们卖"被招聘方看见"，我们卖"可核对的工程判断" |
| 个人博客/静态站 | Bear Blog、Ghost、Hugo/Astro 主题 | **强可比**：排版、阅读、订阅、搜索是同一张考卷 |
| 知识库/双链 | Obsidian Publish、Quartz | **中可比**：它们做"内容之间连起来"，我们目前是"按时间/标签平铺" |
| 开发者社区 | Dev.to、Hashnode | **不可比**：社区靠流量与互动，我们明确无 UGC |

**结论**：真正要补的差距，来自"博客/静态站"与"知识库"这两类；与社区类比互动是自找麻烦。

---

## 二、我们明显领先的地方（别为了对标砍掉）

| 能力 | 我们 | 多数个人站 |
|---|---|---|
| 内容可核对 | 发布时写 SHA-256 + 服务器时间，详情页可复算 | 无 |
| 订阅格式 | RSS + JSON Feed，且**支持按标签订阅**（两种格式） | 多数只有 RSS |
| 阅读路径 | 目录 + 进度条 + 上下篇 + 相关阅读（同标签优先/同项目兜底） | 多数只有目录 |
| 结构化数据 | canonical + OG article + JSON-LD BlogPosting | 常见缺 JSON-LD |
| 后台写路径 | 双栏 Markdown、工具栏、⌘B/⌘I/⌘K、粘贴上传、自动保存、字数、敏感提示 | 多数是纯 textarea |
| 数据主权 | 自建库 + 全量 JSON 导出 | 平台锁定 |

这些是"克制底子"换来的资产，优化时不应该为了像竞品而稀释。

## 三、差距清单（按"读者能感知"排序）

### 3.1 阅读与发现（最痛）

| # | 差距 | 竞品怎么做 | 现状 | 建议 | 级别 |
|---|---|---|---|---|---|
| G1 | **内容之间不互联** | Obsidian/Quartz 的双链、Backlinks | 只有标签与相关阅读 | 支持正文 `[[slug]]` 内链，落点自动识别并生成"被引用"列表（纯 Markdown 插件 + 一次查询） | **P1** |
| G2 | **没有"系列/合集"** | 博客常见 series | 一篇一篇独立 | `Log.series` 字段 + 系列页（同系列按时间排序，顶部给进度"第 2/5 篇"） | **P1** |
| G3 | **搜索只到大厅** | 站点级搜索/命令面板是标配 | ⌘K 已能搜，但**结果不分组、无"查看全部"** | ⌘K 结果底部加"在大厅中查看全部结果"；补最近搜索 | P1（小） |
| G4 | **代码块无高亮** | 所有技术博客都有 | 只有语言标签+复制 | 维持"不做"（成本/体积不划算），但给代码块加"语言 + 行号"可选开关 | P2 |
| G5 | **归档无年份跳转** | 长档案常见年份锚点条 | 有 `#2026` 锚点但无入口 | 归档顶部加年份条（条目 >30 才显示） | P2 |
| G6 | **阅读设置缺失** | Bear 类有字号/宽度 | 固定 18px/720px | 加"紧凑/宽松"两档（cookie 记忆），不影响默认观感 | P3 |

### 3.2 后台效率（次痛）

| # | 差距 | 竞品怎么做 | 现状 | 建议 | 级别 |
|---|---|---|---|---|---|
| G7 | **没有草稿预览链接** | Ghost/Notion 可分享草稿 | 草稿只能自己看 | 一次性 token + 24h 过期 + 只读页（新表 `PreviewToken`） | **P1** |
| G8 | **没有版本历史** | Ghost 有修订记录 | 保存即退回草稿，旧正文无留痕 | 在 `Log` 上存"上次发布快照"（JSON 字段），详情可对比 | P1 |
| G9 | **列表不能按项目筛** | 后台标配 | 只有状态 + 标题搜索 | 加项目下拉（复用 facets） | P1（小） |
| G10 | **不能导入** | Ghost/Hexo 有导入 | 只有导出 | 按 slug 幂等导入 Markdown（冲突三选一） | P2 |
| G11 | **无定时发布** | Ghost/WordPress | 只能手动点 | `publishedAt` 未来时间 + 到点可见（需要请求期判断） | P2 |
| G12 | **概览无趋势** | 后台惯例 | 四张计数卡 | 近 12 周发布柱（纯 CSS，不引图表库） | P2 |

### 3.3 传播与站点健康（可选）

| # | 差距 | 建议 | 级别 |
|---|---|---|---|
| G13 | 无分享按钮 | 详情页加 Web Share + 复制链接（复制已有，缺"分享"） | P2 |
| G14 | 无 OG 图 | 维持不做（CJK 字体成本）；若做，只放站点名+日期，不放中文长标题 | P3 |
| G15 | 无访问统计 | 自建匿名计数（仅聚合、不存 IP），或不做 | P3 |
| G16 | 无 feed 分页 | JSON Feed 支持 `next_url`，日志过 20 篇再考虑 | P3 |

## 四、明确不建议跟随的竞品动作

| 竞品做法 | 为什么不做 |
|---|---|
| 评论区、点赞、关注 | 与"无 UGC"定位冲突；维护成本与风险（垃圾、合规）远高于收益 |
| 花哨的滚动动效/视差 | 与"档案阅读"气质相反；且拖累性能 |
| 卡片阴影、大圆角、彩色渐变 | 会稀释纸白/墨色的品牌资产 |
| 社交平台式信息流 | 我们是"档案"，不是"动态" |
| 强行上全文检索（Meilisearch 等） | 当前 13 篇；`contains` 足够，等破千再评估 |

## 五、优先顺序（建议三批）

| 批次 | 内容 | 理由 | 预估 |
|---|---|---|---|
| **第 1 批** | G3 搜索"查看全部" + G9 项目筛选 + G5 年份条 | 全是小改动，读者与作者都能立刻感到顺 | 1 人日 |
| **第 2 批** | G1 内链 + G2 系列 | 这两条把"平铺档案"变成"可走的知识网络"，是最大结构增量 | 3–4 人日（含一次迁移） |
| **第 3 批** | G7 草稿预览 + G8 版本快照 | 写作安全感；需要新表/字段，单独迁移 | 3 人日 |

G1/G2/G7/G8 都要动数据模型，建议一次评审后作为"V3.1"立项；前三项（第 1 批）不需要迁移，可随时做。

## 六、需要你确认的一件事

G7（草稿预览链接）要引入**一次性 token 与可公开访问的只读页**——它意味着"未发布内容可以离开登录态"。
这属于发布面/合规面的决定，我不自行裁定：你点头我再做。
其余各项（内链、系列、年份条、搜索入口、项目筛选）都只影响已发布内容，我可以直接排期。
