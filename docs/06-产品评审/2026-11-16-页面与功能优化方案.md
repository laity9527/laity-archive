# 页面与功能评审：优化方案（2026-11-16）

评审人：AI（产品视角）
方法：1440×900 实拍 4 页（首页 / 日志详情 / 标签 / 作品）+ 服务端 DOM 与代码核对。
局限（如实标注）：`/logs` 与后台的截图受自动化浏览器限制（隐藏标签页不执行揭示脚本、后台需登录），
这两处的结论来自 DOM 结构、本会话已做过的后台自查与代码，不是"看图说话"。

---

## 一、一句话结论

**视觉与气质是站得住的**：纸白、墨色、宋体、细线、无装饰，读起来像一份档案而不是一个产品页。
问题不在"好看不好看"，而在三处：

1. **低内容量下的版面失衡**——首页精选只有 1 条时，左边 2/3 空着，右边挤着两块；
2. **索引没兑现索引价值**——52 个标签、53 次引用，等于"每个标签只用一次"，标签云的分档失去意义；
3. **少数排版细节在破坏"精确"的人设**——大标题折行断在"每一次"中间、面包屑重复标题、目录出现两个 01。

这三处的共同点是：**不是缺功能，而是已有结构在真实数据量下没被验证过**。

## 二、前台逐页诊断

### 2.1 首页（实拍）

| 观察 | 判断 | 建议 |
|---|---|---|
| 大标题折行为「数字档案，记录每一 / 次工程决策。」 | **P0** 断在词中间，破坏"克制精确"的第一印象 | 宽度从 `max-w-[14ch]` 调到 16–18ch，或在「每一次」前显式换行；验收：1440/1280/1024 三档都不断词 |
| 精选项目只有 1 条，左栏 2/3 大面积留白 | **P0** 版面失衡，读者会以为"内容没了" | 精选 <2 条时改为整宽单列，或把「最新日志」提上来与精选并排 |
| 档案状态行：名称、标签、日志数、日期挤成两行且不对齐 | **P1** 行高不齐，扫读成本高 | 右侧固定列显示「12 篇 · 2026-11-06」，与左侧名称同一基线 |
| 馆藏条（2 个项目 / 12 条 / 最近更新 / RSS） | 好——信息密度与位置都合适 | 保留 |

### 2.2 日志详情（实拍）

| 观察 | 判断 | 建议 |
|---|---|---|
| 面包屑末项是完整文章标题，紧挨 H1 又是同一句 | **P0** 重复且长标题会占两行 | 末项只保留到项目名；或截断到 12 字加省略号 |
| 右侧目录 BEFORE/AFTER 编号 | **已撤回（复核结论）** | 实测产物目录编号为 **01–06 连续**（HTML 里看到的两个 01 是“桌面右栏 + 移动折叠面板”两套渲染器，不是两组各自从头编）；我此前的判断是误读，本条不作修改项 |
| 标题 2 行、双线、时间轴、标签、时长 — 层次清楚 | 好 | 保留 |
| 正文 720px 宋体 18/1.85 | 好——这是全站最强的部分 | 保留 |

### 2.3 标签索引（实拍）

- 现状：`52 个标签 · 被引用 53 次`，列表按频次降序 + 名称；实测只有 14px / 16px 两档真的出现。
- 判断：**分档在数据平坦时不成立**（每标签约 1 次），"云"退化成一段带数字的文字墙。
- 建议（**P1**）：
  1. 按 `topics.ts` 的 8 个主题**分组**呈现（组内按名称排序），未归入主题的进「其他」；
  2. 频次降级为灰色小字，不再用字号表达权重；
  3. 验收：52 个标签分 8–9 组，首屏可见组标题；点任一标签仍进聚合页。

### 2.4 作品档案（实拍）

| 观察 | 判断 | 建议 |
|---|---|---|
| 右栏「12 篇日志 / 最近一篇 / 查看档案」三行，与左侧标题基线不齐 | **P2** 观感毛刺 | 右栏压成两行（计数 + 日期），「查看档案」改成整行可点 |
| `GitHub 同步` 0 篇日志仍给「查看档案」 | **P2** 空项目也引导进入，期望落差 | 0 篇时文案改「还没有日志」并链到 `/logs?project=` |
| 编号 01/02 + 状态点 + 类型/状态 + slug | 好 | 保留 |

### 2.5 其余页面（按 DOM/代码，不冒充截图）

- **大厅 `/logs`**：筛选（项目/主题/标签）+ 搜索 + 排序切换 + 空态双出口都已齐备；PM 视角**不建议再加筛选维度**，复杂度收益已到顶。
- **归档 `/archive`**：年/月分组够用；长列表缺"年份跳转条"（**P2**，条目过 30 再考虑）。
- **关于 / 登录 / 404 / 隐私 / 许可**：结构与文案合规；登录页建议补一句"为什么只能用 GitHub 登录"（**P2**，减少陌生访客的疑虑）。

## 三、后台诊断（DOM/代码 + 本会话自查结论）

| 区块 | 已具备 | 缺口 | 建议 |
|---|---|---|---|
| 概览 | 四卡（项目/已发布/草稿/近 7 天）、继续处理、同步/导出/新建 | 无趋势、无"最近编辑" | **P2** 加一条近 12 周发布柱（纯 CSS，不引图表库） |
| 日志列表 | 状态 tab、标题搜索、分页、行内发布/下架、批量下架、Toast | 无按项目筛选；无批量发布（已裁定不做） | **P2** 加项目筛选；批量发布维持不做（需逐条重算摘要） |
| 编辑器 | 双栏、工具栏、⌘B/⌘I/⌘K、粘贴/拖拽上传、自动保存、字数与时长 | 缺预览滚动同步、缺敏感信息实时提示 | **P2** 敏感提示优先（复用 `sensitive-scan`，把发布前的拦截提前到编辑时） |
| 项目管理 | 列表 + 表单 | — | 保持 |
| 设置 | **不存在** | 站点标识、社交链接、默认主题只能改 env | **P1** 新增 `/admin/settings`（只读展示 + 可改项，写操作走既有 Server Action 模式） |

## 六、与现有计划的关系

- 不改 B0–B5 已完成的结构与令牌，**不动数据模型**（标签分组复用现有 `topics.ts`，设置页可先只读）。
- 本评审**不包含**：换肤、加图标库/图表库、OG 分享图（CJK 字体成本）、批量发布、`tagsKey` 双轨。
- 第 1 批做完后，建议重出一次软著材料（源码会变动）。

这批问题都不大，但都发生在"读者第一眼看到的地方"（首页标题、精选版面、详情面包屑、标签索引）。
