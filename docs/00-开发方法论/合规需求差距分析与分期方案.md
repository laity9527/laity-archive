## 一、先解决定位分歧（后面所有工作量都卡在这一条）

| 维度 | 外部方案假设的产品 | 本仓库现实 |
|---|---|---|
| 用户 | 多用户注册平台（个人开发者 80% + 团队 15% + 招聘方 5%） | 单人：我本人的档案库 |
| 认证 | 邮箱+密码、手机号验证码、GitHub 绑定 | 仅 GitHub OAuth，按 `ALLOWED_GITHUB_IDS` 数字 ID 白名单放行 |
| 数据归属 | 每行数据带 `userId`，严格租户隔离 | `prisma/schema.prisma` 只有 `Project` 与 `Log` 两个模型，**无 User、无 userId** |
| 内容性质 | UGC 平台，需避风港与投诉处理 | 只有我自己发布的内容，无第三方投稿 |
| 商业 | Pro 会员、自定义域名、去页脚标识 | 无付费、无多租户域名 |

三条实测证据（不是推断）：

1. `prisma/schema.prisma:17,29` 只有 `model Project` 与 `model Log`，全文没有 `userId` 与 `model User`。
2. 全仓仅 `src/lib/projects.ts:214` 一处 `db.project.delete`，**日志没有删除能力**，只有"下架"（`src/lib/publish.ts` 的 `unpublishLog` 只翻 `isPublished`）。
3. `src/auth.ts:48` 只往 JWT 里写 `token.githubId`，库里不存邮箱、不存手机号、不存 GitHub Token。
   —— 也就是说，在"最小必要收集"这一项上，**现状比外部方案的假设更严格**（它默认平台会存邮箱、手机与加密 Token）。

结论：外部方案不能整体照抄。它约六成条目的前提（多用户、UGC、付费）在本仓库不成立；
照抄会同时违反 AGENTS.md 的"不得新增依赖""每个 Phase 只做该 Phase""禁止提前实现后续 Phase"三条红线。

## 三、三个决策点（本轮提问未获答复，故一律未开工）

**决策一：产品定位。** 单人档案库 + 合规收口 / 转多用户平台 / 先单人后多用户分两期。
代价对比：转多用户 = 新增至少 4 个依赖与 3 个外部付费服务、schema 大改、每个 lib 查询加 `userId`、
AGENTS.md/SPEC/DESIGN 重写、**已出的十轮软著材料与登记名"Laity 项目档案库软件 V1.0"作废重出**。

**决策二：「存证 / 防伪 / 证据链」措辞。** 外部方案 3.3.2 要求收紧为中性技术标记。
现状该词族分布在 9 个文件（`src/components/Seal.tsx`、`src/app/logs/page.tsx`、`src/app/logs/[slug]/page.tsx`、
`src/lib/content-hash.ts`、`src/lib/publish.ts`、`src/lib/site.ts`、`src/app/admin/log-actions.ts`、
`docs/04-软著材料/软件操作说明书.md`、`SPEC.md`），且产品定位本身就叫"开发复盘证据链"。
三个选项：保留（并驳回外部方案这一条）/ 全面收紧（连带说明书与材料重出）/ 折中（对外中性、对内与软著保留）。
**注意**：`contentHash` 的技术语义不受措辞影响，改的只是宣传口径。

**决策三：日志"彻底删除"要不要做。** 外部方案要删除权；D9 要保留历史摘要与发布时间作留痕。
二者不可同时满足。可选：只加"作者本人彻底删除"且删除前二次确认并记录一条删除事件；或维持"下架即不可见"。

## 五、一句话总结

外部方案里真正适合现在动手的只有 **1 条**（发布前敏感信息检测，零依赖、单人多用户都用得上）
和 **4 个低成本元素**（版权行、公安备案号位、`/licenses`、商标声明）；
其余要么已经满足，要么前提不成立，要么需要你先在三个决策点上拍板并给出主体信息与预算。
