## 二、安装步骤

### 1. Node.js
- 从官网 nodejs.org 下载 LTS 的 Windows 安装包（.msi），一路默认安装；
- 安装后新开一个终端验证：

```bash
node -v    # 预期 ≥ v22
npm -v
```

- 本机 npm 走 npmmirror 镜像，装完顺手确认一下：

```bash
npm config get registry   # 若输出 npmmirror 属正常，install 可用
```

- 注意：npmmirror 未实现 security 端点，`npm audit` 会报错，属已知情况，不代表依赖有问题。

### 2. Docker Desktop
- 官网 docker.com 下载 Docker Desktop for Windows，安装时勾选 WSL2 后端（安装器会引导装 WSL2，需重启一次）；
- 启动 Docker Desktop 后验证：

```bash
docker -v
docker ps    # 能列出（空）容器列表即为就绪
```

### 3. Git 关联远端仓库

本地文件夹已有 docs 等文件，不是空目录，按下面顺序关联（在 D:\ZHANGLEI\laity-archive 下执行）：

```bash
git init
git remote add origin https://github.com/laity9527/laity-archive.git
git fetch origin
# 若远端 main 已有文件（网页端提交过的骨架/日志）：
git checkout -b main
git pull origin main --allow-unrelated-histories
# 如有冲突，逐个保留双方内容后手工合并，不许粗暴覆盖
git add .
git commit -m "从0启动文档入库：方法论、规格、设计、路线图"
git push -u origin main
```

提交信息用我自己的话写，删掉任何工具自动生成的英文描述。

## 三、首次跑通（Phase 1 脚手架就绪后）

```bash
npm install
docker compose up -d           # 拉起 laity-postgres
npx prisma migrate dev         # 建表
npx prisma db seed             # 种子数据
npm run dev                    # 打开 http://localhost:3000
```

跑通的判定不是"命令没报错"，而是 DESIGN.md Phase 1 的 6 条验收标准逐条 PASS。

## 五、已知坑提前记

1. WSL2 安装需要 BIOS 虚拟化开启，若 Docker 启动报 virtualization 错误，先进 BIOS 开 VT-x/SVM；
2. Windows 下 Prisma 迁移偶发文件锁报错，关掉占用 prisma 目录的编辑器/杀软实时扫描再重试；
3. 端口冲突：5432 被占说明本机已有 Postgres，停掉它或改 compose 映射端口（改映射属于配置变更，走停点报批）。
