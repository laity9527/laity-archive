## 二、安装步骤

### 1. Node.js
- 从官网 nodejs.org 下载 LTS 的 Windows 安装包（.msi），一路默认安装；
- 安装后新开一个终端验证：

```bash
node -v    # 预期 ≥ v22
npm -v
```

- 本机 npm 走 npmmirror 镜像，装完顺手确认一下：

```bash
npm config get registry   # 若输出 npmmirror 属正常，install 可用
```

- 注意：npmmirror 未实现 security 端点，`npm audit` 会报错，属已知情况，不代表依赖有问题。

### 2. WSL2（先于 Docker Desktop，不要等安装器代劳）

Docker Desktop 的安装器在这台机器上**没有**代为安装 WSL2，引擎因此起不来。顺序改成先装 WSL2：

```bash
wsl --status    # 期望输出含"默认版本：2"；若提示"未安装适用于 Linux 的 Windows 子系统"就是缺
```

- 缺则用管理员权限的 PowerShell 执行 `wsl --install`，完成后**必须重启**，再跑一次 `wsl --status` 复核；
- 重启后 Docker Desktop 不再报 `Docker Desktop is unable to start`，才算这一关过了。

### 3. Docker Desktop
- 官网 docker.com 下载 Docker Desktop for Windows，安装后启动，验证：

```bash
docker -v
docker ps    # 能列出（空）容器列表即为就绪
```

⚠️ 只看到 `docker -v` 有输出不算装好——CLI 装上了但引擎没起来时，`docker ps` 会报 `Docker Desktop is unable to start`，这时回去做上一步。

### 4. Git 关联远端仓库

本地文件夹已有 docs 等文件，不是空目录，按下面顺序关联（在 D:\ZHANGLEI\laity-archive 下执行）：

```bash
git init
git remote add origin https://github.com/laity9527/laity-archive.git
git fetch origin
# 若远端 main 已有文件（网页端提交过的骨架/日志）：
git checkout -b main
git pull origin main --allow-unrelated-histories
# 如有冲突，逐个保留双方内容后手工合并，不许粗暴覆盖
git add .
git commit -m "从0启动文档入库：方法论、规格、设计、路线图"
git push -u origin main
```

提交信息用我自己的话写，删掉任何工具自动生成的英文描述。

## 三、首次跑通（Phase 1 脚手架就绪后）

```bash

```

## 五、已知坑提前记

0. **Docker Desktop 装了不等于能用。** 本机实测：`docker -v` 正常，`docker ps` 报 `Docker Desktop is unable to start`，`wsl --status` 显示"未安装适用于 Linux 的 Windows 子系统"。Windows 上的 Docker 引擎跑在 WSL2 里，WSL2 缺席时整套数据库验收全部阻塞（对应 ISSUES I004）。顺序永远是：WSL2 装好并重启 → 确认 `wsl --status` → 再启 Docker Desktop。
1. WSL2 安装需要 BIOS 虚拟化开启，若 Docker 启动报 virtualization 错误，先进 BIOS 开 VT-x/SVM；
2. Windows 下 Prisma 偶发 `EPERM: rename …query_engine-windows.dll.node`——实测根因是还有 `next start`/`next dev` 在跑，进程占着这个 DLL。先查 `Get-CimInstance Win32_Process -Filter "name='node.exe'"` 里有没有本项目残留进程，结束后再 `npx prisma generate`；杀软实时扫描也可能造成同类报错；
3. 端口冲突：5432 被占说明本机已有 Postgres，停掉它或改 compose 映射端口（改映射属于配置变更，走停点报批）；
4. **Docker Hub 直连不通。** 本机实测 `registry-1.docker.io` 探测返回 000（无代理），`docker compose up -d` 报 `dial tcp … connectex`。处置：从可达镜像站拉取后本地打标，不改 Docker 配置——
   ```bash
   docker pull docker.m.daocloud.io/library/postgres:16
   docker tag docker.m.daocloud.io/library/postgres:16 postgres:16
   docker compose up -d
   ```
   拉取时记下 digest（本次为 `sha256:1beaa308…77c61c`）留痕；日后有代理时可用官方源重拉覆盖。
