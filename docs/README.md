## 三、文档状态标签

每份非日志类文档在标题下用引用块写状态，四选一：

| 标签 | 含义 | 能否作为实现依据 |
|---|---|---|
| **现行** | 与当前代码一致，随改动同步 | 能 |
| **已实施** | 方案已落地，保留决策与验收记录 | 能查口径，落地细节以现状说明书为准 |
| **历史快照** | 某个日期的报告/建议，数字与结论可能过期 | 不能，仅作过程证据 |
| **已封存 / 未采纳** | 位于 `archive/`，只查历史 | 不能 |

判断"过期"的唯一标准是：**文中口径与 `现状说明书.md` 或代码实测不一致**。
过期不等于删除——先改成「历史快照」并指向现行事实，只有确认无人引用且信息已被完整吸收时才删除。

## 四、格式约定

新建或实质修改文档时按此写；未改动到的旧文档保持原样，随下次修改逐步归一，不做一次性重排。

### 4.1 标题层级

- 全文只有一个 `#`，标题即文件名主题，不加日期后缀（日期写进状态块）。
- `##` 用中文序号（`## 一、结论`）或一句话语义标题（`## 当前状态快照`）；**同一文档内只用一种**，不混排。历史文档保留原风格，重写时再归一。
- `###` 用两级数字（`### 2.1 数据模型`）或语义短标题；`#` 下不直接出现 `###`。
- 段尾不再用 `---` 分隔线堆叠。

### 4.2 列表与表格

- 无序列表统一 `-`，不用 `*` / `+`；嵌套缩进 2 个空格。
- 有序步骤用 `1.` `2.`，不手写"第一步/第二步"。
- 需要横向对照时用表格，首列是判据对象而不是序号；表格前后各留一个空行。

### 4.3 代码块

- 一律围栏式，标注语言：`bash`、`text`、`prisma`、`json`、`ts`。
- 无法判断语言时用 `text`，不臆造高亮；旧文档的裸围栏已统一补齐。
- 命令块只放可复制的命令，注释写在命令右侧或块外，不混排解释段落。
- 路径分隔符在文档中统一 `/`（Windows 实测差异写进正文说明）。

### 4.4 链接

- 仓内链接一律**相对路径**，如 `[现状说明书](现状说明书.md)`、`[V4](05-重构方案/重构方案V4-完整版-2026-11-17.md)`。
- 禁止带本机盘符的绝对链接与百分号编码路径（形如 `%E7%8E%B0...`）——换机器即失效，且不可读。
- 目录链接以 `/` 结尾；指向章节用锚点（`#三文档状态标签`），锚点只用于同文件。
- 外部链接写完整的 `https://`，不写裸域名。

### 4.5 文件命名

- 常驻文档：`主题.md`，版本进文件名（`重构方案V4-完整版-2026-11-17.md`）。
- 一次性文档：`YYYY-MM-DD-主题.md`，日期在前，便于排序；旧文件里的"主题-YYYY-MM-DD"不再重命名，避免打断既有引用。
- 禁止 `最终`、`最新`、`副本`、`new`、`final` 等无法排序的词。
- 归档目录用 `YYYY-MM-DD-主题/`，同一天的归档合并到一个目录，不按人/按批次再分层。

## 五、常见操作

| 要做的事 | 正确做法 |
|---|---|
| 事实变了 | 改 `现状说明书.md` 对应章节 + 变更记录加一行（带日期） |
| 新决策 | 记进 V4 或研发日志；不再新起 `DESIGN.md` 式编号体系 |
| 方案落地了 | 在方案头部把状态从"待批准"改为"已实施（日期）"，并指向现状说明书 |
| 方案被取代 | 移入 `archive/`，加封存头写明"被谁取代、采纳项在哪" |
| 发现两份文档打架 | 以代码实测为准，改错的那份，并在研发日志留一行 |
| 想删一份文档 | 先全局搜索文件名与标题；确认无引用且信息已吸收，再删，并在本轮汇报里列出 |
