Laity 档案库 · 全站重构方案（V2 · 2026-11-13）

一句话判断：这个站点的品牌资产是"克制"——纸白、墨色、宋体、存证感。推翻它去做现代 SaaS 是净损失。
所以本轮方向定为：**保留骨相，重做肌肉、关节与皮肤，并补上现在缺的功能闭环。**

红线已放开，本方案按"产品与体验最优"设计，不再受门禁顺序、视觉铁律、点名授权、留痕铁律约束。
但有一类东西我不建议一起放开：**正确性**。摘要口径（D5）、租户隔离、发布即失真提醒、
密钥不落库不进日志——这些不是仪式，是产品可信度本身。方案里凡涉及它们的地方，一律按"不许动"处理。

======================================================================
零、与上一版方案的关系（先纠正三处事实，避免重复投入）
======================================================================

上一版方案（本文件旧内容）是一份"可能性清单"，功能面铺得很全，但有三类问题：

1) **把已经做完的当成待做**。以下能力在 2026-11-13 的代码里已经存在，上一版仍列为 P1/P2：
   - 上下篇导航、相关阅读（同标签优先 / 同项目兜底）—— `lib/related.ts` + 详情页
   - 大厅分页 —— 已改游标分页（50 条/页，`getLogList` 的 nextCursor）
   - 阅读时长估算 —— `lib/reading-time.ts`，详情页头部显示
   - 复制摘要/链接 —— `components/Seal.tsx` 的档案凭据卡
   - 阅读目录 + 进度条 —— `ArticleToc.tsx` + CSS 滚动驱动进度条
   - 搜索高亮与命中片段 —— `lib/highlight.ts`，大厅 `?q=`
   - JSON-LD 结构化数据 —— 本轮已落 `BlogPosting`（详情页），canonical / OG article 同步
   - 标签聚合页 —— `/tags/[tag]` 已有，含 proxy 真 404
   - RSS 订阅 —— `/feed.xml`（手写 XML，零依赖）
   - 全站数据导出 —— `/admin/export`
   - 跳转正文链接与 aria-current —— `SiteNav` 已具备

2) **两处技术判断需要反着写**：
   - "零圆角 → 2px 微圆角"：不建议。2px 在 1x 屏几乎不可见，却要新增一条令牌、全站一致性检查，
     以及和 1px 线的视觉冲突。层级该由留白与线重表达，不是圆角。**保留 0，浮层可用 4px。**
   - "引入 lucide-react 降认知成本"：不建议。这个站的视觉语言是 1.5px 等宽线性，
     自绘 14 个 `currentColor` 的 SVG 足够，且不会引入 40KB+ 依赖与风格漂移。

3) **把"视觉重构"当成了主菜**。真正的缺口在**结构与状态**：
   导航只有 3 项、没有标签索引、没有归档视图、没有全局检索入口；
   后台没有行内操作与批量；编辑器缺工具栏与自动保存；所有操作反馈靠 URL 参数。
   换肤解决不了这些。

本版方案因此按"结构 → 状态 → 功能 → 皮肤"的顺序组织。

======================================================================
一、现状盘点（按代码实测，不是按文档描述）
======================================================================

1.1 已经站得住的部分（不要动坏了）
- 视觉底座：纸白 #f4f1ec / 墨 #1a1a18 / 辅助灰 #625d53 / 1px 暖线 #d9d2c5；零圆角、零阴影、无渐变。
- 排版底座：正文 Noto Serif SC 18px/1.85，限宽 720px；UI 走 Inter；标签与数字走 JetBrains Mono。
- 中文字体已经按 unicode-range 分片自托管：产物里 602 个 CJK 区间、114 个 woff2（不是"只有 latin 子集"，
  上一版若按此判断会误开一项优化工作）。
- 发布链路：表单 → 保存 → 按 D5 口径算 SHA-256 → 记服务器时间 → 详情页印章可核对。
- 安全底座：Markdown 过 rehype-sanitize；上传按文件内容签名判类型；DAL 强制 userId；
  Proxy 对详情路由做真 404。
- 可访问性起点：跳转正文链接、aria-current、焦点可见、prefers-reduced-motion 已有。

1.2 真实缺口（本方案的靶子）
A. 导航与发现
   - 一级导航只有 作品档案 / 开发日志 / 关于；标签只能从日志里点进去，**没有标签索引页**。
   - 没有归档视图（按年月回看），也没有"随便看看 / 继续读"这类轻量入口。
   - 搜索只在大厅内，**没有全局入口**，也没有键盘唤起方式。

B. 阅读端
   - 详情页信息层级偏平：面包屑缺失，项目/时间/标签/时长挤在一处。
   - BEFORE / AFTER / 经验总结三段只有小标题分隔，长文里缺"区块感"。
   - 代码块没有语言标识、没有复制按钮、没有行号；图片不能放大。
   - 打印时导航、进度条、目录右栏都会进纸面。

C. 创作侧
   - 编辑器没有格式工具栏、没有快捷键、不能拖拽/粘贴上传。
   - 只有"保存前"的 sessionStorage 暂存，没有定时自动保存与可见状态。
   - 敏感信息扫描只在发布时跑，编辑时看不到命中。
   - Slug 要手填；标签要手打（无补全）。
   - 草稿无法给别人看（没有只读预览链接）。

D. 运营侧
   - 后台日志列表只能点进编辑页，**没有行内发布/下架/删除，没有批量**。
   - 没有审计（"我上次改了什么"），没有设置页，没有导入（导出已有）。
   - 概览只有计数与最近草稿，没有趋势/分布。

E. 分发与分享
   - 没有 OG 分享图；分享只能复制链接。
   - 只有 RSS，没有 JSON Feed；RSS 不支持按标签/项目订阅。

F. 反馈与状态
   - 所有操作结果靠 `?saved=1` / `?error=XXX` 回显，刷新即丢、无动效、无"下一步"。
   - 加载态只有骨架行，空态只有一句话，错误态只有错误码。

二、设计方向（克制升级，含四条明确裁定）
======================================================================

2.1 保留（骨相，不许动）
- 纸白底、墨色字、宋体正文、等宽标签。
- 0 圆角、无阴影、无渐变；层级只用"留白 + 线重 + 字号阶"。
- 棕 #7a5a3a 作为唯一强调色，不引入第二强调色。
- 720px 正文限宽（这是阅读体验的硬约束，不是为了好看）。

2.2 升级（肌肉与皮肤）
- **间距节奏**：统一 4/8/12/16/24/32/48/64/96/128 十档，全站禁止 5px、7px 这类手写值；
  节与节之间固定 64/96 两档，段落内 16/24。
- **字号阶**：display 44–56（clamp）、h1 32、h2 24、h3 20、body 18（正文）/15（界面）、meta 12、micro 10。
  界面文字统一 15px（现在 11/12px 混用太多，中文在 11px 下笔画糊）。
- **线重三档**：hairline（#d9d2c5，分隔）/ ink（#1a1a18，区块起止）/ 双线（详情页头部与印章区，
  用 border-top + 1px 偏移的第二条线）——用线表达层级，替代阴影。
- **强调色扩权（有边界）**：棕可用于"当前项左线 / 链接 hover 下划线 / 阅读进度 / 目录当前项 / mark 底色"；
  **不允许**用于按钮填充、卡片背景、大标题。理由：棕一扩大面积，纸感立刻变成"旧报纸"。
- **动效**：只做两件事——hover 的颜色过渡（120ms）与页面进入的透明度位移（180ms，`prefers-reduced-motion` 关闭）。
  不做视差、不做滚动放大、不做 View Transitions（它是整页替换，会打断 PPR 的流式观感）。
- **暗色模式**：做。暖黑 `#141311` 底 + 纸白 `#e8e3da` 字，线与棕同步降明度；
  `html[data-theme]` 覆盖语义层，跟随系统 + 手动切换（localStorage 记忆），
  首屏用 6 行内联脚本消除闪白。正文不用纯黑底纯白字（长时间阅读刺眼）。

2.3 明确不做（否则就是另一种廉价）
- 微圆角铺满、彩色渐变、玻璃拟态、卡片阴影、大图标导航、彩色状态标签。
- 亮色/暗色两套品牌色（暗色只做明度映射，不换色相）。

2.4 Token 分层（落地形态）
```
原始层    paper #f4f1ec · ink #1a1a18 · ink-soft #625d53 · hairline #d9d2c5 · brown #7a5a3a
语义层    --bg --bg-raised --fg --fg-muted --fg-subtle --accent --line --line-strong
          --danger --success --warning（后三者只用于后台状态与错误，不进前台正文）
组件层    按钮/输入/卡片不设独立令牌，直接引用语义层，避免第三套真值
暗色      只覆盖语义层，原始层不动
```

三、信息架构（目标形态）
======================================================================

3.1 一级导航（从 3 项扩到 4 项 + 2 个入口）
```
[LAITY]   作品档案   开发日志   标签   关于        [⌘K 搜索]  [◑ 主题]
```
- "标签"是新页 `/tags`；"关于"保留。
- 搜索不再是页面内控件，而是**常驻入口**：点开是居中命令面板（⌘K / Ctrl+K / `/`），
  可搜日志、项目、标签，也可直接跳转页面。
- 主题切换放导航右端，移动端收进菜单。

3.2 新增两个页面（这是 IA 缺口，不是功能堆叠）
- `/tags`：标签索引。按"使用频次"分三档字号（≥5 条 / 2–4 条 / 1 条），点击进 `/tags/[tag]`。
- `/archive`：归档。按年月分组的时间线，每年一个区块，条目只显示标题 + 项目 + 日期。

3.3 路由不变的部分
- `/`、`/logs`、`/projects`、`/u/[handle]`、`/u/[handle]/logs/[slug]`、`/u/[handle]/projects/[slug]`、
  `/tags/[tag]`、`/about`、`/login`、`/admin/**`、`/feed.xml`、`/sitemap.xml`、`/api/health` 全部保留。
- 后台不新增顶级路由，只在 `/admin` 下加 `/admin/settings`。

======================================================================
四、页面逐页重构规格
======================================================================

每页给四件事：**目标 / 布局 / 状态 / 验收**。状态指空、加载、错误、极端数据四类。

4.1 首页 `/`
- 目标：三秒内说清"这是谁、做了什么、最近在干什么"。
- 布局（自上而下）：
  1) Hero：`clamp(2.5rem, 5.5vw, 4.5rem)` 两行标语 + 18px 副标 + 右侧"最近发布 2026-11-13"；
     标语下面加一条 1px ink 线，与内容区形成"封面—目录"关系。
  2) 馆藏条：项目数 / 已发布数 / 最近更新 / RSS 入口，保留现有形态但统一 15px。
  3) 精选项目：3 条，改为"编号 + 名称 + 一句摘要 + 元信息"，行高加倍（现在偏挤）；
     零日志项目不进精选。
  4) 最新日志：3 条，时间轴保留，标题 20px，经验总结两行截断。
  5) 按主题：8 宫格保留，补"全部日志 →"。
- 状态：无数据时 Hero 下方直接给"还没有内容，去后台写第一条"（仅登录可见），访客看空态文案。
- 验收：1440/768/375 三档无横向滚动；首屏 JS ≤ 现状；Prisma 调用 ≤ 3。

4.2 日志大厅 `/logs`
- 目标：从"能筛"升级为"能找到"。
- 布局：
  - 顶栏：标题 + 结果计数 + 排序（判断时间 / 发布时间）+ 视图（列表 / 紧凑）。
  - 左栏 180px 保留（项目 / 主题 / 全部标签）；选中态由"下划线"改为"棕左线 + 墨字"，
    与目录右栏形成同一套"当前项"语言。
  - 搜索框移到顶栏右侧，回车提交；`/` 键聚焦。
  - 列表行：标题 20px + 项目 · 日期 · 标签；命中时片段行（保留现有 BEFORE/AFTER 片段）。
  - 底部：上一页 / 下一页 + "第 N 页"（游标分页已有，补页码感）。
- 状态：
  - 搜索无结果 → 给"去掉关键词"与"去标签页"两个出口。
  - 筛选无结果 → 给"清除筛选"与"看全部"。
  - 首次空库 → 一句"还没有日志"，不放搜索框。
- 验收：`?q=` 有结果时高亮可用；键盘 Tab 顺序 = 搜索 → 筛选 → 列表；移动端筛选折叠为一行按钮。

4.3 日志详情 `/u/[handle]/logs/[slug]`
- 目标：长文阅读体验与"可核对"体验都要立住。
- 布局：
  - 面包屑：`档案 / 开发日志 / 项目名`（12px，辅助灰，可点）。
  - 头部：项目名（mono）→ 标题（32px）→ 双时间轴 → 标签 → 阅读时长；底部 1px ink 线。
  - 正文：BEFORE / AFTER / 经验总结三段，每段前加"区块头"（编号 + 名称 + 一列细线），
    不再只是小标题；经验总结用棕左线引用块（2px 棕线 + 纸白底）。
  - 目录：桌面右栏 sticky 保留，当前项改"棕左线 + 墨字"；移动端折叠面板保留。
  - 代码块：语言标签（右上角，mono 10px）+ 复制按钮；行号可选；纸感边框，不加背景色块。
  - 图片：点击开原生 `<dialog>` 灯箱（Esc 关闭，焦点陷阱）。
  - 尾部：档案凭据卡（保留）+ 上一篇/下一篇 + 相关阅读三条。
  - 打印：`@media print` 隐藏导航/目录/进度条/复制按钮，正文全宽，印章保留（这一条很重要，
    因为"存证"场景本来就会被打印）。
- 状态：摘要缺失告警保留；目录项 <2 时不画目录；无 tags 时不渲染该行。
- 验收：正文行宽 720px ±0；目录点击落点不被导航遮挡；打印预览 3 页内、无 UI 元素。

4.4 作品档案 `/projects`
- 布局：改为两列卡片（≥1024），每卡：名称 + 类型/状态徽章 + 一句摘要 + 日志数 + 最近日期。
- 状态：零项目 → 空态；零日志项目卡片显示"尚未发布"，不隐藏。
- 验收：卡片高度不齐时用网格自动等高；hover 只变线色，不位移。

4.5 项目详情 `/u/[handle]/projects/[slug]`
- 布局：顶部信息卡（名称、类型、状态、始于、仓库外链）+ 该项目日志（ListRow）。
- 补：右上"在日志大厅筛选该项目"保留；底部给"该项目其他项目"不做（无价值）。

4.6 租户主页 `/u/[handle]`
- 布局：handle + 统计（项目 / 已发布 / 最近发布）+ 精选 + 最新日志。
- 补：有 GitHub 头像就用（`User` 已有 githubId，可存 image 字段），没有就用等宽首字母方块。

4.7 标签索引 `/tags`（新增）
- 布局：标签云，字号三档，按频次排序；顶部一句说明"标签是这套档案的横切面"。
- 验收：≥100 标签时页面高度可控（每档限宽换行）；每个标签可键盘到达。

4.8 归档 `/archive`（新增）
- 布局：年份（mono 大号）→ 月份（12px 辅助灰）→ 条目行（日期 + 标题 + 项目）。
- 验收：条目按 beforeDate 倒序；年份锚点可分享（`#2026`）。

4.9 关于 `/about`
- 保留三段（简介 / 技术栈 / 联系）；技术栈改"分组 + 徽章网格"；补 RSS 与 GitHub 入口。

4.10 登录 `/login`
- 保留 GitHub OAuth；补加载态、错误态中文文案、"为什么只能用 GitHub 登录"一句解释。

4.11 404 / 错误边界
- 404：品牌化版面保留，补"搜索"与"回首页"两个出口；标签/日志/项目三种 404 文案区分（已区分）。
- error.tsx：补"重试"与"复制错误码"，错误码保留（可排查）。

4.12 后台 `/admin`
- 布局：左侧 200px 固定侧栏（图标 + 文字：概览 / 日志 / 项目 / 设置），顶部 breadcrumb + 退出。
  移动端侧栏变抽屉。
- 概览：四张统计卡（项目 / 已发布 / 草稿 / 本周发布）+ 最近编辑 5 条 + 快捷操作（新建日志 / 同步 GitHub / 导出）。
- 日志列表：
  - 状态 tab（全部 / 已发布 / 草稿）+ 标题搜索 + 每页 10 条。
  - **行内操作**：发布、下架、删除（删除走 Dialog 二次确认，要求输入 slug）。
  - **批量**：多选 → 发布 / 下架 / 删除；批量发布沿用"先存再发"语义（D25）。
- 编辑器：
  - 顶部工具栏：保存 / 发布 / 预览 / AI 帮我写 / 敏感扫描状态。
  - 正文区：格式工具栏（粗体/斜体/链接/代码/引用/列表/图片）+ 快捷键 + 拖拽粘贴上传。
  - 右侧元信息：项目 / 标签（带补全）/ 时间 / slug（自动生成可改）/ 字数与阅读时长。
  - 底部：上次发布时间与哈希、草稿预览链接（生成/失效）。
  - 自动保存：每 30s 或失焦存 sessionStorage，顶部显示"已自动保存 12:03"。
- 项目页：列表 + 行内编辑 + 删除确认。
- 设置页：站点标识、社交链接、默认主题、导出/导入、危险区（清空测试数据）。
- 验收：行内发布后列表状态即时变；批量操作有"已选 N 条"计数；任何破坏性操作都要二次确认。

五、功能层（按闭环分组，标 S/A/B，并注明依赖）
======================================================================

S = 强烈建议（价值高、成本低）  A = 建议做  B = 视情况

5.1 发现闭环

======================================================================
六、工程重构
======================================================================

6.1 样式组织
```
src/styles/
  tokens.css        原始层 + 语义层 + 暗色覆盖
  base.css          reset、排版基线、焦点、选区、滚动条
  layout.css        容器宽度、栅格、间距节奏
  components.css    按钮/输入/徽章/卡片/表格/目录/印章/Toast
  markdown.css      .log-body 全部规则（从 globals.css 拆出）
  print.css         打印
globals.css         只留 @import 与 @source 兜底
```
理由：现在 `globals.css` 里混了令牌、正文排版、目录、进度条四类东西，
改一处正文样式要滚 300 行；拆分后每类有唯一落点。

6.2 组件分层
```
src/components/ui/        Button Input Textarea Select Field Badge Card
                          ListRow EmptyState Skeleton Dialog Toast Tabs Pagination
src/components/layout/    SiteNav SiteFooter AdminShell ThemeToggle CommandPalette
src/components/feature/   Timeline Seal Editor ArticleToc PublishCheck SearchResults
src/components/icons/     14 个自绘 SVG（currentColor，1.5px stroke）
```
现在的扁平目录（20+ 文件）在新结构里每个文件都有明确归属。

6.3 数据模型（最小增量）
```
Log        + series String?        // 系列/合集，索引
           + featured Boolean @default(false)  // 手动精选，覆盖自动规则
           + pinnedAt DateTime?    // 置顶
PreviewToken id token LogId expiresAt createdAt    // 草稿只读预览
AuditEvent   id actorId action targetType targetId meta(Json) createdAt
```
迁移策略：一次性加字段（都可空或有默认），不重写历史数据；`featured` 为空时回落现有自动规则。

6.4 代码块高亮的裁定
日志内容在数据库里，Shiki 只能在请求期跑（构建期无法预生成）。为几十个代码块引入
1MB 级依赖 + WASM 初始化，在这个站的规模上不成立。**结论：不做语法高亮**，
改为"语言标签 + 复制按钮 + 行号 + 纸感边框"。等日志里代码块超过 50 个再评估。

6.5 依赖策略
- 新增运行时依赖：**0 个**。图标自绘、图表用纯 CSS 柱状、OG 图用内置 `next/og`。
- 如需引入，必须同时给出"体积 / 可替代方案 / 回退路径"三行说明，一次性批准。

6.6 性能预算（重构后仍要守）
- Prisma 调用：任一前台页 ≤3（`/logs` ≤2，详情 ≤2，不含 Proxy）。
- 首屏 JS：≤ 现状 + 15KB（命令面板与主题切换是唯一的客户端增量）。
- 字体：首屏实际传输 ≤ 120KB（CJK 分片按需拉取，禁止全量）。
- LCP ≤ 2.0s（本地 dev 不作数，按生产构建 + 本地 4G 模拟测）。
- 无布局位移：CLS ≤ 0.05（图片必须带宽高比）。

6.7 可访问性（不降级）
- 对比度：正文 ≥7:1，辅助 ≥4.5:1，暗色同标准；每个新增色对都要有实算记录。
- Dialog 焦点陷阱 + Esc 关闭 + 焦点归还。
- 命令面板：方向键移动、Enter 执行、Esc 关闭、输入框 aria-expanded。
- 路由切换后焦点落到主内容（`#main`）。
- 打印与 200% 缩放不横向滚动。

6.8 测试策略
- 纯逻辑（李在现有 192 条基础上扩）：slug 生成、导入冲突决策、审计动作枚举、标签云分档、归档分组。
- E2E（Playwright，仅 5 条关键链路）：登录 → 新建草稿 → 发布 → 前台可见 → 下架。
- 视觉回归：不做（单人站成本过高），改为"三档截图人工比对"。

======================================================================
八、验收标准（可核对，不是形容词）
======================================================================

视觉
- 全站间距值只出现在 4/8/12/16/24/32/48/64/96/128 十档（grep 检查 className 里的 px 值）。
- 圆角只有 0 与浮层 4px 两种；阴影只在 dialog/dropdown/toast 出现。
- 每个页面只有一处视觉焦点：标题或主操作，不同时出现两个"最大最黑"的元素。

交互
- 任何破坏性操作（删除/下架/批量）都有二次确认，且确认文案包含对象名称。
- 任何异步操作都有三态：进行中（禁用 + 文案变化）、成功（Toast + 状态更新）、失败（错误码 + 重试）。
- 所有列表页在 0 条、1 条、50 条三种数据下都不塌版。

性能
- 首页与详情页 Prisma 调用不回归（用 dev 的 log_statement 计数，Prisma 语句在 `execute` 行）。
- 首屏字体传输 ≤120KB；首屏 JS 增量 ≤15KB。

可访问性
- 键盘可完成：搜索 → 打开结果 → 回到列表；编辑器保存；后台行内发布。
- 暗色与亮色下，所有正文对比度 ≥7:1（实算记录随代码提交）。

| 重构与软著材料/文档脱节 | 材料失效 | 重构完成后统一重出一版材料，SPEC/DESIGN 按实际重写（留痕铁律本轮不适用） |
