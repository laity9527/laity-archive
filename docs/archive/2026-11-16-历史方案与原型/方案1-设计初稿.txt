收到——红线放开后，方案可以按"产品与体验最优"来设计，不必再被门禁、视觉铁律、点名授权、留痕铁律捆住。但我先把一句专业判断放在前面：**这个站点的品牌资产恰恰是"克制"**——纸白、墨色、宋体、存证感。推翻它去做一个花哨的现代 SaaS 是净损失。所以我推荐的是**"克制底子 + 精致升级"**：保留骨相，把肌肉、关节、皮肤全部重做，并补上现在缺的功能层。

下面是完整方案。

## 一、设计方向（先定调，后面全部据此展开）

| 维度 | 现状 | 重构后 | 理由 |
|---|---|---|---|
| 底色 | 纸白 `#f4f1ec` 单色 | 纸白 + **暗色模式**（暖黑 `#141311` 底、纸白字） | 长文阅读场景暗色是刚需；暖黑不破坏纸感 |
| 主色 | 墨 `#1a1a18`、棕 `#7a5a3a`（仅导航当前项） | 墨色体系保留，棕升级为**全站强调色**（链接 hover、选中态、进度、徽章） | 现在棕被锁死只用一处，是浪费；棕是这套色板里唯一有"人味"的颜色 |
| 圆角 | 零圆角 | **2px 微圆角**（卡片/输入/按钮），大组件 4px | 零圆角在信息密度高的后台会显得生硬；2px 既保留锐利感又有现代感 |
| 阴影 | 无 | **极轻阴影层级**（`0 1px 2px rgba(0,0,0,.04)` 起），只用于浮层/弹窗/抽屉 | 层次靠阴影比靠边框更轻 |
| 图标 | 无图标库，纯文字 | 引入 **lucide-react**（tree-shakable，约 2KB/图标） | 后台导航、操作按钮、状态都需要图标降认知成本 |
| 动效 | 基本无 | CSS transition + **View Transitions API**（零依赖，页面切换淡入） | 现代浏览器原生支持，渐进增强 |
| UI 字体 | 系统栈 | **Noto Sans SC**（UI）+ Noto Serif SC（正文）+ JetBrains Mono（代码/标签） | 三者搭配在中英混排下最稳 |

> 暗色模式 + 棕强调 + 微圆角 + 图标库，这四件事是"看起来更美观"的最大杠杆，且互不冲突。

## 二、设计系统（Design Tokens + 组件库）

### 2.1 Token 分层

```
原始色 → 语义色 → 组件色
```

- **原始层**：纸白、墨、棕、暖黑、灰阶 50–900
- **语义层**：`--bg`、`--bg-subtle`、`--fg`、`--fg-muted`、`--fg-subtle`、`--accent`、`--accent-hover`、`--border`、`--border-strong`、`--danger`、`--success`、`--warning`
- **组件层**：`--button-bg`、`--input-border`、`--card-bg` 等（可选，先不做）

暗色模式通过 `[data-theme="dark"]` 覆盖语义层，原始层不动。

**间距 scale**：`--space-1..10` = 4/8/12/16/24/32/48/64/96/128
**字号 scale**：`--text-xs..4xl`，配行高
**圆角**：`--radius-sm 2px`、`--radius-md 4px`、`--radius-full 999px`
**阴影**：`--shadow-sm/md/lg`
**动效**：`--ease-out`、`--duration-fast 120ms`、`--duration-base 200ms`

### 2.2 组件库（新建 `src/components/ui/`）

| 组件 | 用途 | 关键点 |
|---|---|---|
| `Button` | 所有按钮 | variant: primary/ghost/danger；size: sm/md；loading 态 |
| `Input` / `Textarea` / `Select` | 表单 | 统一 focus 环、错误态、helper text |
| `Field` | label+控件+错误 | 后台 7+ 处重复结构收敛 |
| `Badge` | WIP/LIVE/ARCHIVED、标签、AI 辅助 | variant 区分 |
| `Card` | 项目卡、日志卡、看板 | hover 微抬升 |
| `ListRow` | 首页最新、大厅、后台列表 | 主行/副行两段式 |
| `Timeline` | BEFORE/AFTER 时间轴 | 保留现在的结构，补暗色 |
| `Seal` | 内容摘要块 | 重构为 label/value 双行 |
| `EmptyState` | 空态 | 图标 + 文案 + 出口 |
| `Toast` | 操作反馈 | 替代现在纯 URL 参数回显（**关键增强**） |
| `Dialog` | 确认框 | 替代原生 `confirm()` |
| `Tabs` | 编辑器窄屏切换、后台筛选 | |
| `Pagination` | 大厅分页（现在有吗？） | 日志多了需要 |
| `Skeleton` | 加载态 | PPR 场景 |
| `Toc` | 阅读目录 | F23 已有，重构样式 |

> Toast 是这次功能层最重要的增强之一：现在所有操作回执靠 URL 参数（`?saved=1`），刷新即丢、无法复现、体验割裂。改为"URL 参数保留 + Toast 即时反馈"双通道。

## 三、信息架构与页面重构（逐页）

### 3.1 首页 `/`

**现状问题**：四段（标语/看板/精选/最新）平铺，缺视觉层次；看板信息密度低。

**重构**：
```
┌─────────────────────────────────────┐
│ 持久导航（字标 + 导航项 + 主题切换 + 搜索入口）│
├─────────────────────────────────────┤
│ Hero：大标语（clamp 字号）+ 一句副标题     │
│       右下角滚动提示 / 最新日志时间戳       │
├─────────────────────────────────────┤
│ 状态看板：项目卡网格（2–3 列）              │
│   每卡：名称 / 类型徽章 / 状态徽章 / 日期    │
│   零日志项目：虚线卡 + "尚未发布"            │
├─────────────────────────────────────┤
│ 精选项目：横向滚动卡（有日志的前三）         │
├─────────────────────────────────────┤
│ 最新日志：ListRow × 3 + "查看全部 →"        │
├─────────────────────────────────────┤
│ 页脚（合规位 + RSS + 主题切换 + 版权）        │
└─────────────────────────────────────┘
```
- Hero 用 `clamp(2.5rem, 6vw, 5rem)` + 行高 1.05
- 看板从"表格感"改为"卡片网格"，信息分组更清晰
- 精选区用横向滚动（`scroll-snap`），移动端体验好

### 3.2 日志大厅 `/logs`

**重构**：
- **顶部**：标题 + 结果计数 + 排序切换（发布时间/判断时间）+ 视图切换（列表/卡片）
- **筛选区**：项目 chips 一行、标签 chips 一行，**选中态用棕底纸白字**；"清除筛选"做成 ghost 按钮
- **搜索框**：顶部固定，输入即筛（配合 F24 高亮）
- **时间轴**：200px 保留，空心节点改虚线边框，hover 显示 tooltip
- **列表**：ListRow 主行（标题 + 项目 + 时间 + 标签）+ 副行（搜索命中片段，F24）
- **分页**：底部 Pagination（每页 20 条）
- **空态**：EmptyState + "清除筛选"

### 3.3 日志详情 `/logs/[slug]`

**重构**：
- 正文 720px 限宽保留（这是阅读体验的硬约束）
- **顶部面包屑**：首页 / 日志 / 项目名 / 标题
- **元信息条**：项目 + 双时间轴 + 标签 + 阅读时长估算
- **目录**：桌面右栏 sticky（F23 已有），样式升级为"当前项棕左线 + 滚动进度环"
- **正文**：BEFORE / AFTER / LESSON LEARNED 三段用**区块卡片**分隔（不是纯标题），LESSON 用棕左线引用块
- **底部**：Seal（内容摘要）重构为双行 label/value + 复制按钮 + 上一篇/下一篇
- **相关日志**：同项目或同标签的 3 条
- **代码块**：引入 Shiki 做构建时高亮（零运行时成本）
- **图片**：点击用原生 `<dialog>` 灯箱

### 3.4 项目列表 `/projects` + 详情 `/projects/[slug]`

- 列表改卡片网格（2–3 列），每卡：名称 / 类型 / 状态 / 简介 / 日志数 / 最近日期
- 详情：顶部项目信息卡 + 下方日志列表（ListRow）

### 3.5 租户主页 `/u/[handle]`

- 顶部：handle + 头像占位（GitHub 头像可拉）+ 统计（项目数/日志数/最近发布）
- 下方复用首页看板 + 最新日志结构

### 3.6 关于 `/about`

- 三段式保留，补：GitHub 链接、RSS 订阅按钮、技术栈用徽章网格

### 3.7 后台 `/admin` 系列

**重构重点**：
- **布局**：左侧固定侧边栏（图标 + 文字，lucide）+ 右侧内容区；顶部 breadcrumb + 主题切换 + 退出
- **概览**：统计卡片（项目数/已发布/草稿/最近改动）+ 最近改动时间线 + 快捷操作（同步 GitHub / 导出 / 新建日志）
- **日志列表**：**批量操作**（多选 → 发布/下架/删除）+ 状态筛选 tab（全部/已发布/草稿/已下架）+ 搜索
- **编辑器**：
  - 双栏保留，窄屏降为 Tabs 切换
  - 顶部工具栏：保存 / 发布 / 预览 / AI 帮我写 / 敏感扫描结果
  - 右侧元信息面板：项目 / 标签 / 时间 / slug / 摘要预览
  - 底部：操作历史（上次发布时间/哈希）
- **项目管理**：表格 + 行内编辑 + Dialog 确认删除
- **导出/导入**：导出已有，**补导入**（按 slug 幂等策略）

### 3.8 登录页 `/login`

- 保留 GitHub OAuth 一键登录
- 补：错误态友好化、加载态、品牌标识

### 3.9 404 / 错误页

- 品牌化 404 保留，补"返回首页 / 搜索"出口
- 错误边界补"复制错误码"按钮 + 重试

## 八、需要你拍板的 4 个决策

1. **设计方向**：接受"克制底子 + 棕强调 + 暗色 + 微圆角 + 图标"这套，还是想要更激进（如完全现代 SaaS 风、大圆角、彩色强调）？
2. **依赖引入**：lucide-react + shiki 是否同意？（如不同意，图标用 SVG 内联、代码高亮降级为纯 mono 背景）
3. **功能边界**：评论/邮件订阅这类会改变"无 UGC"定位的功能，是否明确排除？（我建议排除）
4. **开工顺序**：按 B1→B5 顺序做，还是先做一个"样板页"（建议日志大厅或首页）给你看效果再铺开？

上一轮方案覆盖了"视觉重构 + 一批功能增强"，这一轮我把功能面**系统性铺全**，按八个域展开，每条标优先级：

- **S** = 强烈建议（价值高、成本低，几乎必做）
- **A** = 建议做（价值明确，成本中等）
- **B** = 视情况（价值/成本需权衡）
- **C** = 可选/不建议（与定位冲突或成本过高）

上一轮已列过的（暗色、Toast、批量、导入、上下篇、代码高亮、灯箱、分页、相关日志、组件库、图标库）用 `（已列）` 标注，不重复展开。

## 十一、明确不建议做的（与定位冲突或过度设计）

| 功能 | 原因 |
|---|---|
| 评论/点赞/收藏（服务器端） | 与"无 UGC"定位冲突，localStorage 版足够 |
| 富文本 WYSIWYG | Markdown 是这个站的表达方式，换掉是倒退 |
| GraphQL | 单体 + Server Actions 已够，GraphQL 是负债 |
| 多角色权限/审核流 | 单人站无意义 |
| 国际化（如果只做中文） | 除非有明确英文受众 |
| 移动 App | 响应式 Web 覆盖 |
| 复杂状态管理库 | RSC + Server Actions 已够 |
| 微服务拆分 | 单体是这个站的正确形态 |
| 自建评论/论坛 | 明确排除 |
