## 1. 设计命题

访客要在 90 秒内验证「这个人真的做过、并且说得清」，不是被打动。第一感受应是**面前有一台可读的仪器**：发布时间、内容摘要、提交来源同屏，读者不必先懂审美就能核对。上一轮「克制」不是最优解——它把可信度寄存在纸、墨、宋体这类可模仿的材质里；真正不可模仿的是可复算摘要与可追溯提交。克制应保留为信息密度纪律，不是视觉命题。

**视觉命题：把档案库做成可核对的仪器，而不是可欣赏的纸上作品。**

## 2. 三个候选视觉方向

三个方向的对比度均按 WCAG 2.1 相对亮度公式实算，保留三位小数；装饰性细线豁免 3:1，控件边界不豁免。

## 3. 我的推荐方向：校验台（2.2）

| 维度 | 判断 | 依据 / 约束 |
|---|---|---|
| 选择 | **2.2 校验台**：暗色是原生仪器态，亮色是「阅图台」 | 三个方向里唯一把证据当数据，而不是当陈设 |
| 匹配可信度 ① | 摘要从脚注变读数：哈希、UTC 时间、提交来源在标题下同屏 | 字段均已存在，无需新增数据模型，不碰 `contentHash` 口径 |
| 匹配可信度 ② | 状态用文字不用灯，颜色只作冗余线索 | 色觉障碍与黑白打印下核对链不断 |
| 匹配可信度 ③ | 复算口径写在卡上，读者知道拿什么去复算 | 只是排版，不新增执行能力；密钥仍不进日志 |
| 对照 | 2.1 把证据当「校样」，2.3 把证据当「展品」 | 二者都要求读者先接受隐喻，2.2 直接给读数 |
| 375 成立 ① | 版心 `100% - 2×16px`，表格转定义列表，读数栏移到正文前 | 3 行摘要条 ≤120px 高 |
| 375 成立 ② | 哈希 `break-all` + 4 位分组，不产生横向滚动 | 按钮最小 40×40px，正文 16px/1.85 |
| 375 成立 ③ | 读数条高度固定 | CLS 由预留高度与固定行高控制 |
| 1440 成立 ① | 760 + 280 + 两栏间隙，整体 1320px 居中 | 右栏 sticky，目录与读数共用一栏 |
| 1440 成立 ② | 一屏内可见标题、三读数与 BEFORE 开头 | 避免第二根 sticky 造成视觉抖动 |
| 预算成立 | Prisma 调用数不变 | 全部为渲染层改动，`userId` 隔离逻辑不动 |
| 最大失败模式 | 变成「霓虹赛博」或「后台管理面板」 | 触发：荧光描边、终端雨、emoji 状态灯、一屏三处高亮 |
| 失败模式 ② | 访客觉得在看别人的 CMS，而不是在看档案 | 对策：前台不出现「管理/编辑/批量」词，状态栏只报档案事实 |
| 失败模式 ③ | 亮色态照抄暗色布局，荧光青在白底变脏 | 亮色强调色必须换 `#0E756B`，实算 **5.077:1** |
| 第二选择 | **2.3 暗厅陈列** | 同样把证据当一等对象且没有 SaaS 脸；代价是信息密度低、核对动作不直观 |

## 6. 与 V3 的根本差异

| 维度 | V3（克制升级） | 本方案（从零） | 为什么是实质差异 | 风险 |
|---|---|---|---|---|
| 视觉命题 | 纸白墨色的克制资产 | 可核对的仪器 | 从材质隐喻换到功能隐喻，判断标准从「像不像档案」变「核不核得动」 | 团队需重建审美共识 |
| 色彩 | 暖纸 `#f4f1ec` + 墨 `#1a1a18` + 棕 `#7a5a3a` | 石墨 `#0C1014` + 磷光青 `#5BD6C4` | 色相与明度结构全换，强调色从导航扩权到读数状态 | 品牌识别需重建 |
| 字体 | 正文宋体 18px/1.85，中文 UI 下限 11px | 正文系统无衬线 16px，中文下限 13px，等宽优先 | 从「读文章」转向「读记录」，字形决定信息性质 | 中文跨平台字形差异变大 |
| 圆角阴影 | 全局 0 圆角、页面零阴影 | 控件 2px、浮层 6px、浮层阴影 | 从纸面隐喻转到分层面板，深度成为新层级手段 | 易滑向通用 SaaS 观感 |
| 图标 | 15 个 1.5px 线性图标（已落地），只做辅助识别 | 组件与 `currentColor` 机制沿用、视觉规格重画；另新增 3 个状态图标 | 从「辅助识别」扩到「仪器状态」，且线宽/尺寸全换 | 未配文字会违反无障碍 |
| 层级手段 | 线 + 留白，禁止阴影 | 背景抬升 > 边线 > 字号 > 字重 | 层级从二维排版变三维面板，信息密度可上调 | 面板过多会碎片化 |
| 动效 | hover 120ms、进入 180ms、无呼吸 | 100ms / 160ms + 同步态 1.2s 呼吸 | 动效第一次承担「系统正在工作」的信息 | 不加 reduce 开关即失败 |
| 暗色 | 亮色反相式暖黑，只覆盖语义层 | 暗为原生态、亮为阅图台，明度阶梯独立推导 | 两套色不是镜像，强调色迁移方向相反 | 维护成本翻倍 |
| 打印 | 黑字白底，印章不隐藏 | 仪器读数小票：保留全读数 + CSS 页码 | 从「带走一页文章」变「带走一份核对单」 | 页码需新增能力 |
| 组件语言 | 编号头、双线、印章、零圆角卡 | 读数条、网格表、状态边、分组哈希 | 组件语义从「档案陈设」变「数据呈现」 | 旧组件需逐个重命名与重写 |
| 强调色权限 | 只给导航当前项与高亮 | 当前、可复算、可操作三类状态 | 扩权后强调色成为信息通道，滥用即失效 | 一屏多处高亮会崩塌 |
| 落地成本 | 已在 V3 批次落地，边际成本近 0 | 机制可复用（图标组件、`CodeBlock.tsx` 抽取、防闪脚本）；视觉全量重写：CSS + 约 30 处 className + 3 个新图标；新增依赖 0 | 贵在推翻已验证的视觉落地状态，不在逻辑或性能 | 需独立批次与回滚位 |

## 7. 三条警告

1. **别把仪表做成控制台**：前台出现「管理/编辑/批量/删除」任何一个词，可信度立刻反转成「在看别人的后台」。
2. **荧光只能有一个**：`#5BD6C4` 一屏最多一处语义（当前项或可复算项），第二处开始是装饰，第三处变廉价。
3. **暗色不是滤镜**：必须按明度阶梯重定义凹槽/面板/文字并实算对比度；直接反相会让控件边界 `#62737E` 掉到 3:1 以下。
