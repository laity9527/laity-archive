# Laity 多用户开发者档案库 合规需求设计方案

**文档版本**：v1.0  
**设计日期**：2026-11-03  
**合规基线**：《个人信息保护法》《网络安全法》《著作权法》《互联网信息服务管理办法》  
**设计原则**：最小必要、权属清晰、风险隔离、全程可审计

---

## 一、用户分层与核心需求洞察

### 1.1 三类核心用户画像

| 用户角色 | 占比预估 | 核心需求 | 支付意愿 | 关键痛点 |
|----------|----------|----------|----------|----------|
| **个人开发者** | 80% | 快速搭建好看的技术作品集，自动同步GitHub提交记录，不用自己折腾服务器 | 低（倾向免费+轻量付费） | 自建博客配置麻烦；国内访问慢；技术博客平台排版太丑、广告多 |
| **独立开发者/创业团队** | 15% | 展示项目迭代过程，打造个人品牌，吸引早期用户/招聘 | 中（愿意为自定义域名、私有项目付费） | 需要同时维护GitHub、个人站、简历多个渠道，信息不同步 |
| **技术团队负责人/招聘方** | 5% | 浏览真实的开发者产出过程，评估候选人实际编码能力 | 低（作为访客使用） | 简历造假多，GitHub提交记录看不出思考过程 |

### 1.2 需求层级（马斯洛映射）

- **基础层（必须有）**：稳定的访问速度、清晰的排版、基础的账号安全、不丢数据
- **期望层（应该有）**：GitHub自动同步草稿、Markdown双栏编辑器、个性化个人主页、敏感信息自动过滤
- **兴奋层（可以有）**：一键生成简历PDF、项目访问统计、自定义域名、团队协作空间

### 1.3 决策链路与行为逻辑

1. **获客阶段**：看到他人分享的Laity主页 → 被极简风格吸引 → 访问首页 → 3秒内看懂"这是什么" → 点击注册
2. **激活阶段**：注册后引导绑定GitHub → 自动拉取最近3个项目生成草稿 → 用户编辑1条日志并发布 → 生成个人主页
3. **留存阶段**：每次Git push后收到草稿提醒 → 定期补充日志 → 分享主页到社交平台获得正反馈
4. **付费阶段**：需要自定义域名/私有项目/去除页脚标识 → 购买Pro会员

## 二、合规架构顶层设计

### 2.1 个人信息处理合规体系（P0级）

#### 2.1.1 最小必要收集原则
严格遵循《个人信息保护法》"最小必要"要求，**不收集任何与功能无关的信息**：

| 收集项 | 收集目的 | 是否必需 | 存储期限 | 用户删除权利 |
|--------|----------|----------|----------|--------------|
| 邮箱地址 | 账号注册、密码找回、重要通知 | ✅ 必需 | 账号存续期+注销后15天 | 可随时修改/注销即删 |
| 手机号 | 验证码登录、账号安全校验 | ⚠️ 可选（不强制绑定） | 账号存续期+注销后15天 | 可随时解绑/更换 |
| GitHub ID/用户名 | 绑定GitHub账号、拉取公开仓库信息 | ⚠️ 可选（用户主动绑定才收集） | 绑定存续期 | 可随时解绑即删 |
| GitHub Token（加密） | 调用GitHub API拉取提交记录 | ⚠️ 仅在用户绑定时收集 | 绑定存续期 | 解绑立即永久删除 |
| 登录IP/时间 | 安全审计、异常登录检测 | ✅ 必需（安全需要） | 最近180天 | 不支持单独删除（合规留存） |
| 用户发布的项目/日志内容 | 提供核心服务 | ✅ 必需 | 内容存续期 | 用户可随时删除 |

❌ **明确禁止收集的信息**：
- 通讯录、位置信息、麦克风、摄像头权限（功能完全不需要）
- 身份证信息、真实姓名（初期不做实名认证，除非监管强制要求）
- 设备IMEI、MAC地址等非必要设备标识
- 用户浏览行为数据做用户画像/个性化广告

#### 2.1.2 告知-同意机制
- **首次注册弹窗**：以显著弹窗方式展示《用户协议》和《隐私政策》核心要点，用户必须主动勾选"我已阅读并同意"才能继续，不设置默认勾选
- **分层告知**：收集手机号/绑定GitHub时，单独弹出告知框说明"收集该项信息的目的、存储方式、使用范围"，用户单独授权
- **隐私政策独立成文**：不与用户协议合并，按功能场景逐项列明收集项，避免模糊表述
- **变更通知**：隐私政策修改时，提前7天在站内信和首页公告通知用户，重大变更需用户重新确认同意

#### 2.1.3 用户数据权利保障
提供完整的数据权利行使通道，所有操作不设不必要门槛：
1. **知情权**：设置"我的数据"页面，清晰展示平台存储了该用户的所有个人信息项
2. **更正权**：用户可自行修改邮箱、手机号等个人信息
3. **删除权**：
   - 单条内容/单个项目可随时删除
   - 提供一键"清空所有内容"功能
   - 账号注销功能：提交后15个工作日内完成所有数据删除（法律要求留存的安全日志除外），注销后不可恢复
4. **导出权**：支持用户导出自己所有的项目、日志内容为Markdown压缩包
5. **撤回同意权**：用户可随时在设置中关闭手机号登录、解绑GitHub，关闭后平台立即停止相关数据处理

#### 2.1.4 数据安全防护
- **传输加密**：全站HTTPS，所有API接口强制TLS 1.3
- **存储加密**：
  - 用户密码使用bcrypt加盐哈希存储（不可逆）
  - GitHub Token使用AES-256对称加密存储，密钥单独保管，不放在代码库
  - 手机号、邮箱等敏感字段数据库层面加密存储
- **访问控制**：
  - 后台严格权限分级，普通运营人员看不到用户完整手机号/邮箱
  - 所有数据访问操作留痕，审计日志保留6个月
  - 禁止生产环境直接查库，所有数据查询走审批流程
- **数据泄露应急**：制定数据泄露应急预案，发生泄露后72小时内上报监管部门并通知受影响用户

### 2.2 知识产权与侵权风险防控体系（P0级）

#### 2.2.1 平台与用户的权利边界
**用户生成内容（UGC）权属规则（写入用户协议）**：
1. 用户对其发布的原创项目描述、日志文字、上传的图片等内容，保留完整著作权
2. 用户授予平台**非独占、可撤销、免费、仅用于提供本服务之目的**的使用许可：允许平台在用户个人主页、平台公开页面展示、转码、存储该内容，不获得任何商业使用、转授权权利
3. 用户注销账号或删除内容后，平台立即停止使用该内容，清除缓存
4. 平台绝不要求"永久、不可撤销、全球性、免费"的宽泛授权，不剥夺用户对自己内容的所有权

**GitHub同步内容的特殊处理**：
1. 初期仅支持绑定**公开仓库（Public Repo）**，不申请私有仓库权限，从源头避免接触用户私有代码
2. GitHub OAuth申请最小权限：仅申请`public_repo`和`read:user`权限，不申请`repo`、`admin:org`等高风险权限
3. 系统仅同步Commit Message、提交时间、SHA值、Diff统计（增删行数），**不同步、不存储完整代码内容**，仅提供跳转到GitHub原页面的链接
4. 在同步的日志页面显著标注："内容来自GitHub公开提交，著作权归原作者所有，本平台仅做格式整理展示"，并附上原Commit在GitHub的直达链接
5. 用户必须手动编辑并确认发布后，同步内容才会公开，默认仅在用户自己的草稿箱可见

#### 2.2.2 侵权投诉处理机制（避风港规则落地）
严格遵循"通知-删除"规则，建立完整的侵权处理流程：
1. **显著的投诉入口**：在网站页脚、每篇日志底部、个人主页底部放置"侵权投诉"链接，公开投诉邮箱和处理流程
2. **投诉材料要求**：权利人投诉需提供：
   - 权利人身份证明
   - 侵权内容链接和位置
   - 权属证明（著作权登记证书、首发证明等）
   - 承诺陈述属实的声明
3. **处理时效**：收到合格投诉后**24小时内**做初步审核，48小时内对明显侵权内容采取删除、屏蔽、断开链接措施
4. **反通知机制**：内容被删除后，发布用户可提交反通知说明不侵权理由，平台转送权利人后，若权利人15个工作日内未起诉，可恢复内容
5. **重复侵权处理**：3次侵权投诉成立的用户，永久封禁账号
6. **处理留痕**：所有投诉、处理记录归档留存至少3年，以备监管查验

#### 2.2.3 侵权风险事前预防
1. **内容审核机制**：
   - 基础敏感词过滤：覆盖违法违规、色情暴力、政治敏感、人身攻击等内容
   - 发布前校验：自动检测内容中是否包含手机号、身份证号、API密钥、数据库密码等敏感信息，提示用户确认
   - 图片审核：接入内容安全API，自动识别色情、暴力、涉政图片
   - 人工审核抽查：对新注册用户前3条发布内容进行人工审核，高风险内容拦截
2. **AI生成内容标注**：如果未来接入AI自动生成日志摘要功能，显著标注"本内容由AI辅助生成，仅供参考"
3. **商标/品牌合规**：
   - GitHub是GitHub, Inc.的注册商标，平台仅在说明功能时合理使用，不暗示官方背书或合作关系
   - 页面中提到的其他产品、品牌名称均为其各自所有者的商标，平台不主张任何权利
   - 平台自身视觉设计（极简黑白灰、排版风格）属于通用设计语言，不使用任何第三方有版权的图标、字体、图片素材
4. **第三方素材合规**：
   - 全站使用开源免费字体：正文使用Noto Serif SIL开源字体、代码使用JetBrains Mono Apache 2.0开源字体，均允许商业使用
   - 不使用任何第三方图标库，所有UI图标使用纯字符或自行绘制的SVG，不引入有版权的素材
   - 默认示例内容使用平台原创或公有领域素材，不照搬任何现有平台的文案、示例项目

### 2.3 内容合规与平台责任（P0级）

#### 2.3.1 禁止内容清单（写入用户协议）
明确禁止用户发布以下内容：
1. 违反宪法确定的基本原则的；
2. 危害国家安全，泄露国家秘密，颠覆国家政权，破坏国家统一的；
3. 损害国家荣誉和利益的；
4. 煽动民族仇恨、民族歧视，破坏民族团结的；
5. 破坏国家宗教政策，宣扬邪教和封建迷信的；
6. 散布谣言，扰乱社会秩序，破坏社会稳定的；
7. 散布淫秽、色情、赌博、暴力、凶杀、恐怖或者教唆犯罪的；
8. 侮辱或者诽谤他人，侵害他人合法权益的；
9. 含有虚假、欺诈、侵害他人隐私、商业秘密等内容的；
10. 含有法律、行政法规禁止的其他内容的。

#### 2.3.2 内容管控机制
1. **先审后发 vs 先发后审**：初期采用"先发后审+关键词拦截"模式，对命中高风险关键词的内容先审后发
2. **用户举报机制**：每篇内容都有"举报"按钮，用户举报后24小时内人工审核处理
3. **违规处置梯度**：
   - 轻度违规（如人身攻击、广告）：删除内容，警告一次
   - 中度违规（如低俗内容、轻度侵权）：删除内容，封禁7天
   - 重度违规（如违法内容、多次侵权）：永久封禁账号，相关内容全部删除
   - 违法内容：立即删除，保存记录，向有关部门报告
4. **日志留存**：所有发布、删除、封禁操作留痕，日志保留6个月以上，配合监管部门依法检查

## 三、核心功能合规设计细则

### 3.1 账号与认证体系（P0）

| 功能点 | 合规设计细节 | 风险等级 |
|--------|--------------|----------|
| 邮箱注册 | 1. 必须验证邮箱所有权（验证码）才能激活账号<br>2. 密码强度校验：至少8位，包含字母和数字<br>3. 注册时必须同意用户协议和隐私政策，不默认勾选<br>4. 同一邮箱/手机号1小时内最多发送5条验证码，同一IP1小时最多注册3个账号，防恶意刷量 | 中 |
| 手机号登录 | 1. 手机号为**可选登录方式**，不强制用户绑定手机号，支持纯邮箱+密码注册使用<br>2. 如果用户选择手机号登录，单独弹窗告知"我们将收集您的手机号用于验证码登录，您可随时解绑"<br>3. 短信验证码有效期5分钟，同一手机号1天最多发送10条短信<br>4. 接入图形验证码/滑块验证码防止短信轰炸，同一IP10分钟内发送超过3条必须完成验证码<br>5. 手机号不在前台公开展示，用户可选择是否在个人主页显示联系方式 | 高 |
| GitHub OAuth绑定 | 1. 授权页面明确告知："我们将请求访问您的公开仓库信息和基础用户信息，用于同步提交记录，不会访问您的私有仓库"<br>2. 申请最小权限scope：`read:user`、`public_repo`，不申请多余权限<br>3. Token加密存储，用户解绑时立即永久删除，不保留备份<br>4. 用户可随时在GitHub后台撤销授权，平台检测到授权失效后立即停止同步<br>5. 不在任何地方展示用户完整的Token，后台也无法明文查看 | 高 |
| 密码找回 | 1. 支持邮箱验证找回密码，邮箱链接有效期15分钟，单次使用<br>2. 重置密码后所有已登录设备自动退出，发送邮件通知用户<br>3. 不允许通过"安全问题"等弱验证方式找回密码 | 中 |

### 3.2 GitHub自动同步功能（P0）

| 功能点 | 合规设计细节 | 风险等级 |
|--------|--------------|----------|
| 仓库绑定 | 1. 仅展示用户自己名下的公开仓库，不展示组织仓库（除非用户明确授权）<br>2. 绑定前明确告知："我们将通过Webhook监听该仓库的新提交，仅获取Commit Message和变更统计，不会拉取代码内容"<br>3. 每个绑定的仓库生成独立的Webhook Secret，用于校验请求合法性，防止伪造Webhook攻击<br>4. 用户可随时解绑仓库，解绑后删除该仓库所有Webhook配置和本地缓存数据 | 中 |
| 自动同步逻辑 | 1. 同步频率严格遵守GitHub API速率限制：认证用户5000次/小时，实现指数退避重试，不突发大量请求<br>2. 仅同步提交的元数据：Commit SHA、提交时间、提交者信息、Commit Message、增删行数统计<br>3. **不存储完整代码Diff内容**，点击查看Diff直接跳转到GitHub对应页面，不在本平台服务器留存代码副本<br>4. 自动同步的内容默认进入用户的**私有草稿箱**，仅用户自己可见，用户必须手动确认、编辑后才能发布公开<br>5. 发布时显著标注"本内容基于GitHub公开提交整理，原始提交地址：xxx"，附直达GitHub链接 | 高 |
| 异常处理 | 1. 如果GitHub API返回401/403（授权失效/限流），立即停止同步，给用户发站内信提醒重新授权<br>2. 同步失败不重试超过3次，避免触发GitHub滥用检测<br>3. 绝不爬取GitHub非公开页面，所有数据通过官方API获取，严格遵守GitHub服务条款 | 中 |

### 3.3 内容发布与编辑功能（P0）

| 功能点 | 合规设计细节 | 风险等级 |
|--------|--------------|----------|
| Markdown编辑器 | 1. 图片上传时自动扫描是否包含敏感内容（色情/暴力/涉政）<br>2. 自动检测内容中的敏感信息：手机号、身份证号、邮箱、API密钥、密码、内网IP等，发布前弹窗提示"您的内容中可能包含敏感信息，请确认是否公开"<br>3. 图片存储按用户ID分目录，用户删除内容时同步删除对应OSS文件<br>4. 不提供匿名发布功能，所有公开内容都关联发布者账号，可溯源 | 中 |
| 内容存证哈希 | 1. 仅对用户发布的内容计算SHA-256哈希，用于证明内容未被篡改<br>2. 哈希值仅作为技术标记展示，不做"存证""防伪""区块链"等夸大宣传，不暗示具备法律效力<br>3. 不使用任何区块链/ NFT相关功能，避免政策风险 | 低 |
| 内容删除 | 1. 用户删除内容后，前台立即不可见，服务器备份72小时后永久删除<br>2. 如果内容因为侵权/违规被平台删除，给用户发送明确的删除通知，说明删除原因和申诉渠道<br>3. 不提供"永久不可删除"的内容存证服务，尊重用户删除权 | 中 |

### 3.4 前台展示与个人主页（P1）

| 功能点 | 合规设计细节 | 风险等级 |
|--------|--------------|----------|
| 公开内容展示 | 1. 所有公开内容都明确标注作者用户名和发布时间<br>2. 用户个人主页默认展示内容，用户可设置"仅登录用户可见"或"私有"<br>3. 不提供全站内容下载/批量爬取接口，反爬机制防止批量抓取用户内容<br>4. 搜索引擎收录默认开启，用户可在设置中关闭"允许搜索引擎收录我的主页" | 中 |
| 联系方式展示 | 1. 用户的邮箱、手机号等联系方式默认不公开，用户可自行选择是否在个人主页展示<br>2. 不强制用户填写真实姓名、所在地、工作单位等个人信息<br>3. 提供"联系我"表单功能，访客发送的消息通过平台转发，不直接暴露用户邮箱，避免爬虫抓取 | 中 |
| 项目引用 | 1. 展示GitHub项目时，明确标注项目来源和作者，提供跳转到GitHub原仓库的链接<br>2. 不把GitHub项目内容作为平台原创内容，不隐藏原作者信息<br>3. 如果原作者删除了GitHub仓库，平台同步停止展示对应内容 | 低 |

### 3.5 管理后台与权限控制（P0）

| 功能点 | 合规设计细节 | 风险等级 |
|--------|--------------|----------|
| 数据权限隔离 | 1. 严格的租户隔离：所有数据库查询必须带userId条件，普通用户绝对无法访问/修改/删除他人数据<br>2. 接口权限校验：所有Server Action和API都必须校验当前登录用户是否为资源所有者，未登录用户只能访问公开内容<br>3. 越权操作自动拦截并记录安全日志，多次尝试越权的账号自动封禁 | 高 |
| 管理员权限 | 1. 管理员账号分角色：超级管理员、内容审核员、运营人员，最小权限分配<br>2. 审核员只能看到违规内容列表，无法查看用户完整手机号、邮箱、GitHub Token等敏感信息<br>3. 管理员所有操作（封禁用户、删除内容、修改配置）都留操作日志，记录操作人、时间、IP、操作内容，永久留存 | 高 |
| 数据导出 | 1. 禁止管理员批量导出用户数据，任何数据导出都需要超级管理员审批<br>2. 不向任何第三方提供用户个人数据，除非法律强制要求且有正式公函 | 高 |

## 六、风险清单与应对预案

| 风险类型 | 风险描述 | 发生概率 | 影响程度 | 应对措施 |
|----------|----------|----------|----------|----------|
| **个人信息合规风险** | 过度收集个人信息、未明确告知、用户无法注销账号，被监管部门通报/罚款 | 中 | 极高 | 严格执行最小必要原则，上线前对照2026年个人信息保护专项行动检查清单逐项自查，所有用户权利通道必须畅通 |
| **知识产权侵权风险** | 用户发布侵权内容，平台未及时处理，被权利人起诉承担帮助侵权责任 | 中 | 高 | 落实避风港规则，建立快速投诉处理通道，24小时响应，显著位置放置投诉入口，不怠于履行审核义务 |
| **GitHub API违规风险** | 调用API频率过高、权限申请过大，违反GitHub服务条款，被封禁接口 | 中 | 高 | 严格遵守速率限制，仅申请最小必要权限，不同步存储私有代码，所有数据通过官方API获取 |
| **内容合规风险** | 用户发布违法违规内容，平台未及时处置，导致域名被墙/服务器被关停 | 低 | 极高 | 接入多层内容审核机制，关键词拦截+人工审核+用户举报，建立违规内容快速处置流程，24小时内处理高危内容 |
| **数据泄露风险** | 服务器被攻击，用户密码、Token等敏感信息泄露 | 低 | 极高 | 所有敏感字段加密存储，密码不可逆哈希，定期做安全渗透测试，制定泄露应急响应预案，发生后及时通知用户和监管 |
| **短信轰炸风险** | 恶意用户利用短信接口轰炸他人手机号，导致短信通道被封、产生高额费用 | 中 | 中 | 接入图形验证码，限制同一手机号/IP发送频率，设置每日发送上限，异常流量自动熔断 |

## 八、待验证事项与边界说明

1. **实名制要求边界**：当前阶段平台仅提供个人作品展示功能，不提供发帖、评论、私信等互动功能，根据现行法规暂不要求强制实名认证。若未来开放评论/社区功能，需按照监管要求评估是否需要实名认证。
2. **私有仓库支持**：初期明确不支持私有仓库同步，避免私有代码泄露和权限风险。若未来用户需求强烈，需单独做安全评估和权限设计。
3. **AI功能合规**：当前版本不包含任何AI生成内容功能。若未来增加AI辅助写日志功能，需按照《生成式人工智能服务管理暂行办法》要求进行备案，显著标注AI生成内容，并对生成内容进行审核。
4. **未成年人保护**：当前平台主要面向成年开发者用户，若发现未满14周岁未成年人注册，需立即注销账号并删除相关数据，不主动收集未成年人信息。
